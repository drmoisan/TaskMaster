- Pre-host cancellation gives every resource a dedicated `completed[index]` flag. Only successful actions set it, and the second attempt skips completed indexes; a completed resource cannot be double-disposed by retry.
- Hosted wrapper cleanup intentionally executes once because a wrapper may finish disposing its owned control and then throw. Direct control cleanup is therefore disabled while the wrapper exists, preventing two owners from disposing the same control.
- Each pending resource executes through its own `RunAsync` call, so one secondary failure does not stop remaining resource attempts. Only first-attempt failures are reported.
- `failure ??= exception` retains the first cleanup failure. Rollback cleanup is awaited and suppressed before the original `throw`, so a cleanup secondary cannot replace the initiating exception.
