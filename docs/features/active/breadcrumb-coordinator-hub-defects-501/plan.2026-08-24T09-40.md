## Conventions used by every task below

- **`WS`** — the workspace root: the agent worktree checked out for this feature. Every command runs
  with `WS` as the current directory. Every path in this plan is relative to `WS` unless stated
  otherwise. No absolute host path (user profile, account name, machine name) may be written into any
  artifact; record `WS` as the literal token `WS` when a path must be referenced.
- **`FF`** — `docs/features/active/breadcrumb-coordinator-hub-defects-501`. Every evidence path in
  this plan resolves to `FF/evidence/<kind>/` where `<kind>` is one of `baseline`,
  `regression-testing`, `qa-gates`, `issue-updates`, `other`. Evidence paths under `artifacts/` are
  forbidden and must never be used.
- **`<TS>`** — the ISO-8601 `yyyy-MM-ddTHH-mm` timestamp at which the task ran. Artifact filenames
  embed it.
- **Artifact schema.** Every command-step artifact records, at minimum, four fields:
  `Timestamp:`, `Command:`, `EXIT_CODE:`, `Output Summary:`. An `[expect-fail]` artifact additionally
  records `ExpectedExitCode: 1` and the failing assertion text. Baseline and final-QC test artifacts
  record NUMERIC coverage values; the literal `UNVERIFIED` is not an acceptable value anywhere.
- **Shell.** PowerShell 7 (`pwsh -NoProfile`). Single-quote command payloads; double any literal
  quote inside them.

#### Toolchain command reference (from `CLAUDE.md`; do not alter)

1. **Format:** `dotnet tool run csharpier format .` (verify read-only: `dotnet tool run csharpier check .`)
2. **Analyze:** `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:EnableNETAnalyzers=true /p:EnforceCodeStyleInBuild=true`
3. **Type-check:** `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:TreatWarningsAsErrors=true`
4. **Test:** `vstest.console.exe <test-assembly-paths> /EnableCodeCoverage`

Two omissions are deliberate and must not be "restored": do NOT add `/p:Nullable=enable`, and do NOT
use `/t:Build`. A warm `/t:Build` returns exit 0 with `CoreCompile` skipped on every project, so the
analyzer and nullable gates would be vacuous.

`msbuild` and `vstest.console.exe` are not on `PATH` under `pwsh -NoProfile`. Phase 0 resolves both
through `vswhere.exe` and records the absolute paths; every later task uses the recorded path with
the call operator `&`.

#### Scoped test-run template

Regression and verification runs use the resolved `vstest.console.exe` path from P0-T5 with an
explicit assembly path and an explicit results directory, so each run deposits its own TRX:

```text
& $vstest 'QuickFiler.Test\bin\Debug\QuickFiler.Test.dll' /InIsolation
    '/Settings:scripts\vscode\TaskMaster.cli.runsettings'
    '/TestCaseFilter:FullyQualifiedName~TESTNAME'
    '/Logger:trx;LogFileName=pN-tM.trx'
    '/ResultsDirectory:docs/features/active/breadcrumb-coordinator-hub-defects-501/evidence/regression-testing/trx/pN-tM'
```

A shared results directory makes "which TRX belongs to which task" ambiguous once several
`[expect-fail]` runs deposit into it, so each run gets its own `pN-tM` segment. `LogFileName=` is
mandatory: the vstest default TRX name embeds the account and host name.

#### Design rulings made by this plan (recorded, with evidence)

- **PD-1 — `RunSynchronous` settles the lease on its own skip path.** AC-19 requires the lease-leak
  regression test to live in `QuickFiler.Test/Viewers/BreadcrumbCoordinatorUpgradeLifetimeTests.cs`,
  to compile against HEAD, to be RED there, and to be green after the fix. That test calls
  `lifetime.RunSynchronous(lease, action)` directly, with no coordinator in the picture, so it can
  only turn green if `RunSynchronous` itself settles the skipped lease. `RunSynchronous` therefore
  calls `Abandon(lease)` when `TryRunCurrent` returns `false`. Both call sites additionally branch on
  `false` exactly as `spec.md` → `## Proposed Fix` → `#502` specifies. The duplicate `Abandon` is
  harmless and is verified idempotent by construction:
  `QuickFiler/Viewers/BreadcrumbCoordinatorUpgradeLifetime.cs:266-271` returns early once
  `CancellationStarted` is set, and the disposal predicates at `:246` and `:285` are both guarded by
  `!lease.SourceDisposed`.
- **PD-2 — AC-11's logging half is verified by a source assertion, not by a runtime log assertion.**
  `QuickFiler.Test/QuickFiler.Test.csproj` carries no `log4net` reference (verified: zero `log4net`
  matches in that project file, and zero `log4net` matches in any `QuickFiler.Test/**/*.cs`), so a
  `MemoryAppender` test of the kind used in `TaskMaster.Test/AppGlobals/AppEventsTests.Helpers.cs:228-247`
  would not compile there. Adding a `<Reference>` is outside this feature's authorized project-file
  budget of exactly one `<Compile Include>` line per project file (spec `## Scope & Non-Goals`). The
  reflective alternative (resolving `log4net` types by name at run time) is rejected as brittle and
  as ~30 lines against 86 lines of headroom. AC-11's second half — `PostJson` does not propagate the
  surface throw — is asserted by a real test. Recorded as a plan-level verification-route decision;
  it changes no spec requirement.

### Phase 7 — Final QA loop

Run the four toolchain steps in order: format, then analyze, then type-check, then test. **If any step
fails, or if any step changes any file, restart the loop from step 1** and re-run every step; the
phase is complete only when all four pass in one uninterrupted pass with no file change after the
formatting step.

The full-suite coverage run takes roughly twenty minutes across nine assemblies. Launch it with
`Start-Process -PassThru` plus `-RedirectStandardOutput` and `-RedirectStandardError` to a log under
`FF/evidence/qa-gates/`, record the PID, poll the log with short waits, and take `EXIT_CODE:` from the
process object's `ExitCode`. Before any retry, kill the whole process tree (the pwsh runner, every
`testhost`, `vstest.console` and `dotnet-coverage`). The coverage runner may be re-run at most twice,
