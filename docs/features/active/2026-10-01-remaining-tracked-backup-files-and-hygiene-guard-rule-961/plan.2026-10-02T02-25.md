Design decisions (made before planning, justified in `issue.md` Suspected Cause / Notes):

- The guard gains rule C: a tracked path whose final extension is `.bak`, matched case-insensitively with `[System.IO.Path]::GetExtension`, after the existing `.claude/` governance skip, with no new exemption mechanism. A broader backup-file family is not adopted.
- The finding line is `HYGIENE backup-file <path>`. A backup file is still content-scanned (no early `continue`), so a `.bak` file that also carries a profile path yields both findings.
- The pure rule is a new function `Test-BackupFilePath` in `scripts/hygiene/Test-RepositoryHygiene.Rules.ps1`. The wiring is one `if` in `Invoke-RepositoryHygieneMain` in `scripts/hygiene/Test-RepositoryHygiene.ps1`. This stays within the budget of 2 production PowerShell files.
- `.gitignore` gains a general `*.bak` line directly after the existing `*.csproj.bak` line; the two existing lines (`*.rptproj.bak`, `*.csproj.bak`) are untouched in Phases 0-2 (amended by Phase 3, task CR-3: both are then removed as redundant with `*.bak`).
- Coverage limitation: the PoshQC coverage document `artifacts/pester/powershell-coverage.xml` does not carry `scripts/hygiene` in its denominator, so no hygiene line-coverage percentage can be read locally and none is asserted. CI (`.github/workflows/_pester.yml`, which asserts `LINE` at 80 over `scripts/hygiene`) measures it. Locally, each added statement is mapped to a named passing test (P2-T4). The limitation is recorded by P0-T16.

## Execution rules for every task

- **Bash discipline (binding, pass verbatim to the executor).** Never use `cd`. Address the item worktree with `git -C <worktree-root> ...` for every git command, and pass absolute paths to every other tool. Never invoke grep, sed, awk, cat, head, tail, find, cp, mv, rm or echo through Bash; use the Grep, Read, Glob, Edit and Write tools with absolute paths instead. The only Bash forms permitted are single commands (no `&&`, `;` or `|` chaining) whose first token is `git`, `pwsh` or `poetry`, plus the three `.claude/lib/bash/*.sh` scripts. If a shell step is genuinely needed, run it as one `pwsh -NoProfile -Command '...'` invocation with the worktree path inside the command string, never as a `cd`. If the shell refuses a `pwsh` or `git` form, stop and report BLOCKED; do not substitute another tool. Tasks P0-T12, P1-T9 and P2-T17 run `pwsh` through the shell. A worktree-isolated executor's shell refuses every `pwsh` form, so these three tasks require a non-isolated executor; when the shell refuses the form, stop at that task and report BLOCKED.
- `<worktree-root>` is a placeholder for the absolute path of the item worktree. Substitute it at run time in every tool call. In every evidence file and in the `Command:` field write the placeholder `<worktree-root>`, never the literal absolute path. The repository hygiene guard flags a tracked file outside `.claude/` that contains a drive-letter user-profile path, so no evidence file may carry one. Before finishing each task, read the evidence file back and redact any absolute host path, drive letter path, machine name or account name. Raw tool documents (the junit and coverage XML) are never copied or committed; evidence records only the counts and the repository-relative test names stated in the task.
- `<TS>` in an artifact file name is the write time formatted `yyyy-MM-ddTHH-mm`, equal to the artifact's own `Timestamp:` value. The only fixed artifact name is `phase0-instructions-read.md`. Every artifact path below is written in full under `docs/features/active/2026-10-01-remaining-tracked-backup-files-and-hygiene-guard-rule-961/evidence/<kind>/`; the only kinds used are `baseline`, `qa-gates`, `regression-testing` and `other`.
- Anchor every diff to the commit `BASE-SHA`, the value printed by `git merge-base origin/main HEAD` and recorded by P0-T3. Substitute the recorded 40-hex-digit value wherever a command below shows `<BASE-SHA>`, and write `<BASE-SHA>` in evidence files. The plan never diffs against the ref `origin/main` itself: that ref is shared by every worktree and advances when a sibling item merges, whereas the merge-base stays at this branch's fork point until HEAD is rewritten. The plan never runs `git fetch` and never merges or rebases.
- PoshQC tools: `mcp__drm-copilot__run_poshqc_format`, `mcp__drm-copilot__run_poshqc_analyze` and `mcp__drm-copilot__run_poshqc_test` are called with `workspace_root` set to the substituted worktree root. Format and analyze use `scan_folders` equal to `["scripts/hygiene", "tests/scripts/hygiene"]`; test uses `scan_folders` equal to `["tests/scripts/hygiene"]`. The tools return a short summary and no numbers, so each task states its own observation. For a PoshQC call, `EXIT_CODE` records 0 when the tool returned an ok result and 1 otherwise. The junit document `artifacts/pester/pester-junit.xml` is read with the Read tool (lines 1 to 2) and the Grep tool with that explicit file path (ripgrep skips the git-ignored `artifacts/` tree unless the file is named explicitly). In that document the root element is `testsuites`, each test is one `<testcase name="<Describe>.<It name>" status="Passed|Failed" ...` line, and the root attributes `tests`, `errors` and `failures` are single-line tokens.
- Test counts are mechanical. The baseline is 31 tests (7 + 19 + 5 `It` blocks across the three files under `tests/scripts/hygiene`). This plan adds 10 `It` blocks to the rules test file and 4 to the orchestration test file, so the post-change count is 45 after Phase 2. No `-ForEach` or `-TestCases` is used in Phases 0-2 (amended by Phase 3, task CR-1: the lookalike case becomes one `-ForEach` `It` of five expansions, so the count after Phase 3 is 49).
