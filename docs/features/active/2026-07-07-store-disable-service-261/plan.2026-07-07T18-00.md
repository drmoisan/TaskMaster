**Fixed F1 contract (binding on all phases; sourced from `spec.md` §3–§6 and `epic-plan.md` "Shared Design Alignment"):**
- Pure `StoreIdentity.Resolve(string displayName, string filePathFallback = null)` — DisplayName primary, `filePathFallback` only when DisplayName is null/whitespace, documented sentinel otherwise; no COM, no I/O. A separate `StoreIdentity.Resolve(Outlook.Store store)` COM overload is reserved for filter-time call sites only.
- `IStoreDisableService` exposed on `IApplicationGlobals` member `StoreDisable`, with `void DisableSessionOnly(StoreIdentity)`, `void DisableForFutureSessions(StoreIdentity)` (persists), `Task ReenableAsync(StoreIdentity)`, `bool IsDisabled(StoreIdentity)`, `IReadOnlyCollection<DisabledStoreEntry> GetDisabledStores()`.
- Injected `IStoreRehookService` NO-OP-default seam is the sole F1↔F3 boundary; F1 takes NO forward dependency on any F3 type.
- Persisted `[JsonProperty] List<string> DisabledStoreIdentities` + `[JsonIgnore] HashSet<string> SessionDisabledStoreIdentities` (OrdinalIgnoreCase) on `StoresWrapper`.
- New `Disabled` reason in `StoreFilterAttribution.Decide` checked LAST (enum order `PublicFolder, NameContains, GwsoFilePath, FilePathContains, Disabled, Included`), applied identically at all three surfaces (`ShouldIncludeStore`, `StoreIsIncluded`, `ShouldIncludeStoreInstrumented`), with existing attribution byte-for-byte unchanged.

**Spec Reconciliation (binding realization for `StoreIdentity` and `DisabledStoreEntry`):** `spec.md` §3.1 and §4.1 prescribe `readonly record struct` with `{ get; init; }` accessors. That form is NOT compilable on this repository's .NET Framework 4.8 target: there is no `System.Runtime.CompilerServices.IsExternalInit` polyfill, so any `init` accessor (including those generated by a `record`/`record struct`) fails with CS0518 and breaks the analyzer and nullable/`TreatWarningsAsErrors` gates. The BINDING realization for both types is a plain `public readonly struct` with an ordinary constructor and get-only auto-properties (`{ get; }`), mirroring the documented `ResourceTimingRow` pattern in `UtilitiesCS/EmailIntelligence/IntelligenceConfig.cs` (~line 165) and the `net48` note in `TaskMaster/AppGlobals/HookReadinessCoordinator.cs` (line 12). `StoreIdentity` is constructed only via its `Resolve` factory; `DisabledStoreEntry` is constructed only via its public constructor. `spec.md` §3.1 and §4.1 have been updated to this form; where any spec text still implies `init`, the plain-struct form here governs.
