## Execution conventions

- **Shell.** PowerShell. A `-Command` payload that contains `$` is single-quoted so the parent shell does not expand it; literal double quotes inside such a payload are doubled.
- **Line counting.** File line counts are taken with `(Get-Content -LiteralPath <path>).Count`. Do not use `Measure-Object -Line`; the two disagree on files without a trailing newline.
- **vstest resolution.** `$vstest` is the single path returned by `& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -find "Common7\IDE\Extensions\TestPlatform\vstest.console.exe" | Select-Object -First 1`.
- **Test runs.** Every test run, filtered or not, adds `/InIsolation`, `"/Logger:trx;LogFileName=p<N>-t<M>.trx"` and an explicit `/ResultsDirectory:` naming the canonical evidence kind directory for that task's phase — `…\evidence\regression-testing` for Phases 1 through 9, `…\evidence\baseline` for Phase 0, `…\evidence\qa-gates` for Phase 11 — written out as a full path, for example `/ResultsDirectory:docs\features\active\itemviewer-surface-defects-489\evidence\regression-testing`. A TRX written without an explicit `/ResultsDirectory:` lands in `TestResults\` relative to the working directory and the artifact-existence acceptance becomes unsatisfiable. `LogFileName=` is also what keeps the default `<account>_<HOST>_<timestamp>.trx` naming out of the evidence tree.
- **Full-suite coverage runs.** `pwsh -File scripts/vscode/Invoke-MSTestWithCoverage.ps1 -SearchRoot . -Configuration Debug -CoverageOutput coverage\coverage.cobertura.xml`. `-SearchRoot .` is mandatory: the sibling `Invoke-MSTest.ps1` throws under StrictMode when a single assembly matches. The script resolves its repo root from its own directory, which is this worktree root, so discovery never reaches a nested worktree. A substring assertion that a discovered assembly path does not contain `\.claude\` is **unsatisfiable by construction** — this worktree root itself lies under `.claude\worktrees\`. The satisfiable form is: strip the worktree-root prefix from each discovered path and assert no remaining path segment equals `.claude`.
- **Diff gates.** `BASELINE_SHA` is the commit recorded in P0-T6. Diff gates use the single-commit working-tree form `git diff --name-only <BASELINE_SHA> -- <pathspec>`, never the two-dot form. Two pathspec widths are used deliberately and they are not interchangeable. A **scope-lock or clean-tree** gate — P10-T2, P11-T2, P11-T15 and P12-T63 — enumerates the **full C# project set**: `QuickFiler/ QuickFiler.Test/ UtilitiesCS/ UtilitiesCS.Test/ ToDoModel/ ToDoModel.Test/ Tags/ Tags.Test/ TaskMaster/ TaskMaster.Test/ TaskTree/ TaskTree.Test/ TaskVisualization/ TaskVisualization.Test/ TaskVisualizer/ SVGControl/ SVGControl.Test/ VBFunctions/ VBFunctions.Test/`. That is every directory holding a tracked `*.csproj` (eighteen of them) plus `TaskVisualizer/`, so no C# project sits outside such a gate; a narrower set would let an edit or a format rewrite outside `QuickFiler/`, `QuickFiler.Test/` and `UtilitiesCS/` pass every lock in this plan unobserved. A **targeted presence or absence** check — P6-T6, P8-T13, P10-T1, P10-T9 — names only the directory holding the path it asserts about, because widening it cannot change that assertion's outcome. `.claude/agent-memory/` and `docs/` are tracked and are deliberately outside every scope-lock pathspec. `.claude/agent-memory/` is outside **every** pathspec in this plan without exception — its contents are tracked, not gitignored, and the executing agent writes into it during a run of this size, so any unscoped `git status --porcelain` or `git diff` gate is unsatisfiable by construction. No file count is asserted for that directory anywhere in this plan: the number drifts as agents write and the argument does not depend on it. `docs/` is outside every scope-lock **diff** pathspec; the single deliberate exception is P12-T63's final commit-completeness porcelain, which re-admits this feature's own folder `docs/features/active/itemviewer-surface-defects-489/` because proving that folder is committed is exactly what that task exists to do.
- **Expected exit codes.** Several gates in this plan run a command that exits non-zero on a passing outcome. Under the evidence schema an artifact whose observed `EXIT_CODE:` differs from its expectation normalizes to `fail`, and the expectation defaults to `0` when `ExpectedExitCode:` is absent. Every such artifact therefore declares `ExpectedExitCode:` explicitly: P0-T9 and P11-T3 (`csharpier check .` exits `1` whenever any file is unformatted), P0-T13, P11-T7 and P11-T12 (`vstest.console.exe` exits non-zero whenever any executed test fails, and a sibling-owned pre-existing failure is tolerated), and P0-T14 and P11-T8 (`Invoke-MSTestWithCoverage.ps1` throws both on a failing test in the search root and on a sub-80-percent line rate). The `ExpectedExitCode:` field is per-file, so each of these gates keeps its own artifact. Gates that wrap a `git grep` in `(… | Measure-Object).Count` — P0-T16, P0-T17, P4-T7, P9-T8, P10-T15 — need no such declaration because the wrapper makes the pipeline's own exit code `0`.
- **Untracked files.** `git add -N` is run before any diff or `git grep` gate that must observe a file this plan created. `git diff` does not see untracked files and `git grep` does not search them.
- **MSBuild file logs.** MSBuild file logs are written with a `.msbuild.txt` extension, not `.log`: `.gitignore:84` is `*.log`, so a `.log` artifact under `FEATURE/evidence/` can never be committed and would be absent from the audit trail while every porcelain gate still reported clean. This applies to P0-T11 and P11-T4, the only two tasks in this plan that pass `/fl "/flp:LogFile=…"`, and to P11-T5, which reads the P11-T4 log. No other evidence extension this plan writes is matched by `.gitignore`: `*.md` and `*.trx` are not listed, and the raw Cobertura output at `coverage/coverage.cobertura.xml` is deliberately gitignored by `coverage/*` and is not an evidence artifact.
- **Restart rule.** The Phase 11 toolchain loop restarts from its first command stage whenever any stage fails or rewrites a file. The loop may not be exited while any stage is failing.
