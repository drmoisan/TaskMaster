## Decisions Record

**D1 — Accepted design.** Section 9 of `docs/features/active/2026-09-08-ilglobals-loadopcodes-unsynchronised-static-race-824/research/ilglobals-static-publication-2026-09-08T23-45.md` is the accepted design: both opcode tables become `public static readonly` with no initializer, an explicit private static constructor builds each `OpCode[0x100]` in a local, runs the reflection loop to completion against those locals, and assigns each field exactly once after the loop; `LoadOpCodes()` is retained with the body `RuntimeHelpers.RunClassConstructor(typeof(ILGlobals).TypeHandle);`.

**D2 — Gate qualification.** The failure is intermittent (observed once in ten full-suite runs) and does not reproduce on demand. No acceptance condition in this plan is keyed to a repeated-run count, to a count of consecutive green runs, or to the exit code of a single run of a known-intermittent test. The two gates are AC2 (`LoadOpCodes_DoesNotRepublishPublishedTables`, FluentAssertions `BeSameAs`) and AC3 (`SingleByteOpCodes_FieldIsInitOnly` and `MultiByteOpCodes_FieldIsInitOnly`, `FieldInfo.IsInitOnly`). AC4's exhaustive population test passes on the unfixed tree and is a supporting test only; no task, artifact, or report in this plan may present it as evidence that the race is fixed.

**D3 — Prohibited stabilisation mechanisms.** No `Thread.Sleep`, no `Task.Delay`, no retry, no timing tolerance, no concurrency-sampling test, no additional thread, and no temporary file anywhere in the delivered tests or in any mechanism used to make them pass. The harness liveness rule in D8 is a rule about terminating a hung test host and is part of no acceptance condition.

**D4 — Test ordering rationale.** The AC4 test and the AC7 renames read the static tables without calling `LoadOpCodes()`. On the unfixed tree that read returns `null` unless some earlier test class already called `LoadOpCodes()`, which makes those tests order-dependent before the fix. They are therefore introduced in Phase 3, after the fix lands in Phase 2, and never run against the unfixed tree. The AC2 and AC3 tests are order-independent red on the unfixed tree and are introduced in Phase 1.

**D5 — Base anchor.** Phase 0 records `BASE_REF` as the output of `git merge-base HEAD origin/main`. Every `git diff` in this plan supplies `BASE_REF` as an explicit ref operand; no bare `git diff` appears. Every name-listing diff is paired with a `git add -N` span or a `git status --porcelain --untracked-files=all` span, because an anchored name-listing diff is blind to untracked files and porcelain goes empty once a change is committed. The plan pins no SHA value: `BASE_REF` is resolved at execution time and recorded as evidence.

**D6 — Owned Write Set rule (a rule, not a fixed list).** At every scope gate, a path is in scope if and only if it satisfies one of these three classes:

1. it is one of the two modified source files named in Scope;

**D11 — Bash discipline.** Only `git *`, `pwsh *`, `poetry run *` and the allowlisted `.claude/lib` scripts run without prompting, and every `&&` or `|` segment of a command is checked independently. No task may use `cd X && ...`, `grep`, `sed`, `cat`, `ls`, `cp`, `mv`, or `mkdir` through the Bash tool. File inspection goes through the Read, Grep, and Glob tools. Directories are created with `pwsh -NoProfile -Command 'New-Item -ItemType Directory -Force -Path <path>'`. msbuild and vstest run through `pwsh -NoProfile` because the Bash tool mangles MSBuild switches (`/m` becomes `M:/`). A refusal is not authorisation to skip the task, and the command is not weakened or reshaped to evade the guard.

**D12 — Command authoring rules.** Wrap the whole payload in single quotes for the Bash tool and use double quotes inside for PowerShell. Author no doubled backslash in any command string: derive Windows separators from data, or use forward slashes, because a doubled backslash can be silently collapsed in transit and the degraded command still produces a number. Inside a `Select-String` pattern, `\x22` is a double quote, `\x5C` is a backslash, and `\|` is a literal pipe rather than alternation. No shell variable survives from one task to the next: each command resolves everything it needs within its own invocation.

**D13 — MSBuild and vstest resolution.** MSBuild: `& "${env:ProgramFiles(x86)}/Microsoft Visual Studio/Installer/vswhere.exe" -latest -requires Microsoft.Component.MSBuild -find "MSBuild\**\Bin\MSBuild.exe" | Select-Object -First 1`, the form used by `scripts/vscode/Invoke-Restore.ps1:27`. vstest: the same vswhere with `-latest -products * -find "Common7\IDE\Extensions\TestPlatform\vstest.console.exe"`. **D14 — msbuild assertion facts (measured in this repository).** A successful msbuild run prints the word `error` roughly 35 times, and `Select-String` is case-insensitive by default, so an acceptance condition of the form "no console line contains `error`" is unsatisfiable. Use the summary line `^\s*0 Error\(s\)$` and the MSBuild diagnostic form `: error [A-Z]+[0-9]+:`; for warnings use `: warning [A-Z]+[0-9]+:`, not the bare word. MSBuild's timestamp-based up-to-date check does not invalidate on a command-line `/p:` change, so an analyzer or nullable gate evidenced only by `EXIT_CODE: 0` cannot fail. Both gate commands use `/t:Rebuild` and both directions are asserted: `Skipping target "CoreCompile"` count equals 0, and `^\s*CoreCompile:` count is greater than 0 with the number recorded. The spelling `Task "Csc"` is not used: it reads 0 on a genuinely non-vacuous compile at default verbosity. The analyzer gate and the nullable gate legitimately produce different `CoreCompile:` counts on the same tree; a mismatch between them is not a defect.

**D15 — TRX count rule.** Where a task asserts test counts it reads them from the TRX rather than from console prose. The command shape, with only the results directory varying, is:

`pwsh -NoProfile -Command '$t = Get-ChildItem coverage/<resultsdir> -Recurse -Filter *.trx | Sort-Object LastWriteTime -Descending | Select-Object -First 1; [xml]$x = Get-Content $t.FullName -Raw; $ns = New-Object System.Xml.XmlNamespaceManager($x.NameTable); $ns.AddNamespace("t","http://microsoft.com/schemas/VisualStudio/TeamTest/2010"); $r = @($x.SelectNodes("//t:UnitTestResult", $ns)); Write-Output ("TOTAL=" + $r.Count); Write-Output ("PASSED=" + @($r | Where-Object { $_.outcome -eq "Passed" }).Count); Write-Output ("FAILED=" + @($r | Where-Object { $_.outcome -eq "Failed" }).Count); foreach ($u in $r) { Write-Output ($u.testName + " " + $u.outcome) }'`

Each task using it gives its own results directory. The `Sort-Object LastWriteTime -Descending` stage is load-bearing and is not an optimisation: the default TRX filename is `<account>_<machine>_<per-second timestamp>_net<tfm>.trx`, vstest never overwrites, and directory enumeration is filename-ordered, so a second run into the same results directory leaves two TRX files and an unsorted `Select-Object -First 1` selects the older one. Without the sort those gates would be evaluated against a superseded run. Each task that uses this shape additionally records the selected TRX's `LastWriteTime` and the count of TRX files found in its results directory. TRX files carry host tokens and are never committed; they stay under `coverage/`.
