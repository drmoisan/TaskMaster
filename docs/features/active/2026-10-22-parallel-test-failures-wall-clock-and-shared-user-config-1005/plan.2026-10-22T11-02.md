## Hard Constraints (bind every task)

- All tests pass when run in parallel. A parallel failure is fixed by removing the shared or timed state, never by serializing: no `Workers` value of one, no `[DoNotParallelize]` added, no retries, no `Thread.Sleep`, no `Task.Delay`, and no longer timeout.
- No test creates a temporary file, and no test writes, redirects, or relocates `user.config`. Settings persistence goes through the per-instance `ISettingsStore` seam (`ApplicationSettingsStore` adapter per spec D2); production defaults keep the current `Properties.Settings.Default` write followed by `Save()`; tests supply `InMemorySettingsStore` or a Moq `Mock<ISettingsStore>`. No static mutable seam and no process-wide `SettingsProvider` is introduced.
- Every settings-saving probe that subscribes to a static `SettingsSaving` event records only saves raised on the subscribing test thread, sets `Cancel` on those saves so nothing is written, and unsubscribes in a `finally` block.
- DfDeedle: the tests use the existing `columnAdder` and `timeProvider` parameters of `AddQfcColumnsAsync` with the already-referenced `FakeTimeProvider`; no NuGet dependency is added and no production file under `UtilitiesCS/Extensions/` changes.
- AC4: the before and after searches are recorded under `<FEATURE>/evidence/regression-testing/`, and every match is fixed in this item.
- Bugfix workflow: fail-before evidence (Phase 1) precedes every fix; each fix is minimal.
- MSTest, Moq, and FluentAssertions only. New seam code reaches at least 90 percent line coverage; changed lines lose no coverage; no `[ExcludeFromCodeCoverage]` is added.
- Every created or modified `.cs` file ends at or under 500 physical lines; `UtilitiesCS.Test/Extensions/DfDeedle_COM_Tests.cs` and `TaskMaster/AppGlobals/AppAutoFileObjects.cs` (already above 500) are split into partials and end smaller than at the merge base.
- Legacy non-SDK projects: every new `.cs` file gets a `<Compile Include>` in its project file in the same task. `ToDoModel.Test`, `TaskTree.Test`, and `QuickFiler.Test` are C# 7.3 (no nullable annotations, target-typed `new()`, `is not`, switch expressions, or `using` declarations). `UtilitiesCS` is C# 12 and new UtilitiesCS and UtilitiesCS.Test files carry `#nullable enable`. `ToDoModel` (latest) and `TaskMaster` (preview) files touched here carry no `#nullable enable` today and gain no nullable annotations.
- The executor does not commit; the orchestrator commits after execution. No task edits `.claude/**` or `CLAUDE.md`.
- Out of scope (issue #1006, already filed): tests that mutate `Settings.Default` in memory without saving, and the per-method `[DoNotParallelize]` in `ApplicationGlobalsStartupTimingTests`. Production `Save()` sites no test reaches (`AppOlObjects.cs` and `AppOlObjects.JunkFolders.cs`) are not changed.
