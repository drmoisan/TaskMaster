## Execution environment notes (record only; not an action)

- **Worktree isolation.** `pwsh` is refused under Agent worktree isolation. The execution child for
  this item must therefore be launched **without** worktree isolation, or every command-bearing task
  below is unrunnable.
- **Bash allowlist.** Only `git`, `gh`, `pwsh`, `poetry run` and the three `.claude/lib` scripts are
  granted, and every chained segment is checked independently. Never write a command of the form
  `cd SOMEWHERE && something`. Use `git -C` for git. There is no Python toolchain in this
  repository; no task below invokes one, and no task below relies on a scripts/dev_tools tree or an
  extensions tree, neither of which exists here.
- **Command transport.** Prefer the PowerShell tool for every PowerShell payload below. When the
  Bash tool is used instead, wrap the payload as `pwsh -NoProfile -Command '<payload>'` with
  **outer single quotes and inner double quotes**. An outer-double-quoted payload is consumed by the
  calling shell and produces a spurious failure. No acceptance condition in this plan requires a
  shell pipeline; every search reads a file on disk so that no chained segment is introduced.
- **Select-String patterns.** A backslash-pipe inside a Select-String pattern is a literal pipe, not
  alternation. Use `\x5C` for a backslash and `\x22` for a double quote rather than escaping them
  directly. A search for a literal beginning with a forward slash must use a bracketed character
  class for that slash, because Git Bash rewrites a leading-slash argument into a Windows path.
- **Test-run summary lines.** On an all-green run `vstest.console.exe` prints only `Test Run Successful.`, `Total tests:`, `Passed:` and `Total time:`; it prints no `Failed:` line and no `Skipped:` line, and that holds with and without a settings file and under `dotnet-coverage collect`. Wherever a task below records the Total, Passed, Failed and Skipped counts, Total and Passed are read from those lines; Failed and Skipped are read when their lines are present and otherwise derived, a summary carrying no `Failed:` line meaning a Failed count of 0 and the Skipped count being `Total tests` minus `Passed` minus Failed. Each artifact states, for each of the four values, whether it was read or derived. Where a task passes a TRX logger, that document's `Counters` element may supply `failed`, but its `notExecuted` attribute is hard-coded to 0 by the TRX logger and is never the skipped count, so Skipped is derived there as well.
- **Helper scripts.** No throwaway helper script is written into the repository. Any scratch file
  goes in the session scratchpad.

## Design summary (what the change is)

Conjoin a live dispatcher-identity re-verification into the `_uiSyncContext` exit of
`SynchronizationContextAwaiter.IsCompleted`, so that exit returns `true` only when the captured
context is the persistent UI context **and** a non-null captured UI dispatcher is reference-equal to
the WPF dispatcher of the executing thread. The exit is at lines 176-179 of the pre-change file and
is the fourth of the accessor's five exits, which occupy lines 155-190: the ambient-identity `true`
at 160-163, the null-ambient `false` at 167-170, the thread-id guard `false` at 171-174, the
`_uiSyncContext` `true` at 176-179, and the dispatcher expression at 184-188. No other exit changes.

Two new test classes go in one new test file, and one positive twin goes beside the existing
`IsCompleted` cases. The retry test in the init-contract test file gains an explicit apartment
assertion and a message constraint. A runtime apartment measurement discharges clause (i) of issue
809's AC5 and a three-repetition run discharges clause (ii).

Two names are fixed here so that no later task selects them: the two negative predicate cases live in
a test class named `UiThreadPredicateHardening_Tests` and the measurement lives in a test class named
`UiThreadApartmentMeasurement_Tests`. Both are declared in the one new file and both carry
`[DoNotParallelize]`.

Out of scope, stated in plain prose so that no excluded path enters the change footprint: the
WPF-dispatcher-operation leg, which must keep returning true; ordering assertions at the eleven
production await sites issue 809 enumerated; the IsCurrentBoundary method of the QuickFiler
breadcrumb dispatcher, which the research of record establishes is not a call site of this awaiter;
the alternative hardening that hoists the dispatcher check above both post-guard exits; reverting the
threading source to its pre-fix state to take the measurement; the UtilitiesCS production project
file, which needs no item because this change adds no production source file; the injectable
dispatcher seam conversion, which belongs to issue 584; and any change to the initializer or its
retry behaviour.
