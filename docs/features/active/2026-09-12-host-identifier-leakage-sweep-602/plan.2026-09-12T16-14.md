## Authoring invariants that bind this document

**Redaction invariant.** This plan is a tracked file. Writing the account name, the host name, the
8.3 short-name form of the account, or an absolute user-profile path into it would re-create the
defect and falsify AC1, AC2 and AC4 by self-reference. Every acceptance command below derives its
tokens from environment values at run time, inside a single PowerShell invocation. The identifiers are
referred to by class, or by the backslash-escaped placeholder tokens \<user-profile\>, \<user\> and
\<host\>, and only in Markdown prose. The canonical convention record is the shared
no-absolute-host-paths document under the agent-memory tree; this plan cites it rather than restating
it. No evidence artifact records a raw before-value, a matched path whose filename carries an
identifier, or a verbatim tool line containing an absolute path; artifacts record counts, booleans,
exit codes, summary lines, rule names and test names.

**XML invariant.** No angle-bracket token appears anywhere in this plan in a position shaped like an
XML attribute value or XML element text, including inside an example. AC8 is asserted structurally:
by the XML-family inventory falling to four, by the four-file load gate, by the deletion-only diff
filter over XML-family paths, and by the transform's throw-on-XML-extension unit test. It is never
asserted by searching for a bracketed token, which is not a checkable literal. One declared exception
is required by the spec: the account-name acceptance search carries a negated preceding-character
class whose members are an at-sign, the alphanumerics and an opening angle bracket. Without the
bracket member the search fires on its own remediation, because the token this item substitutes is
itself preceded by an opening angle bracket. The character appears there as a member of a negated
character class, not as a placeholder token, and the enclosing search is falsifiable by measurement:
it returns a four-digit count before the sweep and exactly one after.

**Blast-radius invariant — do not add or remove backticks.** A downstream scheduler derives this
item's change footprint by harvesting whitespace-free backticked tokens from this plan and from the
spec, with no notion of polarity. Every path the diff creates, modifies or deletes appears below as a
backticked repository-relative path or path class, and the set mirrors the spec's Write Set exactly.
Paths this item deliberately does not touch are written in plain prose with no code span: the
agent-governance settings file under the agent directory, the staged promotion directory under the
features tree, the concurrent-run documentation directory under the features tree, the two agent
configuration files at the repository root, the agent instruction file at the repository root, and
the VS Code scripts directory. Policy files are read-by-mandate citations and are filtered out of
the derivation wherever they appear in this plan, which includes the two cited as code spans in the
P1-T7 coverage-bar argument as well as those in the Phase 0 read task. Locations outside the Write
Set that a command
must name, such as the repository's already-ignored coverage drop directory, appear only inside
multi-word command spans or in plain prose, never as a single-token code span.

**Every acceptance search is case-insensitive.** The case-sensitive host count is twenty files below
the case-insensitive count, because the test runner lower-cases one attribute while leaving another
mixed-case. A case-sensitive gate passes while the leak survives.

**Every staging span, porcelain span, diff span and acceptance search excludes the staged promotion
directory**, carried as an exclude-magic pathspec operand inside the command span. An unscoped
pathspec sweeps a sibling item's queued promotion file onto this branch. Staging is never
`git add -A`: it is an update-tracked staging span plus an explicit add of the paths this item
creates, so an untracked directory belonging to the concurrent run is never staged.

**Leading forward slashes sit inside a bracketed character class.** Git Bash rewrites a leading
forward slash in a search literal into a Windows path before git sees it; a bracket expression is not
path-shaped and survives the rewrite. The class is kept in the PowerShell-emitted forms too.

**The word naming the GNU concurrency utility appears nowhere in this plan.** The shell filter
refuses it anywhere in a command string, including inside a pathspec operand. One member of the
population is a document under the one-off research directory whose filename contains that word; it
is reached only by the sweep script's own directory enumeration and is never named. No command span
names the concurrent-run documentation directory either.

## Execution-environment preconditions

1. **The execution child must run without worktree isolation.** Verified by direct probe this run:
   under isolation the shell tool refuses a command carrying a shell variable expansion, refuses any
   invocation of the PowerShell executable, and refuses a redirect to another checkout. Task P0-T2 is
   the precondition probe and halts the run if either refusal occurs.
2. **A preflight reviewer runs under isolation and cannot execute these commands.** It validates them
   by construction, by reading the expressions and confirming their shape, and must say so. A
   preflight report claiming to have executed them under isolation is not evidence.
3. **The shell allowlist grants only git, gh, pwsh, poetry run and three library scripts, and every
   chained segment is checked independently.** A bare shell assignment is itself a non-allowlisted
   segment. Every literal-free acceptance command below is therefore one segment whose first token is
   the PowerShell executable; the token derivation happens inside the invocation and a labelled count
   is printed. Outer quoting is single quotes and every inner string literal uses double quotes; no
   single quote appears inside any invocation, and where a quote character is needed inside a regular
   expression it is built from its character code.
4. **A count-producing invocation does not exit zero when nothing matched.** The tracked-only
   search exits 1 when it selects no line, and a PowerShell invocation propagates the exit code of
   the last native command it ran, so a terminal-zero gate would otherwise record a non-zero exit
   code with no declared expectation and its evidence row would normalise to a failure. Every count
   gate below is decided by the printed labelled number, never by the exit code, and each such task
   says so. Every invocation whose expected terminal state is a zero count therefore ends with an
   explicit zero exit statement, and the paired baseline invocation carries the same trailing
   statement so that the two command texts stay identical.
5. **No shell variable survives between tasks.** Every invocation derives the account leaf, the
   short-name prefix, the host token and the stem inline.
6. **This repository has no Python toolchain**, no developer-tools Python tree and no extensions
   tree. No task plans around one.
7. **Every PoshQC invocation passes an explicit scan-folder list.** The Pester runsettings file the
   PowerShell rule cites does not exist here, and the scan-configuration file the PoshQC test tool
   reads is also absent, so no configured default resolves. The PoshQC tools return an ok flag and a
   prose summary with no counts; their result is recorded as a reachability observation and is never
   the gate. Rule-by-rule and test-by-test decisions come from direct analyzer and Pester runs. If a
   PoshQC tool is unavailable to the executor, the task records that fact and the direct run carries
   the whole gate; unavailability never halts the run.
8. **Every command runs with the current directory at the checkout root**, and every path is
   repository-relative. The plan pins no commit value; task P0-T4 records the anchor.

## Token derivation used by every acceptance command

Inside each PowerShell invocation: the account leaf is the leaf of the user-profile environment value;
the short-name prefix is the first six characters of that leaf, upper-cased, followed by a tilde; the
host token is the computer-name environment value; the stem is that value with its trailing digit run
removed. The exclusion operand is the exclude-magic pathspec naming the staged promotion directory.
The profile-path expression accepts both the account leaf and the short-name prefix followed by a
digit as its account segment. The short-name residual search is a fixed-string search for the
six-character-plus-tilde token, which is a superset of the digit-suffixed form, so its terminal zero
is at least as strong as the spec's wording. Task P0-T11 proves the stem derivation is sound without
printing any token: the stem population must be strictly larger than the full-token population and
strictly smaller than the tracked-file total.

### Phase 1 — The sweep transform, its driver, and their pure unit tests

The transform is a pure function: text, the extension of the file the text came from, and the rule
parameters in; text out. It performs no filesystem access, which is what makes every ordering and
idempotency case a pure unit test. Temporary files in tests are prohibited by policy, and that
prohibition shapes the function signature rather than being worked around. The driver is a thin
enumerate-read-transform-write loop over exactly the eight script-modified path classes declared in
the Write Set, with the enumerator, the reader and the writer exposed as narrow injectable
script-block parameters whose defaults touch the real filesystem, so that the driver's own branches
are unit-tested with in-memory substitutes. The driver refuses every path under the staged promotion
directory, writes a file only when the transform changed its text, preserves each rewritten file's
byte-order mark and line-ending convention, defaults to detect mode, rewrites only under an explicit
apply switch, and declares supports-should-process on the apply path. The transform throws when the
supplied extension is in the XML family (the test-result extension, the XML extension, the Visual
