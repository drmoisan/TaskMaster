## Planning Contract

This is a minimal-audit plan for issue #243. The only authoritative acceptance criteria source is the explicit `## Acceptance Criteria` section in docs/features/active/2026-07-06-appevents-loadasync-inbox-gating-243/issue.md. This plan must not require spec.md, user-story.md, or research.md.

The objective is to fix the AppEvents.LoadAsync startup race where LoadAsync calls ProcessNewInboxItemsAsync before the Outlook readiness polling path has populated OlInboxes. ProcessNewInboxItemsAsync must run only after the same readiness checks that hook OlInboxes have passed, while preserving deferred readiness polling and existing event subscription behavior.

In-scope C# files for constrained implementation are:
- TaskMaster/AppGlobals/AppEvents.cs
- TaskMaster/AppGlobals/AppEvents.ReadinessHookup.cs
- TaskMaster/AppGlobals/HookReadinessCoordinator.cs
- TaskMaster.Test/AppGlobals/AppEventsTests.cs
- TaskMaster.Test/AppGlobals/HookReadinessCoordinatorTests.cs
