## Design decisions locked in by this plan (read before executing)

1. **`FolderPredictor` seam is an interface + factory-delegate combination**, not delegate-only. `TextBoxSearch_TextChanged` (`#27`) calls `_folderHandler.FindFolder(...)`, which walks live Outlook folders (`FolderPredictor.cs:280` `GetMatchingFolders`) — genuinely COM-bound and not reachable through the concrete `FolderPredictor` type. The consuming surface (`FolderArray`, `Suggestions`, `FindFolder`) is narrowed to a new interface `IFolderSearchHandler`; `_folderHandler`'s field type becomes `IFolderSearchHandler`; `FolderPredictor` implements it via a **separate partial-file declaration** (see decision 3). Construction still goes through a `Func<..., FolderPredictor>` factory delegate (concrete return type, because `LoadFolderHandlerAsync`'s `Task.Run` body calls `fp.InitAsync(...)`, which is not part of the narrow interface).
2. **`FolderPredictor.cs` is 823 lines today (`UtilitiesCS/OutlookObjects/Folder/FolderPredictor.cs`) — already over the 500-line cap before this cycle.** Splitting it is out of scope (not part of the 17-member/2-seam cycle-3 mandate). This plan touches it with exactly one word (`partial`) and adds zero lines to it; the interface implementation (`: IFolderSearchHandler`) is declared on a **second partial-class file** so `FolderPredictor.cs`'s line count is unchanged by this cycle. This is recorded as a known, deliberate, minimal, pre-existing-condition exception in the final file-size gate (Phase 11), not a new violation.
3. **`Theme.cs` is 544 lines today (`UtilitiesCS/HelperClasses/ThemeHelpers/Theme.cs`) — also already over the 500-line cap.** Because this cycle DOES substantively edit `Theme.cs` (new constructor parameter, new field, three call-site changes), it must end at or under 500 lines. Phase 10 makes `Theme` `partial` and moves the private ~96-line `SetQfcTheme()` method verbatim into a new file `Theme.Rendering.cs`, before making the dispatcher-retrofit edits.
4. **Dispatcher-routing tests verify the changed dispatch call itself (`_uiDispatcher.InvokeAsync`/`.BeginInvoke` invoked once), not full-body execution of `Theme`'s pre-existing, unrelated ~96-line rendering method.** `Theme.SetQfcTheme()` (private) was never part of the `QfcItemController` exemption boundary and carries no `[ExcludeFromCodeCoverage]` of its own; this cycle's coverage obligation is the *changed lines* (the new dispatcher parameter/field and the three retrofitted call sites) and the 3 `QfcItemController` residuals the retrofit unblocks — not retroactive full coverage of `Theme`'s pre-existing rendering internals. This mirrors the already-accepted precedent in this codebase (`SetThemeDark`/`SetThemeLight` tests dodge the same method's body via a parked, never-pumped dispatcher). All new dispatcher-routing tests therefore use non-executing `Mock<IUiDispatcher>` setups (`.Returns(Task.CompletedTask)`/dummy `IAsyncResult`, no `.Callback` that invokes the delegate) and reflection field injection (`typeof(Theme).GetField("_uiDispatcher"/"_lblSender", NonPublic|Instance)`), mirroring the existing `QfcItemControllerTestSupport.SetField` pattern. No new project references (`Microsoft.Web.WebView2.WinForms`, `ObjectListView`/`BrightIdeasSoftware`) are added to `QuickFiler.Test.csproj` or needed in `UtilitiesCS.Test.csproj` (the latter already has them).
5. **Tier 1 `ToggleFocus()`/`ToggleFocus(Enums.ToggleState)` (`#33`/`#35`) do not touch the dispatcher at all** (`Theme.SetQfcTheme(async: false)` bypasses `_uiDispatcher` entirely when `_lblItemNumber.InvokeRequired == false`). Their tests use a non-executing `Mock<IItemViewer>.Invoke(...)` (verifying the marshal call occurred once), mirroring the already-accepted `AssignControls_WhenInvokeRequired_MarshalsViaInvoke` pattern in `QfcItemController.ViewerSetupTests.cs:121-141`. No `Theme` construction is required for these two tests.
6. **New seam-adjacent QuickFiler.Test additions go into the existing seam-test files** (`QfcItemController.SeamDispatcherTests.cs`, 199 lines) rather than the per-cluster files, mirroring the cycle-2 convention (`SeamCoreTests.cs`/`SeamDispatcherTests.cs`/`SeamFactoryTests.cs` already exist as dedicated seam-test files). This keeps `QfcItemController.FocusAndThemeTests.cs` (347 lines) and `QfcItemController.FolderHandlingTests.cs` (193 lines) from approaching the 500-line cap.
7. **Evidence paths.** All evidence in this plan resolves to `docs/features/active/2026-06-29-qfc-item-controller-testability-227/evidence/<kind>/`, per `evidence-and-timestamp-conventions`. No `artifacts/baselines/`, `artifacts/qa/`, or `artifacts/coverage/` paths are used anywhere in this plan.
