## Command conventions

Every `msbuild`, `vstest.console.exe` and `dotnet` invocation in this plan runs through
`pwsh -NoProfile`. The Bash tool mangles MSBuild switches (`/m` is rewritten to `M:/`, producing
MSB1008), so no task in this plan may be executed from a Bash shell. Payloads passed with
`pwsh -NoProfile -Command` are single-quoted so the parent shell does not expand them; literals inside
the payload are double-quoted.

Neither `vstest.console.exe`, `MSBuild.exe` nor `vswhere.exe` is on `PATH` in this environment. Each
task resolves them at run time with the prelude below. No absolute host path, account name or machine
name appears anywhere in this plan.

```
    $vswhere = Join-Path ([Environment]::GetFolderPath("ProgramFilesX86")) "Microsoft Visual Studio\Installer\vswhere.exe"
    $msbuild = & $vswhere -latest -requires Microsoft.Component.MSBuild -find "MSBuild\Current\Bin\MSBuild.exe" | Select-Object -First 1
    $vstest  = & $vswhere -latest -products * -find "Common7\IDE\Extensions\TestPlatform\vstest.console.exe" | Select-Object -First 1
```

Full-suite test-assembly discovery, run from the workspace root. The exclusion is expressed against the
path **relative to the workspace root**, because the workspace root is itself an agent worktree beneath a
`.claude` directory and an absolute-path substring test would exclude every assembly:

```
    $asm = Get-ChildItem -Path . -Recurse -Filter *.Test.dll -File |
        Where-Object { $_.FullName -match "\\bin\\Debug\\" } |
        ForEach-Object { Resolve-Path -Relative $_.FullName } |
        Where-Object { $_ -notmatch "\.claude" }
```

Every `vstest.console.exe` invocation passes `/InIsolation` (mandatory for the Moq-based assemblies and
matching CI) and `/Settings:scripts\vscode\TaskMaster.cli.runsettings`. Every invocation that passes
`/Logger:trx` also passes a `/ResultsDirectory:` whose value ends in that task's own lower-case task-ID
segment, because `vstest.console.exe` otherwise writes the TRX into a `TestResults` folder relative to
the working directory and the acceptance condition would assert against a file the command never
produces at the stated location. Each task's results directory is private to that task so a count-based
acceptance is unambiguous. `vstest.console.exe` 18.x rejects `OR` inside `/TestCaseFilter`; join clauses
with `|`.

The scoped single-assembly form used throughout Phases 1 through 3:

```
    & $vstest "QuickFiler.Test\bin\Debug\QuickFiler.Test.dll" /InIsolation `
        "/Settings:scripts\vscode\TaskMaster.cli.runsettings" `
        "/TestCaseFilter:FullyQualifiedName~<TestName>" /Logger:trx `
        "/ResultsDirectory:docs\features\active\quickfiler-bug-family-446\evidence\regression-testing\<task-id>"
```

The intra-phase compile used before a scoped run (see D-Plan-5):

```
    & $msbuild TaskMaster.sln /t:Build /m /p:Configuration=Debug "/p:Platform=Any CPU"
```

Artifact naming: every evidence artifact is named `<task-id>-<slug>.<ISO-8601 timestamp>.md` using the
`yyyy-MM-ddTHH-mm` timestamp format, for example
`docs/features/active/quickfiler-bug-family-446/evidence/baseline/p0-t9-csharpier-check.2026-08-24T10-15.md`.

## Merge-base and diff-gate convention

Several acceptance criteria are expressed as `git diff ... <mb>...HEAD`. Those gates verify nothing
unless HEAD has advanced past the merge base, so this plan carries an explicit commit task at the end of
every phase. `[P0-T3]` resolves and records the merge-base commit; every later diff gate reads that
recorded value rather than a value pinned in this document. No task in this plan asserts an expected
HEAD sha.

The feature artifacts (plan, spec, issue and research) are already tracked at the merge base, so
`git status --porcelain` carries no guaranteed content at Phase 0. Clean-tree acceptance conditions in
this plan are stated as type assertions ("no path with a `.cs`, `.csproj`, `.props`, `.targets`,
`.sln` or `packages.config` suffix appears") so mid-phase evidence does not trip them, including the
two terminal commit tasks, whose zero-output requirement is scoped to the change-set and
feature-folder pathspecs.
`.claude/agent-memory/` is a tracked directory in this repository, so every scope-lock diff gate in this
plan is explicitly scoped by pathspec and never run unscoped.
