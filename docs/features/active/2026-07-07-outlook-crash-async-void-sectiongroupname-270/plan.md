## Seam design (deterministic, no COM/network/temp files)

The two `async void` COM handlers are refactored to delegate to two `internal async Task` core methods that hold the try/catch. A narrow injectable-delegate seam (`.claude/rules/csharp.md` DI Seams, preference tier 2) lets a deterministic MSTest drive each path with a collaborator that throws. All seam members live in `AppEvents.ReadinessHookup.cs`; `TaskMaster.Test` already sees `internal` members via `InternalsVisibleTo("TaskMaster.Test")` (`TaskMaster/Properties/AssemblyInfo.cs:38`).

Planned members (in `AppEvents.ReadinessHookup.cs`):
- `internal Func<object, System.Threading.Tasks.Task>? InboxItemAddCollaborator { get; set; }` (nullable; default null)
- `internal Func<object, System.Threading.Tasks.Task>? ToDoItemChangeCollaborator { get; set; }` (nullable; default null)
- `internal async Task HandleInboxItemAddAsync(object item)` — awaits `(InboxItemAddCollaborator ?? (i => ProcessMailItemAsync(i)))(item)` inside the try/catch.
- `internal async Task HandleToDoItemChangeAsync(object item)` — awaits `(ToDoItemChangeCollaborator ?? (i => ToDoEvents.OlToDoItems_ItemChange(i, OlToDoItems, Globals)))(item)` inside the try/catch.
- Wrappers become thin host-bound wiring: `internal async void OlInboxItems_ItemAdd(object item) => await HandleInboxItemAddAsync(item);` and `private async void OlToDoItems_ItemChange(object item) => await HandleToDoItemChangeAsync(item);`

Log-and-contain (green state) mirrors the existing pattern in this file (`ProcessStartupInboxItemsAfterReadinessHookup` uses `logger.Error(message, exception)`): `catch (System.Exception ex) { logger.Error("<handler> faulted; contained to prevent process termination.", ex); }`. The original exception object is passed to `logger.Error` so it is preserved (AC3).
