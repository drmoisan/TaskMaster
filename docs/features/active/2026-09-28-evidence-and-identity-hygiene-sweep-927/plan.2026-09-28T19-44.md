## Environment and conventions (binding on every task)

- **C1 Working directory.** Every command runs with the current directory at the worktree root of the branch above. Every path in a command is repository-relative. The executor's worktree may be a different checkout from the one this plan was authored in; P0-T2 verifies identity. The Bash command channel starts pwsh with its process working directory at the session root, and `Set-Location` moves only the PowerShell location, not the directory against which `[System.IO.File]` methods resolve a relative path (measured at preflight). The executor therefore begins every pwsh payload with `Set-Location -LiteralPath <worktree-root>; [System.IO.Directory]::SetCurrentDirectory((Get-Location).Path);`, substituting the absolute worktree root at run time and recording it only as `<repo-root>`. Without it, FORMAT-OBSERVE, the UTF-16 census (P1-T10, P5-T8) and the P7-T3 mark check read the session checkout's copies.
- **C2 Command channel and quoting.** Non-git commands are written as `pwsh -NoProfile -Command '<payload>'` with the payload in single quotes and every inner string literal in double quotes, so neither a Bash nor a PowerShell parent expands `$` before pwsh runs. Re-quoting must preserve that property. Git commands are written bare. A payload that must expose an exit code ends with an explicit `exit`. The Git-Bash argument conversion collapses a doubled backslash to one before pwsh runs, even inside single quotes. A .NET regular expression (Select-String -Pattern, -match) that needs a backslash inside a character class therefore builds it at run time from `$b = [char]92`, writing the class as `"[" + $b + $b + "/]"`. A git grep -E pattern is unaffected, because a POSIX bracket expression treats the surviving single backslash literally.

## Decisions (D1 to D19)

- **D1 One profile-path finding per file.** `Find-UserProfilePathMatch` returns a record for every matching line, but `Invoke-RepositoryHygieneMain` emits one `HYGIENE profile-path <path>:<line>` line per file, carrying the first matching line number. Reason: AC1 defines the pre-sweep findings total as the raw-document population plus the profile-path FILE population, which is a per-file count; a per-line count could not satisfy AC1 by construction. The same file may additionally produce one `HYGIENE raw-document <path>` line, so a raw document that also carries a path contributes two findings, exactly as the two gate populations overlap.
- **D2 Binary records.** A record whose eol listing reads i/-text is read for content only when its first two bytes are FF FE or FE FF (a UTF-16 byte-order mark); otherwise it is classified by extension only (rule A) and skipped for rule B. Reason: UTF-16 files are the one class of tracked text that `git grep -I` omits (it treats them as binary), so gate 4 alone undercounts by exactly the UTF-16 files that carry a profile path. P0-T17 and P1-T10 count those files separately (`UTF16-FILES=`, `UTF16-PROFILE-FILES=`, `UTF16-IDENTIFIER-FILES=`), and the AC1 operand `PROFILE-PATH-FILES:` is GATE4 plus `UTF16-PROFILE-FILES=`, which is the population the guard scans. The P0-T17 run recorded `UTF16-FILES=1` and `UTF16-PROFILE-FILES=0`, but its census pattern reached pwsh with the doubled backslashes collapsed (C2). Measured with a [char]92-built pattern, the one UTF-16 file (the msbuild analyzer baseline in the issue 155 archive folder) carries a drive-rooted profile path, so the AC1 operand is GATE4 plus 1; P1-T10 records the corrected figure.
- **D3 Unreadable rule.** The rule name `unreadable` is emitted when the ReadContent delegate throws. The default delegate decodes by byte-order mark (UTF-8, UTF-16 little-endian, UTF-16 big-endian) and otherwise as UTF-8 without throwing on invalid bytes, so the default never produces this finding on a readable file; a seventh orchestration test pins the branch with a throwing delegate. Reason: a throwing UTF-8 decoder would turn any Latin-1 tracked file into a permanent finding the sweep cannot fix.
- **D4 No list switch.** The entry point gains no `-ListRawDocuments` switch. The removal list is derived from the guard's own output: the paths on lines beginning `HYGIENE raw-document ` from the P2-T12 pre-sweep run, saved under SCRATCH. Reason: the default behaviour stays the only behaviour, and the classifier that CI enforces is the classifier that drove the removal.
- **D5 MSBuild resolution.** `msbuild` is not on PATH in this environment. Every msbuild task resolves the executable in the same payload through vswhere under the thirty-two-bit Program Files Visual Studio Installer directory with `-latest -prerelease -products * -requires Microsoft.Component.MSBuild -find "MSBuild/**/Bin/MSBuild.exe"`, records the leaf name only, and passes the argument list character-for-character as CLAUDE.md writes it. The repository build wrapper is not used because it runs the package-reference synchroniser that rewrites project files. Console output is captured with `Tee-Object` under coverage/logs/ at the default normal verbosity, where each project's csc command line (carrying the /out:obj\Debug\ token) is echoed and a skipped CoreCompile target would print a `Skipping target "CoreCompile"` line.

":!.claude/"`, skipping i/-text records without a UTF-16 byte-order mark, and skipping for writing (never for counting) every record whose extension is .ps1, .psm1 or .psd1 (C16). Rules 1 to 7 are the spec's Proposed Fix table and rule 8 is D17, all built at run time from the environment; the account alternation is the escaped `$env:USERNAME`, the escaped profile leaf when it differs, the escaped eight-dot-three leaf, and the three legacy user tokens named in research section 3.4. Rules 1 to 5 and rule 8 use RegexOptions.IgnoreCase; rules 6 and 7 are case-sensitive (D18). Rule 3 is skipped by path for .mcp.json and .codex/config.toml.
