The first is the direct proof of #486 D3: `WireIntentEvents()` at
`QuickFiler/Controllers/QfcItemController.EventWiring.cs:66` subscribes sixteen intent events —
including the `ConversationModeChanged`, `EmailCopyChanged` and `AttachmentsChanged` siblings — and
subscribes `PicturesChanged` **zero** times, even though `IItemViewer` declares both
`event System.EventHandler PicturesChanged` (`IItemViewer.cs:71`) and
`bool PicturesChecked { get; set; }` (`:72`). The second shows the user-visible consequence: with
the viewer reporting `PicturesChecked == true`, raising the event leaves the controller's cached
`_optionsPictures` (`QfcItemController.cs:57`) at `false`, so the save-pictures option the user
toggled is never read back and `QfcItemController.MailActions.cs:127` files the message with the
stale value.
