## Test-File Sizing Rule (binding on every test-file creation task)

Measured lines-per-test in existing CSharpier-formatted Moq fixtures in `QuickFiler.Test/Controllers/`: `QfcCollectionControllerTests.cs` 38.5, `QfcFormControllerSeamTests.cs` 31.5, `QfcItemController.NavigationTests.cs` 30.1, `QfcItemController.FolderHandlingTests.cs` 29.3, `QfcItemController.FocusAndThemeTests.cs` 29.2, `QfcItemController.EventHandlersTests.cs` 27.4, `QfcFormControllerTests.cs` 20.2 (the leanest in the repo, and itself the deferred 827-line violation tracked by #450). Pure-logic fixtures run 15-18. **The empirical ceiling for a sub-500-line mock-heavy fixture in this project is 17 test methods.**

Therefore:

- A mock-heavy fixture file is capped at **16** `[TestMethod]` members.
- A fixture whose every test builds the full seven-mock controller bundle **plus** a WinForms control graph or an Outlook COM chain is capped at **12**.
- A pure-logic fixture is capped at **16** and its projected size is stated explicitly.
- Splits are taken at member boundaries wherever the cap permits.

**Split-file shape.** Split files follow the in-repo convention set by `QuickFiler.Test/Controllers/QfcStreamingDequeueConfidenceGateTests.Part2.cs` and `.Part3.cs`: the base file carries `[TestClass]` and the `[TestInitialize]`/`[TestCleanup]` pair, and each `.PartN.cs` declares `public partial class <Same>` with **no** repeated `[TestClass]`, `[TestInitialize]`, or `[TestCleanup]`. `[TestClass]` is `AllowMultiple = false`, so repeating it is CS0579; the parts therefore share the base file's fixture skeleton rather than duplicating it. This also keeps every `/TestCaseFilter:"FullyQualifiedName~<Class>"` in this plan valid unchanged, because a partial class has one fully-qualified name. Every base-file creation task in this plan declares its class `partial` for that reason.

## Standing Acceptance Criteria (apply to every task of the stated kind)

- **Test-authoring task.** The named `[TestMethod]` exists exactly once in the named file, uses MSTest attributes, Moq for boundaries, and FluentAssertions for assertions, is written in Arrange-Act-Assert form with a one-line scenario comment, and passes in that phase's scoped test run. It creates no temporary file, contacts no external service or process, constructs or shows no WinForms `Form`, opens no modal dialog, and uses no `Thread.Sleep`, `Task.Delay`, `DateTime.Now`, `DateTime.UtcNow`, or `Random.Shared`. It neither reads nor mutates `UtilitiesCS.UiThread` static state.
- **Split-file creation task.** The named `.PartN.cs` file declares `public partial class <Same>` in the same namespace as its base file, carries a header comment recording that `[TestClass]` stays on the base file only because `AllowMultiple = false` makes a repeat CS0579, and declares no `[TestClass]`, `[TestInitialize]`, or `[TestCleanup]` of its own. The only edit to the base file is the addition of the `partial` keyword if it is not already present.
- **Production seam task.** The edit compiles, the seam default reproduces the replaced call argument-for-argument and in binding, no member is added to, removed from, or renamed on any of the five interface files in the F6 set, and no public constructor signature changes.
- **Evidence task.** The named artifact exists at the named canonical path and contains all four required fields with real values (never `UNVERIFIED`, never a placeholder).
- **csproj wiring task.** Exactly one `<Compile Include=...>` line is added; no existing entry is removed, reordered, or otherwise edited; no project property, target, reference, or `packages.config` entry changes.
- **Per-phase file-size gate.** Every **test**-file size measurement in Phases 1-5 ([P1-T65], [P2-T78], [P3-T71], [P4-T83], [P5-T153]) and the Actions.cs measurement at [P4-T18] are taken **after** that phase's scoped CSharpier format task has run, so the number recorded is the formatted line count and cannot drift from the post-format count re-measured at [P11-T15]. The four production-file checks that precede their phase's format task ([P1-T14], [P3-T15], [P5-T27], [P5-T28]) are pre-format headroom checks only; [P11-T15] is the authoritative post-format measurement for those five production files.

## Coverage Risk Note (QfcExplorerController.cs) - read before executing Phase 5

Per binding fact 4 the dead `#region Email Sorting To Rewrite` (lines 183-321, six caller-free members, roughly 139 lines) stays in the file. Research `research/QfcExplorerController.cs.md` section 6 projected 97-98% line coverage **after** deleting that region; with the region retained the denominator carries roughly 50-60 additional statements that no deterministic test can reach, because `WriteCSV_StartNewFileIfDoesNotExist` requires filesystem I/O (prohibited by `.claude/rules/general-unit-test.md`) and the remaining members are `private static` with zero callers. **The 80% line-coverage floor for `QuickFiler/Controllers/QfcExplorerController.cs` may therefore be unreachable inside F6.** `spec.md` records this consequence directly under "Implementation Strategy" and as OOS-7.

This plan does not respond by deleting the region, by adding `[ExcludeFromCodeCoverage]`, or by reflection-invoking private statics to inflate the numerator. It responds by:

- covering the one dead-region member that is honestly reachable (`internal static StripTabsCrLf`, [P5-T94] through [P5-T98]);
- measuring the real per-file rate at [P5-T155];
- and, if the measured rate is below 80%, writing a residual dossier at [P5-T157] that routes the residual to F1's ledger naming issue #449 as the sequenced remedy. F6 does not ratify an exemption on its own say-so (spec AC-2).
