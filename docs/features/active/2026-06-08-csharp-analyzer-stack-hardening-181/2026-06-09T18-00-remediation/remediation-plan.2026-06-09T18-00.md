## Seam Decision — S8 inner-timer abstraction (smallest behavior-preserving option)

Two options were specified in the inputs:
- (a) extend the public `IGenericTimer` additively with `AutoReset` (and `ResetTimer`), updating all implementers; or
- (b) define a small dedicated internal inner-timer interface.

**Selected: option (b) — a dedicated internal inner-timer interface in `TimerWrapper.cs`.** Justification (verified against source):
- `IGenericTimer` (`UtilitiesCS/Interfaces/IGenericTimer.cs`) is implemented only through `ITimerWrapper : IGenericTimer` (`UtilitiesCS/Interfaces/ITimerWrapper.cs`), whose concrete implementers are the production `TimerWrapper` and the cycle-6 test double `ManualFireTimerWrapper`. `ITimerWrapper` ALREADY declares `AutoReset` and `ResetTimer`, so extending `IGenericTimer` with those members would be redundant at the outer level and would still force edits to every implementer.
- The inner-timer seam is an INTERNAL implementation detail of `TimerWrapper` (it wraps the underlying `System.Timers.Timer`). It is not part of the public `IGenericTimer`/`ITimerWrapper` contract that consumers depend on. A dedicated internal interface confined to `TimerWrapper.cs` touches zero existing implementers, keeps `IGenericTimer.cs` and `ITimerWrapper.cs` unchanged, and keeps the public surface minimal (per C# policy "prefer `internal` for non-public APIs").
- Consequence: `UtilitiesCS/Interfaces/IGenericTimer.cs` is NOT modified this cycle. The authorized-file list for production is therefore `TimeOutTask.cs`, `OlTableExtensions.TableAccess.cs`, and `TimerWrapper.cs` only. If implementation discovers `IGenericTimer.cs` MUST be touched, that is a Scope-Change finding requiring re-confirmation, not a silent edit.
