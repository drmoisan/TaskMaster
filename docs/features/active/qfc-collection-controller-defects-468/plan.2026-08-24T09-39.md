### Toolchain commands (from CLAUDE.md, verbatim; run in this order)

1. `dotnet tool run csharpier format .` — verify with `dotnet tool run csharpier check .`
2. `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:EnableNETAnalyzers=true /p:EnforceCodeStyleInBuild=true`
3. `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:TreatWarningsAsErrors=true`
4. `vstest.console.exe <test-assembly-paths> /EnableCodeCoverage`

Binding notes for the executor:

- Use `/t:Rebuild`. A warm `/t:Build` skips `CoreCompile` on every project and returns exit 0 having run no analyzers, so the gate becomes vacuous.
- Do **not** add `/p:Nullable=enable`. No project carries a `<Nullable>` element; forcing it produced 195 errors in `UtilitiesCS.csproj` and CI omits it deliberately.
- **Invoke MSBuild through `pwsh -NoProfile`, never through the Bash tool.** The Bash tool rewrites `/m` into `M:/` and MSBuild fails with MSB1008.
- `msbuild.exe` is not on `PATH`. Resolve it once per session:

  ```
      $vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
      $msbuild = & $vswhere -latest -products * -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1
  ```

  The repo wrapper `scripts/vscode/Invoke-VSBuild.ps1` emits exactly the two policy command lines above and is the preferred entry point: `-Target Rebuild -EnableNETAnalyzers -EnforceCodeStyleInBuild` for step 2 and `-Target Rebuild -TreatWarningsAsErrors` for step 3. Record the emitted MSBuild command line in the artifact's `Command:` field.
- Restart the loop from step 1 whenever any step fails or changes a file.

### Scoped test-run command (used by every regression task)

`vstest.console.exe` is not on `PATH`; neither is `vswhere.exe`. The canonical form is:

```
    $vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
    $vstest  = & $vswhere -latest -products * -find 'Common7\IDE\Extensions\TestPlatform\vstest.console.exe' | Select-Object -First 1
    & $vstest QuickFiler.Test\bin\Debug\QuickFiler.Test.dll `
        /Settings:scripts\vscode\TaskMaster.cli.runsettings `
        /InIsolation `
        /TestCaseFilter:"FullyQualifiedName~<TestName>" `
        /Logger:"trx;LogFileName=p<N>-t<M>.trx" `
        /ResultsDirectory:<FEATURE>\evidence\regression-testing\p<N>-t<M>
```

Rules that make this executable and auditable:

- `/ResultsDirectory:` is **mandatory** whenever the trx logger is used. Without it the TRX lands in `TestResults\` relative to the working directory and any "the TRX exists at the evidence path" acceptance is unsatisfiable. `.gitignore` hides `TestResults/`, so the clean-tree gate will not catch the omission.
- `LogFileName=` is **mandatory**. Without it vstest names the file `<account>_<HOST>_<timestamp>.trx`, embedding the operator's account and machine name into a committed artifact. Before committing any TRX, replace the workspace root prefix in `<TestRun>`/`<Deployment>` path attributes with `<repo-root>` and the `computerName` attribute value with `<host>`, and record that substitution in the owning task's artifact.
- Every `/ResultsDirectory:` value ends in a distinct lower-case `p<N>-t<M>` segment matching the task ID that produced it. Renumbering a task means renaming its segment.
- `/InIsolation` is mandatory for the Moq-based assemblies.
- vstest 18.x rejects `OR` inside `/TestCaseFilter`; join clauses with `|`.
- **Precondition for every test task:** build first with `pwsh -NoProfile -File scripts/vscode/Invoke-VSBuild.ps1 -Target Build`. A build failure blocks the task; it is not a test result.

- **D2 — `KbdActions.cs` is never written.** Removing `WireUpKeyboardHandler` deletes a *caller*; it deletes zero lines in `QuickFiler/Controllers/KbdActions.cs`. Any further hardening of `KbdActions(IEnumerable<UClass>)` is recorded as a downstream note for #444 and is out of scope.

- **D3 — Do not remove the live overload.** `AnyOpenDropDowns(bool, CancellationToken)` at `<CTRL>:1319` is live (called at `:1309`). Only `AnyOpenDropDownsAsync` at `:1324` is dead.

- **D4 — `#470-1` guarded-path shape.** `PromoteFirstChild` returns the sentinel `-1` when no child is found; it does not throw. `ToggleGroupConv(string)` returns without further action when the promoted index is `-1`. `ChangeConversationSilently(int, bool)` additionally guards its own subscript and returns without action for an out-of-range index. Rationale: this member sits on the same VSTO UI event path as the `#470-2` reconciliation, where the repository has already ratified log-and-proceed over throw (`QuickFiler/Helper Classes/ConversationResolver.Loading.cs:41-50`). A typed throw here would propagate to the VSTO UI thread for a recoverable state.

- **D5 — `#470-2` production behaviour is log-and-proceed, not throw.** The spec resolves the conflict between the two research documents in favour of log-and-proceed. Tests are designed against that decision. No production `throw` is introduced to make a test easier to write.

- **D6 — `#470-2` helper decomposition.** Two pure static members are introduced in the owned file as part of the `#470-2` fix (they are part of the fix, not among the three AC-20 seams):
  - `internal static IReadOnlyList<MailItem> ResolveConversationInsertions(ConversationResolver resolver, string entryID)` — exactly the current `:1883-1886` expression.
  - `internal static int ReconcileInsertionCount(string entryID, int conversationCount, int insertionsCount, int sameFolderCount, int expandedCount, int baseEmailIndex, Action<string> warn)` — returns `insertionsCount` as the single source of truth and invokes `warn` exactly once, with a message carrying all six named values, when `insertionsCount != conversationCount - 1`.

  `ToggleUnGroupConv` calls the resolver once before `MakeSpaceForItems`, passes `msg => logger.Warn(msg)` as `warn`, uses the returned count as `insertCount`, and passes the resolved list into `EnumerateConversationMembers`. `EnumerateConversationMembers` loses its dead `conversationCount` parameter and gains `IReadOnlyList<MailItem> insertions`; it no longer re-resolves. Neither `EnumerateConversationMembers` nor `PromoteFirstChild` nor `ChangeConversationSilently` is declared on `IQfcCollectionController` (verified: the interface declares only `EliminateSpaceForItems` at `:47`, `MoveEmailsAsync` at `:50`, `ToggleUnGroupConv` at `:81`, `ReadyForMove` at `:96` among the members this feature touches), so no interface signature changes.

- **D7 — `#470-2` testability boundary, stated rather than hidden.** `ToggleUnGroupConv` cannot be driven COM-free: its first two statements are `SafeSetTlpLayout(false)` and `UnregisterNavigation()`, and `MakeSpaceForItems` reaches `TableLayoutHelper.InsertSpecificRow` on `_itemTlp`. - **D8 — `#471` seam shape.** `internal static Size ShrinkByRows(Size current, float templateHeight, int removalCount)` returns `new Size(current.Width, current.Height - (int)Math.Round(templateHeight * removalCount, 0))`. It is used at both `:2018-2026` (shrink, positive count) and `:2031-2034` (grow, negative count, with an in-code comment stating that a negative row count grows). The seam lands **preserving the current inverted sign**, so the seam commit changes no observable behaviour; the sign correction is a separate later edit in exactly one place — the argument passed at the `EliminateSpaceForItems` site — not in both places.
