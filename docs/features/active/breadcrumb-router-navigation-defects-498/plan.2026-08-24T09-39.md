## Baseline-Comparison Rule for Whole-Solution Gates (binding)

Sibling epic children execute concurrently against the same integration branch and three pre-existing 500-line violations exist. This plan therefore NEVER asserts an absolute diagnostic count, an absolute test count, or a zero-skip condition over a file or assembly it does not own. Every whole-solution gate is expressed as a comparison against the corresponding Phase 0 baseline artifact:

- **Formatting.** `EXIT_CODE: 0` is required. If and only if the `P0-T12` baseline artifact recorded a non-zero exit code for the identical command, the gate degrades to: no file on this plan's written-file list appears in the unformatted list, and the unformatted list is a subset of the `P0-T12` baseline list. The degradation is recorded explicitly in the task artifact with a pointer to `P0-T12`. `P0-T12` is the csharpier baseline (`p0-t12-csharpier-check.md`); `P0-T11` is the toolchain bootstrap and is NOT a formatting baseline.
- **Analyzer and nullable gates.** `EXIT_CODE: 0` is required. If and only if the corresponding baseline artifact (`P0-T13` for the analyzer gate, `P0-T14` for the nullable gate) recorded a non-zero exit code for the identical command, the gate degrades to: the total warning and error counts are at or below the baseline counts, and no reported diagnostic names any file on this plan's written-file list. The degradation is recorded explicitly with a pointer to the baseline artifact.
- **Full-suite test run.** The set of FAILING test identifiers must be a subset of the failing set recorded in the `P0-T15` baseline artifact (`BASELINE_FAILURE_SET`), and no failing identifier may belong to any test class this plan writes. Skipped counts are never asserted.
- **Scoped runs over test classes this plan does NOT write.** `P6-T17`, `P7-T4`, `P7-T5`, `P7-T6` and `P7-T8` each run a complete test class that this plan does not author. Each states `failed 0` as its primary gate, degrading against `BASELINE_FAILURE_SET` exactly as its own task text describes, so that a test already red at baseline — including one turned red by a concurrently-executing sibling epic child — cannot fail this feature's gate for a cause this feature did not create.
