## C# Toolchain (exact commands, exact order)

1. `dotnet tool run csharpier format .` — verify with `dotnet tool run csharpier check .`
2. `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:EnableNETAnalyzers=true /p:EnforceCodeStyleInBuild=true`
3. `msbuild TaskMaster.sln /t:Rebuild /m /p:Configuration=Debug "/p:Platform=Any CPU" /p:TreatWarningsAsErrors=true`
4. `vstest.console.exe <test-assembly-paths> /EnableCodeCoverage`

Constraints the executor must not get wrong:

- `/t:Rebuild` is mandatory. `/t:Build` skips `CoreCompile` on a warm tree, so the analyzer and nullable gates return exit 0 having compiled nothing.
- Do NOT add `/p:Nullable=enable`. It is absent from CI deliberately and conscripts files that never adopted the `#nullable enable` pragma.
- `dotnet tool restore` must run once in the execution worktree before the first csharpier invocation. The manifest is at the repository root (`dotnet-tools.json`, CSharpier pinned to 1.2.6). CSharpier 1.2.6 requires a subcommand; the bare-path form does not run.
- msbuild and vstest MUST be invoked through `pwsh -NoProfile -Command` with explicitly resolved executable paths. A bare bash invocation mangles MSBuild switches and MSBuild fails with MSB1008.
- Quote every `pwsh -NoProfile -Command` payload with OUTER SINGLE quotes and use inner double quotes for literals. A double-quoted payload is expanded by the parent shell before pwsh sees it.
- If any step fails or changes files, restart the loop from step 1.

**Step 1 scoping exception (mandatory).** The MUTATING pass `dotnet tool run csharpier format .` is replaced by a pass scoped to the file list this plan writes. Sibling epic children execute concurrently against the same integration branch, and a repo-wide mutating format would place unrelated files in this feature's diff, breaking AC-30. The READ-ONLY repo-wide verification `dotnet tool run csharpier check .` is run unchanged, exactly as CI does.

**Evidence artifacts are exempt from formatting.** `.csharpierignore` already excludes `**/evidence/**`, `*.trx`, and `*.cobertura.xml`, so writing evidence under the feature folder cannot break the format gate.

```
pwsh -NoProfile -Command '& "scripts\vscode\Invoke-VSBuild.ps1" -Target Build; $vsw = Join-Path ${env:ProgramFiles(x86)} "Microsoft Visual Studio\Installer\vswhere.exe"; $vs = & $vsw -latest -products * -find "Common7\IDE\Extensions\TestPlatform\vstest.console.exe" | Select-Object -First 1; & $vs "ASSEMBLY" /InIsolation "/TestCaseFilter:FILTER" "/Logger:trx;LogFileName=results.trx" "/ResultsDirectory:RESULTS"; "EXIT_CODE: $LASTEXITCODE"'
```

Every scoped run writes to its OWN results directory so that an earlier `[expect-fail]` run's TRX cannot be mistaken for a later run's. Each task names its directory explicitly.

Rebuild recipe (analyzer and nullable gates):

```
pwsh -NoProfile -Command '$vsw = Join-Path ${env:ProgramFiles(x86)} "Microsoft Visual Studio\Installer\vswhere.exe"; $mb = & $vsw -latest -requires Microsoft.Component.MSBuild -find "MSBuild\**\Bin\MSBuild.exe" | Select-Object -First 1; & $mb "TaskMaster.sln" /t:Rebuild /m "/p:Configuration=Debug" "/p:Platform=Any CPU" "/p:EnableNETAnalyzers=true" "/p:EnforceCodeStyleInBuild=true"; "EXIT_CODE: $LASTEXITCODE"'
```

Coverage recipe (full suite, Cobertura output; expect a long run, allow it to complete):

```
pwsh -NoProfile -Command '& "scripts\vscode\Invoke-MSTestWithCoverage.ps1" -SearchRoot . -Configuration Debug -CoverageOutput "coverage\coverage.cobertura.xml"; "EXIT_CODE: $LASTEXITCODE"'
```

`-SearchRoot .` must always be supplied explicitly. The raw Cobertura lands in the gitignored `coverage/` directory, so every coverage task copies it into the feature evidence folder.
