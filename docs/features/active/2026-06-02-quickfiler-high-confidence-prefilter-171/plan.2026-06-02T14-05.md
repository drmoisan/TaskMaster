## Language and Toolchain

This is a C# / VSTO change. Every implementation task is verified with the repo C# toolchain in this exact order, restarting from step 1 if any step fails or rewrites files:

1. **Format:** `dotnet tool run csharpier .` (check mode for verification: `dotnet tool run csharpier check .`)
2. **Analyzers:** `msbuild TaskMaster.sln /t:Build /p:Configuration=Debug /p:Platform="Any CPU" /p:EnableNETAnalyzers=true /p:EnforceCodeStyleInBuild=true`
3. **Nullable type-check:** `msbuild TaskMaster.sln /t:Build /p:Configuration=Debug /p:Platform="Any CPU" /p:Nullable=enable /p:TreatWarningsAsErrors=true`
4. **Test + coverage:** `vstest.console.exe <test-assembly-paths> /EnableCodeCoverage`
   - Test assemblies: `QuickFiler.Test\bin\Debug\QuickFiler.Test.dll`, `UtilitiesCS.Test\bin\Debug\UtilitiesCS.Test.dll`

Tests use **MSTest** + **Moq** + **FluentAssertions** only. No live Outlook COM and no temporary files in tests.

## Standing Constraints (apply to every task)

- **File-size constraint:** `QfcCollectionController.cs` (~2,206 lines), `QfcItemController.cs` (~2,431), `QfcFormController.cs` (~1,082), and `QfcHomeController.cs` (~724) already exceed the 500-line policy limit. These are pre-existing violations not introduced by Issue #171. New scoring/filter logic MUST go in the new file `QuickFiler/Controllers/QfcHighConfidencePreFilter.cs`. Additions to the oversized files must be the minimum interface/overload glue only; if a touched file would grow materially, prefer extracting into the new file. Each task that touches an oversized file states the net line delta and must keep it minimal (single-overload / single-property scope).
- **DRY constraint:** Scoring reuses the existing `FolderPredictor` + `FolderScorer` path. Do not duplicate the Bayesian classification sequence; extract or call a shared helper so the pre-filter and the existing item-controller path share one scoring sequence.
- **Scope constraint:** Only the async `QfcHomeController.RunAsync` path changes. Do NOT touch `QfcHomeController.Run()` (sync, lines 231–243), `IterateQueueAsync`, or `QfcQueue`. Initial batch only.
- **Threading constraint:** Scoring runs off the UI thread (`Task.Run` / `Task.WhenAll`); UI construction stays on the UI thread (`LoadControlsAndHandlers_01Async` asserts UI-thread at line ~328).
- **Retain-but-do-not-invoke constraint:** `QfcFormController.ApplyHighConfidenceFilterAsync` and `QfcCollectionController.RemoveBelowThresholdAsync` remain in the codebase (existing tests cover them) but must NOT run in the high-confidence load sequence.
