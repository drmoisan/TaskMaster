- **D-482-A — fix #482 by unifying both expansion registries.** A single `private void SyncExpandedRegistrations(bool expanded)` in `QuickFiler/Controllers/QfcItemController.Navigation.cs` becomes the sole owner of expansion registration, called by both `ToggleState` overloads after `ToggleExpansionOn()` / `ToggleExpansionOff()` has written `_expanded`. - **D-P1 — the new test file is self-contained.** `QuickFiler.Test/Controllers/QfcCollectionControllerNavigationDigitsTests.cs` carries its own `private static` reflection field-setter and item-group builder rather than depending on `QuickFiler.Test/Controllers/QfcCollectionController.TestSupport.cs` (created by #468 `[P2-T1]`). - **D-P2 — every evidence path this plan resolves is already canonical, and no override record is written.** An earlier revision of `spec.md` named a non-canonical `evidence/coverage/` folder for the Phase 0 coverage baseline, and this plan carried an `EVIDENCE_LOCATION_OVERRIDE_REJECTED` record against it. `spec.md` has since been amended and its AC-QA-10 now names `docs/features/active/quickfiler-keyboard-action-defects-444/evidence/baseline/`, which is a canonical `<kind>` under `.claude/skills/evidence-and-timestamp-conventions/SKILL.md`. If the executor is nevertheless handed a non-canonical evidence path at run time by some later instruction, it substitutes the canonical path and records the override line in the affected artifact at that point, per the skill.
- **D-P3 — the `Digits` zero-read gate uses a word-boundary match.** The new field name `_registeredDigits` contains the substring `Digits`, so a substring search cannot express "zero reads of the `Digits` property". Every gate on that condition uses the regular expression `\bDigits\b`, which does not match `_registeredDigits` because the character preceding the `D` is `e`, a word character, so no word boundary exists at that position. Every such gate is additionally run with `Select-String -CaseSensitive`, because `Select-String` matches case-insensitively by default and an uncased `\bDigits\b` would also match a local variable named `digits`, which would make the post-fix zero-read gate fail on a correct implementation.
- **D-P4 — no coverage claim is made for `QuickFiler/Controllers/QfcCollectionController.cs`.** That class carries `[ExcludeFromCodeCoverage]` at the class declaration, so its lines are outside every coverage denominator. No acceptance condition anywhere in this plan asserts a coverage figure, a coverage delta, or a coverage increase attributable to that file.
- **D-P5 — no helper script is written under the evidence tree.** Feature-review language matching is extension-only and path-blind, so a retained `.ps1` under an evidence folder forces a coverage FAIL. Every command in this plan is executed inline; nothing executable is persisted under `docs/features/active/quickfiler-keyboard-action-defects-444/evidence/`.
- **D-P6 — `QuickFiler/Controllers/QfcCollectionController.cs` exceeds the 500-line cap before this feature touches it, and that excess is not remediable here.** The file is far above the cap at the epic base commit, and upstream #468 reduces it without bringing it anywhere near 500 (its own plan task `[P15-T7]` records exactly this disposition: "the artifact records the post-feature size of `<CTRL>` together with the statement that its excess over the cap is a pre-existing condition this feature reduces rather than creates"). Every file-size gate in this plan is therefore expressed as: files this feature **creates** must be at or below 500 lines; a pre-existing file must be at or below 500 lines **or** no larger than its `[P0-T21]` baseline. Acceptance criterion AC-QA-01 as amended in `spec.md` states **the same rule** as these gates — every **added** file at or below 500 lines, and every pre-existing changed file either at or below 500 lines **or** no larger than its Phase 0 baseline — so the acceptance criterion and this plan's gates now express one condition and `[P4-T14]` evaluates it directly against the counts `[P4-T3]` records. `QuickFiler/Controllers/QfcCollectionController.cs` satisfies the second disjunct by construction rather than by exemption: `[P2-T4]` adds two lines (the field declaration and its assignment) while `[P2-T5]` replaces the eight-line `if`/`else` inside `UnregisterNavigation`'s loop with a single `Remove` call plus one hoisted `var format` declaration, a net reduction larger than the addition, so the post-change count is **below** the `[P0-T21]` baseline.
```powershell
    $vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
    $msbuild = & $vswhere -latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1
    $vstest  = & $vswhere -latest -products * -find 'Common7\IDE\Extensions\TestPlatform\vstest.console.exe' | Select-Object -First 1
```

Scoped test-run shape used by every non-final run task in this plan:

```powershell
    & $vstest QuickFiler.Test\bin\Debug\QuickFiler.Test.dll `
      /Settings:scripts\vscode\TaskMaster.cli.runsettings /InIsolation `
      /TestCaseFilter:"<the filter stated by the task>"
```

`vstest` 18.x rejects `OR` inside `/TestCaseFilter`; join clauses with `|`. `/InIsolation` is mandatory for these Moq-based assemblies: omitting it produces empty-message, sub-millisecond assembly-load failures that are not real regressions.

Compile-only build shape (used to produce test binaries between edits):

```powershell
    & $msbuild TaskMaster.sln /t:Build /m /p:Configuration=Debug "/p:Platform=Any CPU"
```

`/t:Build` is used here deliberately and only to produce binaries. The analyzer gate and the nullable gate in Phase 4 use `/t:Rebuild`, because MSBuild's up-to-date check does not invalidate on a command-line `/p:` change and a warm `/t:Build` would return exit 0 with `CoreCompile` skipped on every project. `/p:Nullable=enable` is never added to any command in this plan.

Every command in this plan is a PowerShell command and is run from a PowerShell host (`pwsh -NoProfile` when invoked from outside a PowerShell session). None of them may be run through a POSIX shell: a Git-Bash layer rewrites a bare MSBuild switch such as `/m` into a drive-style path (`M:/`), so the build silently receives a different argument set. `MSBuild.exe`, `vstest.console.exe`, and `vswhere.exe` are resolved to absolute paths by the prelude above and are never invoked by bare name.
