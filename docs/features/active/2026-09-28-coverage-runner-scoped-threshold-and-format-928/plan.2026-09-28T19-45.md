## Objective

Make a `-SearchRoot`-scoped run of the coverage runner exit on the outcome of the tests it executed, by skipping the two document-level threshold assertions automatically when the run is scoped, with exactly one warning naming the reason and the search root; keep the unscoped run byte-for-byte on the same two assertion calls; document the behavior in comment-based help; and leave both coverage runner scripts formatter-clean under the repository formatter route.

## Selected Approach (decided by the preparation orchestrator; not reopened here)

1. A pure predicate `Test-CoverageRunIsScoped -RepoRoot <string> -ResolvedSearchRoot <string>` returns true when the full path of the resolved search root differs from the full path of the repository root, compared ordinal case-insensitive with trailing directory separators ignored. An omitted `-SearchRoot`, a lone dot, and a dot followed by a backslash all resolve to the repository root and are unscoped.
2. The entry point calls the predicate once, after post-processing and before the two threshold assertions. When it returns true the entry point writes one warning and skips both assertions; when it returns false the two existing assertion statements run unchanged, in their existing order.
3. No new command-line switch is added.
4. The predicate lives in a new part file so the 500-line ceiling is not approached in the entry point.

- **D12 — Committed Test Evidence Format.** No raw test-result document and no raw coverage collector document is written under the feature folder: not the bundled JUnit document, not the bundled JaCoCo document, not any Pester JaCoCo output, not any trx. CMD-PESTER-DIRECT writes its JaCoCo output under the repository coverage directory, which .gitignore line 144 ignores. Evidence records derived figures and counts only.
- **D13 — Host-identifier hygiene.** No evidence artifact, no plan text and no issue text may contain an absolute host path, the developer account name or the host name. The MCP tools echo `workspace_root` as an absolute path: transcribe it as `<repo-root>`. Sibling test fixtures use a neutral drive-letter root; when quoting any test name, failure message or console line that carries it, replace the drive-letter root with `<fixture-root>`. The final task scans the whole feature folder for two patterns and requires zero matches.
- **D14 — No commit task; intent-to-add only.** The caller owns the commit. No task in this plan runs `git commit`. Each newly created file is registered with `git add -N` immediately after creation so every anchored `git diff 177b6d78e` in Phase 2 can see it; no content is staged. Every worktree-state gate is a negative path-class clause over `git status --porcelain -uall`, never an emptiness clause, because the plan file and the evidence artifacts are uncommitted by construction.
- **D15 — Exit-code conventions per channel.** The MCP tools return `{ok, tool, workspace_root, summary}` plus `stderr_excerpt` on failure and no other field. For a format or analyze artifact, `EXIT_CODE:` is 0 when `ok` is true and 1 when `ok` is false, and `MCP_RESULT_OK_FLAG:` is recorded separately. For a test artifact, `EXIT_CODE:` is derived from the bundled JUnit document at artifacts/pester/pester-junit.xml: 1 when the root `failures` plus `errors` is greater than zero, else 0; the MCP ok flag is recorded separately and a passing final-QC test stage requires it to be true. A direct Pester run, when reachable, sets its own exit through the explicit `exit` statement in CMD-PESTER-DIRECT and is recorded as `DIRECT_PESTER_EXIT:`, never as the artifact's `EXIT_CODE:` row.
- **D16 — Restart rule for the Phase 2 loop.** A step "changes files" when a Write Set PowerShell file's raw-byte hash (`git hash-object --no-filters`) differs across the step, or when the step leaves a porcelain line for a path outside the Write Set under the two script folders that is not a member of the P0-T5 `FORMAT-DRIFT-SET:` (such a path is restored with `git checkout --` and recorded before the restart). A step "fails" when its gate condition is not met. Either restarts the loop at P2-T1 with the iteration number incremented; every artifact carries `iter<N>` in its name so iterations never overwrite one another.

```

```
Set-StrictMode -Version Latest

function Test-CoverageRunIsScoped {
    <#
        .SYNOPSIS
        Returns true when a coverage run's resolved search root is not the repository root.

        .DESCRIPTION
        Pure predicate; no I/O. Both paths are normalised with GetFullPath, trailing directory
        separators are trimmed, and the comparison is ordinal case-insensitive, so an omitted
        search root, a lone dot and a dot followed by a backslash all read as the repository root.
        The entry point skips the document-level threshold assertions when this returns true,
        because those assertions compare a rate taken across every instrumented assembly against
        floors set for the whole solution, and a single-assembly run fails them on a healthy
        tree (issue #928).

        .PARAMETER RepoRoot
        The repository root as an absolute path.

        .PARAMETER ResolvedSearchRoot
        The search root after it has been joined to the repository root, as an absolute path.

        .OUTPUTS
        True when the run is scoped, false when it is unscoped.
    #>
    [CmdletBinding()]
    [OutputType([bool])]
    param(
        [Parameter(Mandatory = $true)]
        [string]$RepoRoot,

        [Parameter(Mandatory = $true)]
        [string]$ResolvedSearchRoot
    )

    $separators = [char[]]@([IO.Path]::DirectorySeparatorChar, [IO.Path]::AltDirectorySeparatorChar)
    $normalizedRepoRoot = [IO.Path]::GetFullPath($RepoRoot).TrimEnd($separators)
    $normalizedSearchRoot = [IO.Path]::GetFullPath($ResolvedSearchRoot).TrimEnd($separators)

    return -not [string]::Equals(
        $normalizedRepoRoot,
        $normalizedSearchRoot,
        [StringComparison]::OrdinalIgnoreCase)
}
