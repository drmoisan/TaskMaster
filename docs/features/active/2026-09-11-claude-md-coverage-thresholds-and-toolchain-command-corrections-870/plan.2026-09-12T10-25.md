## Scope statement (plain prose, no backticks)

This plan covers a documentation-only correction confined to the single repository-root file named CLAUDE.md. Five prose edit sites, zero source files, zero build files, zero test files. Four of the five are the sites spec.md enumerates in its Implementation strategy section: the two toolchain step 4 entries, the UT2 coverage-figures block, and the analyzer-severity citation correction applied at two lines. The fifth is the Committed Test Evidence Format paragraph corrected by P1-T5; it is not a defect spec.md identifies but a consequence of the correction spec.md's AC3 and AC4 require, because a sibling item merged into this branch after spec.md was written made that paragraph cite the very switch list those two criteria remove. Amending it is in scope because it is inside CLAUDE.md and because leaving it would trade one inaccurate citation for another; no acceptance criterion changes, and spec.md is not edited by this plan. The governance rules files published into this repository under the dot-claude tree (the general unit test rule, the quality tiers rule, and the C# rule) and the feature-review coverage validation hook state a stricter pair of figures, eighty five percent line and seventy five percent branch, applied uniformly across module rigor tiers. Those files arrive by an automated push-down process from an upstream governance repository with zero templating applied, so a local edit to any of them here is overwritten the next time that push-down runs. They are out of scope for this item: no task below reads, edits, or asserts over any of them, and none of them is named as a path in this plan. The enforcement half of the issue-563 divergence — reconciling the eighty/seventy-five figures this fix records in the repository's own instructions against the eighty-five/seventy-five figures actually enforced by the rules tree and the review hook — is tracked upstream in the governance repository and is not resolved by this item.

Because the production diff touches no source, build, or test file, no formatter, linter, type-checker, or test-runner has an applicable target. Phase 2 states this rationale explicitly as its own task rather than including a vacuous toolchain gate.
