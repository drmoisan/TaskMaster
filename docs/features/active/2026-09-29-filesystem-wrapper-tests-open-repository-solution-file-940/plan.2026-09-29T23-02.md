## Decisions

- **D-1 Test-only rewrite on owned fixtures (research approach A).** No production file changes. The fixtures are the running host's own loaded assembly image (`typeof(<test class>).Assembly.Location`), its directory and that directory's parent, which exist for the whole run and are owned by the test process; a rooted literal `C:\Repo\fixture` for pure path computations (the #931 D-14 shape); and names under the owned directory that nothing creates, prefixed `__940_missing_`, for every mutating member, each asserted absent with `Exists.Should().BeFalse()` before the act so a stale entry fails loudly instead of being deleted or moved. Approach B (a delegate seam on `PhysicalDirectoryInfoAdapter`) is rejected because it adds production surface with no consumer and lowers real-delegation coverage; approach C (tolerate contention) is rejected because it needs a retry or a catch, both prohibited.
- **D-2 Every member the two files exercise today stays exercised (AC4).** Target Source A keeps all 18 enumeration overloads, both `Create` overloads, both `CreateSubdirectory` overloads (as no-ops on existing owned entries whose returned wrapper is asserted to name the owned directory, which makes the delegation and the wrapping observable), `GetAccessControl` x2, `SetAccessControl`, `GetObjectData`, `Refresh`, `ToString`, `Parent`, `Root`, every getter, every setter (through the missing-path throw), `Delete` x2, `MoveTo`, `CopyTo` x2, `Replace` x2, the three unseamed opens and the four seamed members. P2-T8 gates this with a per-member token census (Token Census Expectations) and P2-T7 with the per-file covered-line comparison (D-8).
- **D-3 Direct runs use the CLI runsettings file** scripts/vscode/TaskMaster.cli.runsettings with the isolation switch (fact 12), the same parallel regime the coverage route uses; no collector output is produced by a direct run.
- **D-4 Coverage route is selected by a recorded observation (P0-T9).** `COVERAGE-ROUTE: RUNNER` runs scripts/vscode/Invoke-MSTestWithCoverage.ps1 verbatim (CLAUDE.md step 4). `COVERAGE-ROUTE: DIRECT` runs the runner's inner collector invocation directly, built from the same functions (`ConvertTo-DerivedCoverageSettingsXml`, the same assembly discovery filter, the CLI runsettings, the isolation switch, the LiveOutlook category filter) with the four-class exclusion appended, and post-processes with the runner's own helpers, so both routes yield the same three committed forms: the JaCoCo package projection, the one-line first-party summary and the TRX-derived summary. Under either route the raw Cobertura and the TRX stay under coverage\ and are never copied into the feature folder.
- **D-5 The fix is committed before the controls (P1-T8).** Each test-file revert is then anchored: `git checkout -- <file>` restores exactly the committed fixed state, `git diff --exit-code HEAD -- <file>` exits 0 and the SHA-256 equals the `FIX-HASH-` anchor. Production-file reverts are anchored to the P0-T4 `PRE-EDIT-HASH-` values.
- **D-6 Predicted failing assertion per control (Control Table).** Each control names the one assertion predicted to fail and the fixed phrase its `MESSAGE` must contain (fact 23). Any other failing assertion, a passing control, or a `MESSAGE` lacking the phrase is `MUTATION PREDICTION MISMATCH`: stop and report the text; do not adjust the test.
- **D-7 Package comparison (AC8, AC4).** For the package named `UtilitiesCS` in the two JaCoCo projections, the final LINE rate and BRANCH rate, each computed as covered divided by covered plus missed, must be no lower than the baseline rate. The repository-wide first-party totals are compared against the CLAUDE.md floors (line at least 80 percent, branch at least 75 percent), and the repository first-party line rate (covered divided by valid, re-derived from the two post-processed Cobertura documents by the runner's own first-party function, printed as `REPO-LINE` by `CMD-PACKAGE-COMPARE`) must be no lower than the baseline rate, which is AC8's clause "repository line coverage at or above the baseline figure"; both are recorded with a comparability note, because the collector's cross-assembly merge is order-sensitive. If a package rate, the `REPO-LINE` rate, or a per-file count (D-8) reads lower, the final coverage command is re-run once, identically, as a second measurement (recorded as such); if it still reads lower, `AC8: NOT MET` (or `AC4: NOT MET` for D-8) is recorded and the run stops with the two projections quoted. No test is retried by this rule; only the measurement is repeated.
- **D-8 Per-file comparison (AC4).** `CMD-FILE-COMPARE` reads the two post-processed Cobertura documents and, for each of the three adapter and wrapper files, unions the line elements reached through the class-level lines axis and through the methods axis of every `class` element whose `filename` ends with that file name (max hits per line number), and requires the final covered-line count to be no lower than the baseline count. The valid-line count is expected equal because no production line changes.
- **D-9 Exception types are observed before they are pinned (P1-T7).** Target Source A writes the research's predicted types (`FileNotFoundException` for every setter on a missing path and for `CopyTo`, `MoveTo` and `Replace` on a missing source; `DirectoryNotFoundException` for `Delete`, `Delete(true)` and `MoveTo` on a missing directory, already observed by today's passing assertions). The first scoped run of the rewritten classes is the observation: a test failing with `to be thrown, but found` names the observed type, and the executor pins exactly that type in exactly that assertion, then re-runs P1-T5 through P1-T7 as the next iteration. Because FluentAssertions stops a method at its first failing assertion, one iteration can expose only the first mismatching assertion of each method, so a later iteration may expose a further, not-yet-pinned assertion of the same method that the earlier failure masked; that takes the pinning branch again, bounded at nine iterations. A mismatch on an assertion pinned in an earlier iteration is `EXCEPTION TYPE UNSTABLE`: stop and report. Each pinned type T not already in the token list adds the literal `Throw<T>()` to the `CMD-CENSUS` token list for every later census, and `THROW-SUM:` (the sum of the `TOKEN` values of `Throw<FileNotFoundException>()`, `Throw<DirectoryNotFoundException>()` and each appended literal; the `Throw<TargetInvocationException>()` occurrence is not a census token and is excluded) stays 23.                         FileAccess.Read,
                        FileShare.ReadWrite

                    openReadCanRead = openRead.CanRead;
                }

                {
                    openTextLine = openText.ReadLine();
                }

                // adapter's internal injectable-delegate seam with test-owned sentinel streams, so no
                // write handle and no exclusive handle is ever requested on the image. The append
                // sentinel wraps an in-memory stream because StreamWriter requires a writable backing
                // stream; the other sentinels are read-only opens of the image with read-write sharing.

                    sentinelAppendStream,
                    System.Text.Encoding.UTF8,
                    1024,
                    leaveOpen: true
                );

                    typeof(PhysicalFileSystemAdapters_Tests).Assembly.Location,
                    FileMode.Open,
                    FileAccess.Read,
                    FileShare.ReadWrite
                );

                    typeof(PhysicalFileSystemAdapters_Tests).Assembly.Location,
                    FileMode.Open,
                    FileAccess.Read,
                    FileShare.ReadWrite
                );
                using var sentinelOpenWriteStream = new FileStream(
                    typeof(PhysicalFileSystemAdapters_Tests).Assembly.Location,
                    FileMode.Open,
                    FileAccess.Read,
                    FileShare.ReadWrite
                );
                var seamAdapter = new PhysicalFileInfoAdapter(
                    file,
                    () => sentinelAppendWriter,
                    _ => sentinelOpenModeStream,
                    (mode, access) => sentinelOpenModeAndAccessStream,
                    () => sentinelOpenWriteStream
                );

                var accessWithSections = adapter.GetAccessControl(AccessControlSections.Access);
                adapter.GetObjectData(serialized, context);
                adapter.Refresh();
                adapter.SetAccessControl(security);

                adapter.LastAccessTime.Should().Be(file.LastAccessTime);
                adapter.LastAccessTimeUtc.Should().Be(file.LastAccessTimeUtc);
                adapter.LastWriteTime.Should().Be(file.LastWriteTime);
                adapter.LastWriteTimeUtc.Should().Be(file.LastWriteTimeUtc);

                seamAdapter.Open(FileMode.Open).Should().BeSameAs(sentinelOpenModeStream);
