## 0. Summary

Both test classes locate the repository root by walking up from the test assembly until `TaskMaster.sln` is found, then run the production adapters against the real repository root directory and the real solution file. The runs are not merely reads: the current code sets timestamps and attributes on the repository root and on `TaskMaster.sln`, calls `Create`/`CreateSubdirectory`/`SetAccessControl` on the repository root, names `TaskMaster.sln` as the overwrite target of `CopyTo(..., overwrite: true)` and `Replace(...)` from a missing source, and swallows `IOException` around the setters. Eight of the twelve test methods in the two files are affected; the other four already use Moq through the internal `IDirectoryInfo` constructor seam and are unaffected.

Recommendation: a test-only rewrite (no production change) that (a) verifies path computations against a rooted literal that is not expected to exist, following #931 decision D-14; (b) verifies read-only adapter delegation against fixtures the test process owns, namely the running test assembly image (`typeof(T).Assembly.Location`), its containing directory and that directory's parent; (c) verifies every mutating member either through its documented throw on a missing path under the owned directory (delegation is observable, nothing on disk changes) or through a call that is a no-op by construction on an existing owned entry; (d) keeps the four already-seamed `PhysicalFileInfoAdapter` stream members on the existing internal delegate constructor with sentinel streams, exactly as today; and (e) deletes both `catch (IOException)` blocks and both `GetRepositoryRoot` helpers plus `GetSolutionFile`. No `[DoNotParallelize]`, retry, sleep or temporary file is introduced. Each rewritten test gets one negative control (a temporary, reverted mutation of the wrapper or adapter) recorded in the #931 M1/M4 format.

### 4.2 Fixture helpers (test-only, private to each class; no csproj edit)

`UtilitiesCS.Test.csproj` uses explicit `Compile Include` entries (lines 232-234 register the three wrapper test files), so adding a shared fixture file would require a csproj edit. Two private static members per class are sufficient and match the #931 style (a private const):

```csharp
// Owned fixtures (issue #940). The running host's own loaded assembly image exists for the
// whole run and its physical path is bin\<Configuration>\ (csproj OutputPath), so its
// directory and that directory's parent are at least two levels deep and owned by this test
// process. No repository file and no temporary file is involved.
private static FileInfo OwnedAssemblyFile =>
    new FileInfo(typeof(PhysicalFileSystemAdapters_Tests).Assembly.Location);
private static DirectoryInfo OwnedAssemblyDirectory => OwnedAssemblyFile.Directory;
private static string MissingOwnedPath(string suffix) =>
    Path.Combine(OwnedAssemblyDirectory.FullName, "__940_missing_" + suffix);
private const string RootedFixturePath = @"C:\Repo\fixture";
```

Use `Assembly.Location` rather than `AppDomain.CurrentDomain.BaseDirectory`: `DirectoryInfoWrapper_Tests.cs` 377 uses the latter, and `PhysicalFileSystemAdapters_Tests.cs` 351-353 already records why it can point at the vstest host directory. A `[V]` grep over `UtilitiesCS.Test` for `Path.GetTempPath|Path.GetTempFileName|File.WriteAll|File.Create(|Directory.CreateDirectory` returned no matches, so no other test writes into the output directory during a parallel run; enumeration assertions nonetheless use `Contain`/`ContainSingle` on named entries rather than exact set equality.

### 4.3 Remedy per test method

**T1 `PhysicalDirectoryInfoAdapter_PropertiesEnumerationAndAccessors_MirrorDirectoryInfo`** (16-135). Split into three focused tests (UT1 isolation; also keeps each Arrange readable):

- T1a, read-only accessors over `OwnedAssemblyDirectory`: `Exists` true, `FullName`/`Name`/`Parent.FullName`/`Root.FullName` mirrored, `GetAccessControl()` and `GetAccessControl(AccessControlSections.Access)` not null, `GetObjectData`, `Refresh`, `ToString` mirrored. `SetAccessControl(security)` where `security` is the unmodified object returned by `GetAccessControl()` (as today) or `new DirectorySecurity()`: expected to persist nothing because no section is marked modified `[P]`; either way the target is the owned output directory, not the repository. `Create()` and `Create(directory.GetAccessControl())` on the existing owned directory: `Directory.CreateDirectory` returns without a Win32 create call when the path exists `[P]`, and the same calls run today against the repository root without effect. `CreateSubdirectory(OwnedAssemblyDirectory.Name)` and the security overload invoked on `new PhysicalDirectoryInfoAdapter(OwnedAssemblyDirectory.Parent)`: the subdirectory exists, so nothing is created, and the returned wrapper's `FullName` must equal `OwnedAssemblyDirectory.FullName`, which makes the delegation and the wrapping observable.
- T1b, enumeration: files over `OwnedAssemblyDirectory` with pattern `OwnedAssemblyFile.Name` (exact name, `ContainSingle`) and `*` / no pattern (`Contain`); directories over `OwnedAssemblyDirectory.Parent` with pattern `OwnedAssemblyDirectory.Name` (`ContainSingle`) and no pattern (`Contain`); `EnumerateFileSystemInfos`/`GetFileSystemInfos` on the owned directory `Contain` a `FileInfoWrapper` named `OwnedAssemblyFile.Name` and on the parent `Contain` a `DirectoryInfoWrapper` named `OwnedAssemblyDirectory.Name`. All 18 overloads stay exercised; the `SearchOption.TopDirectoryOnly` overloads use the same names. The parent is used for directory assertions because the presence of subdirectories inside `bin\Debug` (MSTest adapter satellite folders) is not guaranteed by construction, whereas the parent containing the DLL directory is.
- T1c, mutators on a missing owned directory (`MissingOwnedPath("directory")`): precondition `adapter.Exists.Should().BeFalse()`; then each of `Attributes`, `CreationTime`, `CreationTimeUtc`, `LastAccessTime`, `LastAccessTimeUtc`, `LastWriteTime`, `LastWriteTimeUtc` setters wrapped in an `Action` and asserted to throw.
