## Global execution rules

1. **Evidence artifact schema.** Every command-step artifact carries `Timestamp:` (ISO-8601 `yyyy-MM-ddTHH-mm`), `Command:` (the exact command run), `EXIT_CODE:`, and `Output Summary:` (1 to 20 lines carrying the essential result signal). Baseline and final-QC test artifacts additionally carry numeric coverage headline values. An artifact whose expected exit code is non-zero declares `ExpectedExitCode: <int>` with that exact spelling, in its own file, one artifact per non-zero-expectation gate.
2. **Shell discipline.** Run every C# toolchain command through `pwsh -NoProfile` from the repository root, using absolute tool paths resolved in Phase 0. The Bash tool mangles MSBuild switches (`/m` becomes an absolute path and raises MSB1008), so no msbuild or vstest command in this plan may be issued through Bash. When passing a payload with `pwsh -Command`, single-quote the outer payload and double the inner literals.
3. **Tool resolution.** Phase 0 resolves and records three absolute paths and then every later task reuses them. Both vswhere forms are the ones the repository's own scripts already use, so the plan does not depend on the local install profile. MSBuild: `$msbuild = & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1`, which is the form scripts/vscode/Invoke-Restore.ps1 uses at its line 27. Test runner: `$vstest = & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -find 'Common7\IDE\Extensions\TestPlatform\vstest.console.exe' | Select-Object -First 1`, which is the form scripts/vscode/Invoke-MSTestWithCoverage.ps1 uses at its line 286. The `-products *` argument is load-bearing: omitting it restricts the lookup to the default product set and returns nothing on a Build-Tools-only install. The third resolved path is the `dotnet-coverage` global tool. A task that cannot resolve its tool halts and records the blocker; it never reports `SKIPPED` as a pass.
4. **MSBuild gate form.** Both msbuild gates use `/t:Rebuild`, never `/t:Build`. A warm `/t:Build` returns exit 0 with `CoreCompile` skipped on every project, so it runs no analyzers and the gate becomes vacuous. Neither gate adds `/p:Nullable=enable`: no project carries a `<Nullable>` element and forcing it produces hundreds of errors that CI deliberately does not enforce. Interim, non-gate compile checks inside Phases 1 to 3 may use `/t:Build` and are labelled as such.
5. **Test run form.** Full-suite runs execute through the repository wrapper: `pwsh -NoProfile -File scripts\vscode\Invoke-MSTestWithCoverage.ps1 -SearchRoot . -Configuration Debug -CoverageOutput coverage\<name>.cobertura.xml`. The `.cobertura.xml` ending is mandatory and is fixed by Global rule 8. That wrapper supplies `/InIsolation` and `/TestCaseFilter:TestCategory!=LiveOutlook`, which is what keeps a real Outlook process from launching; a bare `vstest.console.exe` call omits the exclusion and must not be used for a full-suite run. Scoped runs use `& $vstest <assembly> /InIsolation "/TestCaseFilter:FullyQualifiedName~<Name>"` with alternates joined by `|`, plus `"/Logger:trx;LogFileName=<task-id>.trx"` and `"/ResultsDirectory:coverage\trx\<task-id>"` so each run gets its own results directory and no default account-named or host-named TRX is produced.
6. **Discovery contamination.** The wrapper discovers `*.Test.dll` by absolute `FullName` and filters only on `\bin\Debug\`, `\obj\` and `\ref\`; it applies no agent-worktree exclusion. This execution worktree itself sits beneath a `.claude` segment, so the exclusion is evaluated against each discovered path **expressed relative to the repository root**: no relative path may contain a `.claude` segment. A run whose discovered set contains such a path records `CONTAMINATED-DISCOVERY:` and is rerun.
7. **Coverage threshold branch.** `Assert-CoberturaLineCoverageThreshold` inside the wrapper throws when the repository-wide Cobertura `line-rate` is below 80 percent, and it throws **before** the Koverage post-processing rewrite, leaving the raw pre-processing document on disk. Each coverage task records whether that branch was taken. If taken, the task records `COVERAGE-THRESHOLD-THROW:` with the observed percentage and copies the raw document aside under the gitignored `coverage/` tree; it does not treat the throw as a test failure. On the throwing branch, the on-disk document is the raw pre-processing output: absolute `class/@filename` values, all instrumented packages, and unmerged duplicate classes. The wrapper computes the processed content at its line 340, asserts at its line 341 and only writes back at its line 343, so the throw skips the write-back. Before reading any numeric field from that document, the task dot-sources the helpers and applies `ConvertTo-KoverageCoberturaXml` in memory, supplying the raw file content as its `-XmlContent` argument and the repository root as its `-RepoRoot` argument, casts the returned string to `[xml]`, and reads every figure from that in-memory document, so the values are on the same footing as on the non-throwing branch and the relative-path `filename` lookup this plan prescribes resolves. The artifact records that it did so.
8. **Redaction.** No plan artifact, evidence file, test literal, or commit message may contain a real mailbox address, user-profile path, host name, or organization name. Raw TRX and raw Cobertura output embed the machine account and host name, so they stay under the gitignored `coverage/` tree and are never written under `<FEATURE>/evidence/`. Evidence artifacts are hand-authored Markdown quoting only redaction-safe output. Every Cobertura document this plan writes, including the raw copy-aside taken on the Global rule 7 throwing branch, is named so that its filename ends in `.cobertura.xml`. `.csharpierignore` excludes coverage output by the glob `*.cobertura.xml` and does not exclude the `coverage/` directory, while CSharpier processes `*.xml` per CLAUDE.md C#1.1. A coverage file named otherwise is read by `csharpier check .` at P4-T2, which both raises the checked-file count above the P0-T10 baseline and reports the file as needing reformatting, so P4-T2 could pass under neither of its two branches.
9. **Git gate scoping.** Every `git diff` gate in this plan is anchored to `BASE` and additionally carries an explicit pathspec. Every `git status` and `git grep` gate carries an explicit pathspec but is not anchored to a ref: `git status` compares the working tree and index against `HEAD` and accepts no ref operand, so its pathspec is the whole of its scoping and the anchoring half of this rule does not apply to it. The usual pathspec is `-- UtilitiesCS UtilitiesCS.Test` or a single path beneath one of those two roots, so that tracked files elsewhere in the tree cannot make a gate pass or fail for an unrelated reason. Four deliberate exceptions exist. (a) P0-T7's ownership check is scoped by the two glob pathspecs `"*.csproj"` and `"*packages.config"`, which are solution-wide on purpose, because the property it proves is that the analyzer reconciliation edited no project file and no packages-config file anywhere. (b) and (c) P3-T5's fourth and fifth spans are scoped wider than the two owned roots on purpose: they are the only spans in this plan that can observe a repository path outside `UtilitiesCS` and `UtilitiesCS.Test`, which is what makes AC-4's, AC-9's and AC-12's out-of-root absence claims decidable. (d) The final-commit task's staging pathspec additionally covers this feature folder, and that task records a `-- .claude` status as an observation rather than as a gate. All four still carry an explicit pathspec. No gate in this plan runs `git status --porcelain` with no pathspec at all. The `.claude/agent-memory/` tree is tracked and receives modifications written by other agents at times this plan does not control, so an unscoped clean-tree assertion is not reliably satisfiable and an unscoped `git add -A` would sweep that unrelated work onto this branch. Whether it is dirty at any given moment is not asserted here; every gate is scoped so that the answer cannot change a result.
10. **Formatter scope.** The mutating CSharpier pass in Phase 4 is scoped to the three owned paths. A repository-wide mutating pass would rewrite any pre-existing formatting drift elsewhere in the tree and break AC-12's exactly-three-files diff. The repository-wide `csharpier check .` verification still runs, unscoped, immediately afterwards.
11. **Toolchain restart rule.** In Phase 4, if any step fails or the formatter rewrites any file, restart the loop from the first Phase 4 task. `EXIT_CODE: SKIPPED` is never a passing outcome for any command task in this plan.
12. **Line-number drift.** Every `file:line` citation in this plan was re-derived at authoring time against `BASE`. If a cited line does not match at execution time, re-locate the construct by name, record the drift in that task's evidence artifact, and do not assume the construct is absent.

The span form carries a non-emptiness floor so that an empty lookup fails rather than passes. This reasoning about measurement noise applies to the per-file figures; the repository-wide figures are gated by a stated tolerance in P4-T6 gate (1).
