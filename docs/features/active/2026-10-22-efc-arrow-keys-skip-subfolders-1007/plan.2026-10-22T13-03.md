## Design Resolutions

The spec leaves these points to the plan; each is binding and does not change the meaning of any spec decision.

- R1 `BreadcrumbVisiblePosition` is a sealed immutable class (net48: no `record`, no `init`) with `RowIndex`, `NodeId` (null for a row entry), `ParentNodeId`, `Depth` (-1 for a row entry, 0 for a first-level node), `HasChildren`, `IsExpanded`, and `IsRowEntry`. A node's `HasChildren` is false when its segment reports no children or when it is loaded with zero children (AC14). `BreadcrumbVisibleOrder` exposes `IndexOf(order, rowIndex, nodeId)`, `Step(order, index, delta)` (clamped to the first or last entry, -1 when the result equals `index` or `index` is invalid), `First(order)`, `Last(order)`, and `ParentOf(order, index)` (index of the parent node entry, or of the row entry for depth 0, -1 for a row entry); a null order throws `ArgumentNullException`.
- R2 EFC position: the row addressed by the message `rowId` plus that row's `SelectedDescendantId` when the row is the selected row (a node entry), otherwise its row entry. An empty `rowId` on `arrowKey` is the no-selection case (D-Q26) and is handled before the unknown-row rejection in `ProcessInboundAsync`; a non-empty unknown `rowId` keeps today's logged rejection. This keeps the existing Up and Down row tests valid, because they address a row that is not selected.
- R3 EFC shortened-anchor rule: a row whose `CollapsedAfterIndex` equals its `ActiveSegmentIndex` can expand its active segment (`ToggleLeafExpanded`, `RightArrow`, `[+]`, Right) through one provider query and stays shortened. A collapse not anchored at the active segment, which no gesture produces after S10, keeps today's `ReExpand`. The QFC `BreadcrumbStateRow.ActiveSegmentHasSubfolders` applies the same anchored rule.
- R4 Re-entrancy (S7): `BreadcrumbRow` gains an idempotent `ExpandLeaf()` (sets `IsLeafExpanded` true, false when already expanded) and a leaf-fetch guard (`TryBeginLeafFetch()` false while a fetch is in flight, `EndLeafFetch()`); `ExpandLeafAsync` returns without a provider call when the guard refuses and ends with `ExpandLeaf()`, not a toggle.
- R5 AC7 detection: `BreadcrumbRow.IsSelectedDescendantWithin(string nodeId)` reports whether the selected descendant is a strict descendant of the node; a row-level collapse hides the selection when the row is selected and `SelectedDescendantId` is non-null. The router re-commits the collapsed node (or `SelectRowEntry` for a row collapse) after the collapse.
- R6 QFC router surface (in `FolderBreadcrumbBridgeRouter.Navigation.cs`): `MoveSelectorToBoundary(bool first)`, `MoveSelectorPage(bool previous, int pageSize)`, `MoveSelectorToParent()`, `CommitSelectorBoundaryRow(bool first)`, `DoubleClickSelectorSegment(string rowIdentity, int segmentIndex)`, and `HighlightSelector(string identity)`, each returning `BreadcrumbSelectionTransition`; `ClassifyPendingArrow(BreadcrumbArrowDirection)` returning the new public enum `BreadcrumbPendingArrowAction` (`Route`, `CommitAndClose`, `CancelAndPopOut`). With the session closed, the router arrows act on the committed row exactly as before minus the #440 walks.
- R7 QFC session (in `BreadcrumbSelectionSession.Tree.cs`): `PendingNode` (pending node identity or null), `MoveToBoundary(bool first)`, `MovePage(bool previous, int pageSize)` (false for `pageSize` below 1), `MoveToParent()` (pending-only when open; on a closed session a no-op until P13-T1 adds the D-Q19 immediate commit), `CommitBoundaryRow(bool first)`, and a row-shape snapshot (`ActiveSegmentIndex`, `CollapsedAfterIndex` per row) taken by `Open` and restored by `Cancel`. `Open` sets `PendingNode` to the committed descendant when that descendant is visible (D-Q29); this lands with the open-list walk in Phase 11, because an open-list Down from the row entry of a row whose committed subfolder is shown would otherwise stop on that subfolder and break `OpenSelector_SubfolderActivation_PublishesOneDurableRenderAndNoLegacySelectionChange`. `MoveNext` and `MovePrevious` walk the visible order when open and keep the closed-list row commit (AC10).
- R8 Coordinator (in `BreadcrumbBridgeCoordinator.Keyboard.cs`): page `arrowKey` and page `unhandledArrow` messages pass through one decision: closed Right calls `OpenSelector()`, closed Left is consumed, open `CommitAndClose` calls `CommitSelector()`, open `CancelAndPopOut` calls `CancelSelector()` and then raises `UnhandledArrow(Right)`; a consumed arrow raises no `FolderArrowKeyDown`; every other arrow keeps today's route (synthetic key, router, outputs). `HandleSelectorKey` gains an optional `int? pageSize = null` and arms for `Parent`, `Home`, `End`, `PageUp`, `PageDown`.
- R9 New selector messages: `selectorSegmentDoubleClick` (`BreadcrumbSelectorSegmentDoubleClickMessage`, `RowIdentity`, `SegmentIndex`) and `selectorHighlight` (`BreadcrumbSelectorHighlightMessage`, `Identity`; spec amendment of 2026-10-23 under Inputs/outputs). The EFC atomic double-click logic and its #498 range guard move from the `ProcessInboundAsync` arm into `HandleSegmentDoubleClick` in `BreadcrumbBridgeRouter.Navigation.cs`, so `BreadcrumbBridgeRouter.cs` shrinks.
- R10 Declaration-only seams: methods declared in Phase 1 throw `NotImplementedException`; properties return null; enum values, optional constructor parameters, and message classes are real declarations with no parsing, validation, or production caller. Every Phase 2 to Phase 16 test therefore compiles against the seams and fails at run time rather than at build time.
