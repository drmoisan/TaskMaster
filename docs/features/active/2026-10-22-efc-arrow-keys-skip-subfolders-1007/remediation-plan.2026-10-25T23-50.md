## Scope

- B-1 (blocking): the QFC page marks a pending descendant `class="sub active"` (`FolderBreadcrumb.js` `makeSubfolders`), and `render` suppresses the row's own `active` class while a pending node owns the highlight, but the `QuickFiler/Resources/FolderBreadcrumb.html` stylesheet styles only `.row.selected`, `.row.active`, and `.sub.selected`. The fix adds `.sub.active` to the existing `.sub.selected` rule, proved first by a failing C# string-contract test, then AC4 is re-checked.
- N-1: direct tests for unchanged paths that lost their only test execution: EFC `leafExpandToggle` on a row collapsed away from its active segment (`BreadcrumbBridgeRouter.HandleLeafToggleAsync`); QFC `affordanceToggle` on a non-anchored collapsed row (`FolderBreadcrumbBridgeRouter.ToggleAsync`); the non-anchored branch of `BreadcrumbStateModel.Expand`; and a coordinator test that a router `unhandledArrow` output raises `UnhandledArrow` (`BreadcrumbBridgeCoordinator.PublishRouterOutputs`, which also runs the `UnhandledArrowMessage` arm of `RaiseSyntheticArrowKey`).
- N-2: rename the six rewritten #440 tests whose names contradict their assertions (list in `<FEATURE>/code-review.2026-10-25T23-25.md`).
- Out of scope: any acceptance-criterion text, the keyboard state machine, the visible-order helper (`BreadcrumbVisibleOrder`), and every C# production file. N-3 to N-5 and O-1 to O-5 are informational and are not acted on.

## Design Decisions

- D1 B-1 fix shape: the selector list of the existing rule becomes `.sub.selected, .sub.active`; its declarations (`background: var(--bc-sel-back)`, `color: var(--bc-sel-fore)`) are unchanged. Both variables are redefined by the dark-theme blocks of the same stylesheet, so the pending highlight has the committed-subfolder contrast in the light and dark themes. No other line of the HTML changes, and `FolderBreadcrumb.js` does not change.
- D2 B-1 test: `FolderBreadcrumbKeysIssue1007Tests.Stylesheet_StylesPendingDescendantLikeSelectedSubfolder` reads `FolderBreadcrumbDocument.Html` (the source the sibling string contracts read), extracts the text between `<style>` and `</style>`, and finds the rule whose selector list contains a given selector. As a positive control it first finds the `.sub.selected` rule and asserts both variables in its declaration block; it then finds the `.sub.active` rule, with the reason text `the QFC stylesheet must style the pending descendant (.sub.active)`, and asserts that its block contains `var(--bc-sel-back)` and `var(--bc-sel-fore)`. Restricting the search to the style block keeps the page script's `"sub active"` class string from satisfying the test.
- D3 N-1 reachability (no branch is deleted): the EFC branch is reachable from inbound messages: a `segmentDoubleClick` at segment 1 followed by `segmentActivate` at segment 0 leaves `CollapsedAfterIndex` at 1 and `ActiveSegmentIndex` at 0 (the existing `ArrowRight_OnRowCollapsedAwayFromActiveSegment_RestoresChain` uses this sequence for Right). The two QFC branches are reachable through the public `BreadcrumbStateRow.CollapseAfter` contract, which accepts any non-leaf index whatever the active segment (as the existing `CollapseAfter_NonLeafSegment_HidesDownstreamAndClosesLeafExpansion` relies on); they keep the Right and `[+]` behavior of that public state defined. Deleting them would edit the keyboard state machine, which this cycle must not change. The coordinator arm is reachable when an inbound `unhandledArrow` message is classified `Route` (open list, pending row expanded, Left): the router echoes the message as its output.
- D4 Placement: new QuickFiler.Test code compiles at C# 7.3, so it carries no `#nullable enable` and no C# 8 pattern syntax; new UtilitiesCS.Test files carry `#nullable enable`. `BreadcrumbBridgeCoordinatorIssue1007Tests.cs` is at 477 lines, so it becomes `partial` and the new coordinator test goes in a new partial file that reuses its private `Harness`. `FolderBreadcrumbBridgeRouterIssue1007Tests.cs` is at 499 lines and is already `partial`, so the new QFC router test goes in a new partial file that reuses its helpers. Every new file gets an explicit `<Compile Include>` in its legacy project file.
