- Timestamp: 2026-07-07T03-55

## Executive Summary

The fix directly addresses the reported defect: `Cleanup()` and `CleanupAsync()` now unsubscribe `DarkMode_CheckedChanged` from `_globals.Ol.PropertyChanged` before nulling `_globals`, mirroring the existing correct pattern in `QfcFormController.SetupDisposal.cs`. `DarkMode_CheckedChanged` additionally gains a defensive `_formViewer is null` early return. The two new regression tests are well-structured (AAA, FluentAssertions, Moq, no temp files, deterministic) and independently verified to fail before the fix and pass after. Two non-blocking code-quality observations are noted below: (1) added conditional complexity in `DarkMode_CheckedChanged` beyond what is required to fix the reported defect, exercised by no test in either its old or new form, and (2) a reflection-based private-field injection technique in the test that is reasonable for this legacy class but slightly brittle.

## Positive Observations

- The fix precisely mirrors the existing, already-correct unsubscribe pattern in `QfcFormController.SetupDisposal.cs:208-213`, rather than inventing a new idiom — good adherence to "match existing style."
- Both `Cleanup()` and `CleanupAsync()` receive the identical unsubscribe statement, guarded with `_globals?.Ol is not null`, placed immediately before the existing `_globals = null;` assignment in each method — correct null-conditional guarding, no risk of a `NullReferenceException` from the unsubscribe itself.
- The regression tests use real, raisable Moq events (`mockOl.Raise(o => o.PropertyChanged += null, ...)`) rather than reflection-invoking the handler directly, which correctly exercises the actual subscribe/unsubscribe wiring rather than only the handler body in isolation.
- The tests correctly avoid asserting on the fully-mocked, unobservable `_formViewer`/WinForms controls; they instead inject a mocked `IQfcItemController` into `_itemGroups` purely to observe `SetThemeDark`/`SetThemeLight` invocation, which is the correct indirect proxy for verifying `SetDarkMode`/`SetLightMode` were never called (both production methods iterate `_itemGroups` and call exactly those two members — confirmed by reading `SetDarkMode`/`SetLightMode` at lines 2156-2169).
- No temporary files, no `Thread.Sleep`/`Task.Delay`, no wall-clock reads, and no external dependencies in the new tests — consistent with `general-unit-test.md` UT4 and the deterministic-test rules in `csharp.md`.
- Doc-comments on the test class and both test methods clearly state intent, the pre-fix defect, and which AC each half of the test satisfies.
