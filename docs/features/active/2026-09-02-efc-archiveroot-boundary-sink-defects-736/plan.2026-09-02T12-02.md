**D1 — Toolchain resolution.** Neither `msbuild`, `vstest.console.exe`, nor `vswhere.exe` is on PATH in this environment. Every task that needs them resolves them first, in PowerShell:

```

$msbuild = & $vswhere -latest -products * -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1
```

**D2 — Coverage floors, and which policy supersedes.** CLAUDE.md is rank 1 in `policy-compliance-order`, above `.claude/rules/general-unit-test.md`. This item therefore enforces CLAUDE.md's General Unit Test Policy UT2 figures — repository-wide line coverage `>= 80%` against UT2's testable denominator, and `>= 90%` for new and changed code — and not the 85%/75% pair in `.claude/rules/general-unit-test.md`. **Which figure the `>= 90.00%` changed-line floor is evaluated against.** It is evaluated against the **strict** figure — the aggregate computed over every changed coverable line, *including* the lines this plan knows in advance no test it authors can reach. Those lines are enumerated in P6-T9 and comprise exactly two groups known in advance: the getter-body assignment `_archiveRootPath = ResolveValidatedArchiveRootPath();` in `TaskMaster/AppGlobals/AppOlObjects.cs` (P1-T5 forbids constructing an `AppOlObjects`, and the assignment sits in the caller, outside the `[ExcludeFromCodeCoverage]` wrapper it calls), and every coverable line of the production body of `InvokeFilerAsync` in `QuickFiler/Controllers/EfcDataModel.cs` (P5-T4's `TestableEfcDataModel` overrides it away, so the base body never runs under test). The lenient figure excluding them is recorded alongside, for the reader, but the gate is not evaluated against it — an executor free to move a line into an exclusion set could otherwise clear any floor. Reachability arithmetic: let `U` be the number of changed coverable lines this plan knows in advance no test it authors can reach, enumerated line by line in P6-T9, and let `N` be the strict denominator. The strict quotient `(N − U) / N` reaches 90.00% at `N = 10U` and rises monotonically above it, so the floor is reachable whenever the four production files contribute at least `10U` changed coverable lines. The four files contribute a large denominator relative to any plausible `U` — D3's delegate-driven static core is over 12 lines by itself, D4's guard is about 22 lines, and D5's notifier and default-sink members are about 50 lines before the `[ExcludeFromCodeCoverage]` wrapper is removed from the Cobertura document — so the arithmetic condition is expected to hold with margin. No expected percentage is pinned here, because the quotient depends on `U` and `U` is only known once P6-T9 enumerates it; the second group is a method body rather than a single line, so its size is not fixed in advance. If the delivered denominator is nonetheless below `10U`, the strict figure can sit under 90.00 with no implementation defect present; in that single case the executor records both figures and the denominator and reports the arithmetic condition to the caller, rather than excluding lines on its own authority.

**D8 — Red-before ordering (Bugfix Workflow, CLAUDE.md).** A C# regression test that references a member which does not exist yet produces a **compile** error, and because that failure is per-assembly it also destroys the assertion-time evidence of every other test in the same assembly. This plan therefore never authors a compile-breaking test before its seam exists. Every phase that needs a new member lands a **defect-preserving or declaration-only seam first** — a member with the correct signature and the pre-fix behaviour — proves the solution still builds, then authors the tests, records a genuine **runtime** red, and only then applies the behavioural fix. No behavioural change precedes the red run it is supposed to turn green.

**D9 — Non-vacuity gate mechanics for the two msbuild steps.** Exit code 0 alone cannot distinguish a real compile from a skipped one, so each msbuild gate attaches two file loggers and asserts two independent observations:

- Detailed-verbosity log into the gitignored `coverage` directory (`.gitignore` line 144 is `coverage/*`): **zero** case-sensitive occurrences of the literal `Skipping target "CoreCompile"`, and **at least one** case-sensitive occurrence of the literal `Task "Csc"`. The second literal is a task-started event MSBuild emits only at detailed verbosity, which is why the detailed logger exists; the first would appear on a vacuous warm build. Detailed logs of a 19-project rebuild are large and are deliberately **not** committed — a prior session committed an 81 MB coverage artifact under docs/features and it must not recur.
- Minimal-verbosity log written directly into this feature folder's evidence subdirectory and committed; this is the log retained as evidence for AC13. **Its file name ends in `.log.txt` and deliberately not in `.log`.** `.gitignore` line 84 is the bare pattern `*.log`; no negation anywhere in that file un-ignores it — the four `!` lines in `.gitignore`, at 137, 145, 193 and 219, name `.axoCover/settings.json`, `coverage/.gitkeep`, `**/[Pp]ackages/build/` and `?*.[Cc]ache/` and none of them bears on `*.log` — and no `.log` file is tracked in this repository, so this plan has no in-repo precedent of a committed `.log` artifact to rely on. That last statement is about the current tracked set rather than about every commit ever made, and it rests on two concordant measurements: a recursive glob for `**/*.log` across this worktree returns zero files, and because a clean worktree materializes every tracked path, zero files on disk entails zero tracked; independently, `git ls-files '*.log'` was run in round-5 preflight and returned zero rows.
