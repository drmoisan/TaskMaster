## Finding Under Remediation (single Major, non-CI-blocking, closing in-PR)

The cycle-1 out-of-scope finding plus the cycle-1 re-audit identified a test-determinism robustness gap: `TaskMaster.Test/OutlookObjects/Store/StoresWrapperEnumerationScopeTests.cs` both opens a `CurrentStoreContext` process-global-static scope (via `wrapper.Init()` / `wrapper.RewireAfterDeserializeAsync()` → `StoresWrapper.MaterializeFilteredStores` and `StoresWrapper.AddOrRestoreStore`) and reads the null baseline (T4/T5 assert `CurrentStoreContext.Current.Should().BeNull()`), yet is not marked `[DoNotParallelize]`. It is race-free under the required CI invocation (`TaskMaster.Test` carries no `[assembly: Parallelize]`, so CI runs it sequentially) but can observe pollution under `scripts/vscode/TaskMaster.cli.runsettings`, which force `ClassLevel` parallelization. This is the same shared-static parallel-race class fixed in cycle 1 for `UtilitiesCS.Test`.
