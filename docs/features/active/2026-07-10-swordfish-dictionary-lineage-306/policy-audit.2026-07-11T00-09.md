### 1.1 Out-of-scope-lock production edits (explicit evaluation)

The plan's Scope-Lock listed nine production files. Two production edits landed in
files not on that list, plus one behavior addition inside a scope-locked file.
Each is evaluated as mechanically-necessary-by-necessity:

- `FilterOlFoldersController.cs` and `FolderRemapController.cs`: `.Remove(key)` ->
  `.TryRemove(key, out _)`. Necessary because `ScoDictionaryNew` (ConcurrentDictionary-backed)
  does not expose a public `bool Remove(TKey)` accessible on the concrete/interface
  type; the `IToDoObjects` contract change forced the consumer to compile against the
  new removal API. Behavior-preserving: both remove the key if present and are no-ops
  otherwise; the discarded `out`/`bool` are irrelevant inside `.ForEach`. Covered by
  `SyncGlobalMap_WhenKeyNotInMappings_RemovesObsoleteKey` and
  `Save_WhenSelectionChanges_RemovesDeselectedKeysAndAddsSelectedKeys`. Verdict: PASS, non-blocking.
- `FolderScorer.cs`: `.ThenBy(x => x.Key, StringComparer.Ordinal)` added to both
  `ToArray()` overloads. Necessary because `ScoDictionaryNew` enumerates in
  non-deterministic ConcurrentDictionary order (the legacy Swordfish type enumerated
  in insertion order); the ordinal key tie-break restores deterministic, culture-independent
  ranking among equal-score folders. Directly asserted by
  `LoadFromField_WithMailItemAndFolderKeyArray_ReturnsTrueAndAddsSuggestion` and its
  `MailItemHelper` sibling (`ToArray().Should().Equal("Archive\\Finance","Archive\\Ops")`,
  an equal-score pair in ordinal order). A rationale comment documents the why.
  Verdict: PASS (behavior made more deterministic), non-blocking.
- `SortEmail.cs`: `await ...Encoder.SerializeAsync()` -> `...Encoder.Serialize()`
  (this file IS on the Scope-Lock, task P3-T5). Necessary because `ScoDictionaryNew`
  exposes no async serialize. Consistent with the spec's "persist via plain `Serialize()`"
  contract. Minor behavior note (Low): the write is now synchronous on the calling
  thread rather than awaited; the surrounding method signatures remain `async` and
  persist-on-completion semantics are preserved. Verdict: PASS, non-blocking.
