## Settled decisions this plan implements (not open for relitigation)

1. **Scope is four production files, not two.** Sites A' (`EfcHomeController.cs`) and B'
   (`ProgressPane.cs`) carry the character-for-character identical defect and were brought in scope
   by the mandated enumeration (spec "Scope widening", OQ4, OQ5).
2. **OQ3 supersedes one bullet of the spec's "Recommended shape".** The spec labels that section
   *recommended, not mandated*. Its bullet suggesting an inline `Enabled = tokenSource is not null;`
   at `UtilitiesCS/Threading/ProgressViewer.cs` line 67 is superseded **for `ProgressViewer` only**:
   `SetCancellationTokenSource` instead delegates to the already-correct `CancelSource` property
   setter, which removes the duplicated enabling logic rather than duplicating and patching it
   (General Code Change Policy, reusability). `ProgressPane` has no `CancelSource` property, so it
   keeps the inline null check. AC10 and AC11 are satisfied under both shapes, because AC10 asks
   only that a null source leaves the button disabled. **This is a recorded reconciliation, not a
   deviation.**
3. **OQ2 requires both test actions.** AC3 adds a dedicated single-purpose test *and* AC4 relocates
   the existing blind assertion. Neither substitutes for the other.
4. **AC21 files no GitHub issue.** AC21's own Discharge boundary paragraph states that filing O-4 is
   deliberately **not** an acceptance criterion, superseding the "Rollout & Follow-up" bullet that
   says "promote O-4 as its own issue before merge". The promotion obligation sits at the
   orchestration layer. **This plan contains no task that calls the GitHub API and no task that
   writes under `docs/features/potential/`**; such a task would be undischargeable by the executor
   and would falsify AC20.
5. **Coverage policy divergence is resolved in favour of CLAUDE.md.** The 80% repository line floor
   and the 90% new-code floor govern. The 85% and 75% figures in `.claude/rules/general-unit-test.md`
   and `.claude/rules/quality-tiers.md` are not used here. Because no merge-base coverage baseline
   exists in this feature folder, the repository-wide figure is a **record-and-report** obligation;
   the **blocking** coverage conditions are change-scoped (AC18).
6. **AC20 footprint, reconciled with the evidence contract.** AC20 polices repository source and
   configuration. The permitted changed-path set for this plan is exactly: the eight Write Set
   files, `spec.md`, `issue.md`, `research/enumeration-findings.2026-09-08T23-45.md`, this plan
   file, and paths under the feature folder's `evidence/` tree. The four feature-folder documents
   are included because the branch already carries the preparation commit that added them, so
   `git merge-base HEAD origin/main` resolves below that commit and every anchored diff this plan
   runs lists all four whether or not this plan edits them; they are permitted rather than
   out-of-scope. Entries under `.claude/agent-memory/` are additionally excluded from the footprint
   condition: they are tracked in this repository, are written by agents mid-run, and must be
   neither staged nor committed by this plan. Every other path — in particular any `.csproj`,
   `.editorconfig`, `BannedSymbols.txt`, anything under `.claude/rules/` or
   `.github/instructions/`, `CLAUDE.md`, and every path named in the spec's "Out of scope /
   non-goals" section — must be absent from both spans.
