## Decisions

- **D-1 Seam (orchestrator decision).** The two-overload delegate seam of the Orchestrator Decisions section, mirroring the precedent of fact 4. Both overloads keep `[ExcludeFromCodeCoverage]`. The two-parameter overload is a NON-async method returning `Task<bool>` whose only statement is `return TrySaveAttachmentAsync(attachment, filePathSave, path => System.IO.Directory.CreateDirectory(path));` (an async wrapper would add a state machine for no benefit); the core keeps `async`.
- **D-2 Tests (orchestrator decision).** T-A records events in a `List<string>` (the seam adds `mkdir:` plus the directory; a `SaveAsFile` callback adds `save:` plus the path) and asserts the exact ordered list, so it proves both that the seam received the destination directory and that it ran before `SaveAsFile`. This is the recording-list form research section 10 item 4 permits in place of a strict mock. T-B passes a seam that throws `IOException`, asserts propagation and that `SaveAsFile` is never called.
- **D-3 Fail-before is a compile-red run plus a dossier.** The rewritten tests are written before the production seam (P1-T1 and P1-T2). P1-T3 builds that state and requires the build to FAIL with a compiler error that names `TrySaveAttachmentAsync` (the call passes an argument no overload accepts; the compiler is expected to report CS1501, recorded as an observation), which is the recorded fail-before observation. A runtime-red run of the pre-fix behavior cannot be obtained without a side effect: the pre-fix behavior is a direct call to the real `Directory.CreateDirectory` with a rooted path on the system drive, which creates a directory outside the repository or, when the create is denied, raises `UnauthorizedAccessException` and reaches the modal `YesNoToAll.ShowDialog`. A stub that omits the call avoids the side effect but is the production edit P1-T14 already applies as the control, so it adds no separate observation.
