## Blocking planner finding carried into this plan

The fix direction supplied for this item — match the `.claude` clause against the candidate path computed relative to `$resolvedSearchRoot` — is correct, but a literal substitution that keeps the existing regex `'\\\.claude\\'` unchanged **breaks the regression test this item is required to preserve**.

`[System.IO.Path]::GetRelativePath` returns a descendant path with **no leading separator**. For the fixture in `tests/scripts/vscode/Invoke-MSTest.RunSettings.Tests.ps1` line 423, the candidate `C:\repo\.claude\worktrees\agent-1\QuickFiler.Test\bin\Debug\QuickFiler.Test.dll` relative to the search root `C:\repo\.` is `.claude\worktrees\agent-1\QuickFiler.Test\bin\Debug\QuickFiler.Test.dll`. The existing regex requires a backslash immediately before `.claude`, so it does not match that string, `-notmatch` returns true, the nested sibling worktree is **retained**, and the assertion at lines 440-441 fails. That would violate spec AC3 and AC6 while appearing to implement AC1.

The corrected clause therefore anchors the alternation to the start of the relative path as well as to an interior separator. The exact replacement literal this plan requires is:

`(^|\\)\.claude\\`

and the exact replacement expression is:

`([System.IO.Path]::GetRelativePath($resolvedSearchRoot, $_.FullName)) -notmatch '(^|\\)\.claude\\'`

This stays inside the supplied fix direction: the match **target** changes from the absolute `FullName` to the relative path exactly as directed, and the anchor is the corollary that direction requires in order to keep the same set of paths excluded. `[P1-T3]` measures the three `GetRelativePath` return values directly and records them, so the anchor decision rests on an observation rather than on this paragraph.
