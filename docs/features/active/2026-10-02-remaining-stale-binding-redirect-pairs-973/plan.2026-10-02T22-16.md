## 6. Conventions

- **C1 Artifact fields.** Every command-bearing artifact carries `Timestamp: <yyyy-MM-ddTHH-mm>` read from the clock (`Get-Date -Format yyyy-MM-ddTHH-mm` inside the first pwsh payload of the task, or the Bash tool's `date` is not used; when no pwsh runs in a task the executor runs `pwsh -NoProfile -Command 'Get-Date -Format yyyy-MM-ddTHH-mm'`), `Command: <exact invocation>`, `EXIT_CODE: <int>` as observed, `Output Summary:` (1 to 20 lines). An expect-fail task carries `ExpectedExitCode: 1`. One artifact carries one `EXIT_CODE:` row; further exit values are named `Output Summary:` lines.
- **C2 Artifact naming.** Fixed names where section 5 lists one; otherwise `<FEATURE>/evidence/<kind>/<task>-<slug>.<timestamp>.md`. A toolchain-loop iteration that is not the final clean pass writes `<fixed-name-stem>.iter<N>.md`; the final clean pass writes the fixed name.
- **C3 MCP exit derivation.** For a PoshQC MCP call, `EXIT_CODE:` is 0 when the payload `ok` is true (and, for the test tool, the JUnit root `failures` is 0) and 1 otherwise; the payload is recorded verbatim with the worktree root replaced by `<execution-worktree-root>`.
- **C4 Host paths.** No evidence line carries an absolute host path, machine name or account name; `<execution-worktree-root>` replaces the worktree prefix. The placeholder is never defined by an absolute line anywhere in the feature folder: the executor substitutes it from the absolute worktree path its launch prompt supplied, P0-T2 records only `WORKTREE-MATCH: True` (that path equals `git rev-parse --show-toplevel`) and `WORKTREE-LEAF: <final path segment>`, and P4-T12 and P5-T25 Grep the whole feature folder, plan included, for host-path residuals (`HOST-PATH-RESIDUALS: 0`), per `.claude/agent-memory/_shared_no_absolute_host_paths.md`.
- **C5 Tool routes.** Read-only tree observations use the Read, Grep and Glob tools or `git`. Grep patterns in this plan are ripgrep patterns run through the Grep tool; a Grep over a gitignored file (`artifacts/pester/pester-junit.xml`, anything under `coverage/`) passes the absolute file path and no glob. Every git command is `git -C <execution-worktree-root> ...`. Every shell step is one `pwsh -NoProfile -Command '<payload>'` invocation; payloads are single-quoted so the parent never interpolates `$`, contain no single-quote character (strings inside use double quotes), begin with `Set-Location -LiteralPath "<execution-worktree-root>"`, and name every file operand relative to that root or absolutely. `cd`, `grep`, `sed`, `awk`, `cat`, `head`, `tail`, `find`, `cp`, `mv`, `rm`, `echo` are never issued through the Bash tool. If the Bash tool refuses a pwsh invocation, the executor records `PWSH-REFUSED: <tool message>` and STOPs (no fallback is defined for a command-bearing C# task). The executor must be launched non-isolated: the worktree-isolation guard refuses `pwsh` in every form (`-Command`, `-File` and bare), so a `PWSH-REFUSED` at the first pwsh invocation of the run (the P0-T1 timestamp read) means the launch topology is wrong; it is recorded as `LAUNCH-TOPOLOGY: ISOLATED` for the orchestrator to relaunch and is not a plan defect.
- **C6 Git gate scoping.** `<PLAN-START-HEAD>` is the P0-T2 value. Every `git diff` carries a ref operand. Every footprint evaluation removes paths under `.claude/agent-memory/` and the P0-T2 `INHERITED` list before comparing against the Write Set union (section 5 files plus every path under `docs/features/active/2026-10-02-remaining-stale-binding-redirect-pairs-973/`).
- **C7 Stop rule.** Where a task says STOP, the executor writes the task's artifact with the observed values, leaves the checkbox unchecked and ends the run with a report. No stop is a pass.
- **C8 Check-off protocol.** Plan checkboxes flip only after the task's artifact exists with every C1 field. spec.md check-offs happen only in P5-T1 to P5-T17 and P5-T19 to P5-T23, one criterion per task, changing `- [ ]` to `- [x]` and nothing else on the line; AC18 stays unchecked (D10).
- **C9 Hooks.** A hook block is recorded verbatim (`HOOK-BLOCKED: <message>`) and reported; the executor does not rephrase, re-anchor or restructure to pass it. A block on an edit or command is a STOP for that task (C7); the CLAUDE.md edit of P3-T26 names its own STOP label (D16).
- **C10 Scripted file rewrites.** The two Part H payloads (CMD-SPLIT-NEWFILE, CMD-SPLIT-ORIGINAL) and the CRLF normalisation command (CMD-NORMALISE-CRLF, the P1-T4 command with its path parameterised) are the only `pwsh` payloads in this plan that write a repository file; each prints the counts the next gate reads, and each is followed in the same task by the Grep and count gates that verify the written text. Every other edit of a repository file is an Edit-tool replacement.
