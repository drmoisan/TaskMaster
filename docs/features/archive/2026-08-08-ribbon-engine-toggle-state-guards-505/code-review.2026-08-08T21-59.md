## Detailed Analysis Against the Review Focus Areas

### 1. Ordering invariant and memory visibility

`ExecuteToggleAsync` performs `await ToggleEngineAsync` -> `await EngineActiveAsync` -> cache write -> `invalidateControl`, and the test pins the sequence with a cache probe inside the invalidation sink. Cross-thread visibility is sound: `_pressedState` is a `ConcurrentDictionary`, so the STA `getPressed` poll observes thread-pool writes with correct ordering, and the invalidation delegate marshals through `UiThread.Dispatcher`. The invariant holds for each path in isolation. It is **not** race-free across overlapping paths: see the Major finding (prime-overwrites-toggle) and its residual double-click variant. Neither interleaving can deadlock or throw; both degrade to a stale display corrected by the next click.

### 2. The `async void` boundary

Verified sound. Both viewer handlers are single awaited expressions into `HandleEngineToggleClickAsync`, whose returned task cannot fault: the only `catch` in the type wraps `ExecuteToggleAsync` and routes to `logError` without rethrow and without invalidating. The prime path is observed by a `ContinueWith` continuation that reads `Task.Exception` (marking the fault observed — no `UnobservedTaskException` remains) and whose own task always completes successfully, which is what makes `GetPrimeTask` safely awaitable by tests. The boundary test (`HandleToggleClickAsync_WhenToggleFaults_...`) asserts the fault instance is delivered to the sink. Residual exposures are the two Info/Minor items (sink outside the `try`; canceled prime ignored).

### 3. The two-guard-shape split

Correct, and each of the ten sites is assigned to the correct shape. The four configuration-backed sites (Spam/Triage click + getPressed) route through the coordinator and never consult `InboxEngines`; the six `InboxEngines`-backed save/info sites route through the pre-existing `RunEngineCommandAsync` gate with the dereference deferred into the lambda, backed by six new catalog entries and six `getEnabled` attributes landed atomically. Independently re-derived: 11 `Engines.` references at merge base, 1 pre-gated, 10 unguarded; at head, 0 unguarded production dereferences and `TestSpam_Click` byte-identical. The checkbox ids stay out of `EngineCommandCatalog`, preserving the button-only XML test.

### 4. Test quality

MSTest + Moq (strict) + FluentAssertions throughout; TCS-driven determinism; no sleeps, wall-clock reads, temp files, `Form`/`MessageBox`/`BackgroundWorker`, message pump, or COM; no test drives `NotifyEngineCommandNotReady`. The tests exercise behavior: recorded sequences with in-sink cache probes, reflection invocation of the real pre-`SetGlobals` viewer, XML-resolved callback names, and the `AsyncStateMachineAttribute` pin (present only for genuinely awaited bodies). No tautology found. Gap: the uncovered defensive guard (Minor, above).

### 5. Does the fix genuinely fix #505?

The automated evidence establishes everything automatable: the signature now matches the Office contract exactly (pinned red-first by R1), the read is a lock-free dictionary lookup that cannot block the STA, and the cache converges to the true engine state through the prime -> cache -> invalidate -> re-poll cycle (verified end-to-end at the coordinator seam). Actual VSTO binding cannot be proven without a live Outlook session — VSTO ignores mismatches silently — which is exactly what the pending MANUAL-ONLY AC-22 checklist covers. Within the automated boundary, yes; final confirmation is deliberately deferred to AC-22.
