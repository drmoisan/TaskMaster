### Why this is the correct fail-before signal

The stack confirms the defect exactly where `P2-T4` will fix it. `ProcessInboundAsync` reaches
`BreadcrumbBridgeRouter.cs:242` — the `SegmentDoubleClick` arm's null-forgiving
`row.CollapseAfter(message.SegmentIndex!.Value)` — with no range validation, and
`BreadcrumbRow.CollapseAfter` throws from its documented guard. The row under test carries two
segments, so the valid range is `[0, 1]` and both 99 and -1 sit outside it.

The synchronous `Inbound` helper was used deliberately. It calls
`ProcessInboundAsync(json).GetAwaiter().GetResult()`, so the exception is re-thrown on the MSTest
thread and produces a deterministic, readable RED naming the exception type. The four
`_host.Raise(...)` boundary-containment methods that AC-1 requires literally are authored and first
executed in `P2-T6`, after the guard exists; running them here would have leaked an unhandled
exception onto a thread-pool thread through the async void seam.
