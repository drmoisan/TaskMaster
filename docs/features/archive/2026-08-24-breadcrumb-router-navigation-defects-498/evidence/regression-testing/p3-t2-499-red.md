### Why this is the correct fail-before signal

Both failures are the #499 defect stated directly. The internal `BindRowsAsync` overload at
`QuickFiler/Controllers/BreadcrumbBridgeRouter.cs:92-138` resets `_selectedRowId = null;` at `:136`
but leaves the `SelectedFolderPath` property at `:59` holding the pre-rebind value, and raises no
`SelectedFolderPathChanged` (`:62`) notification.

- The first test observes the retained value literally: after a selection of `row-0` and a second
  bind, the property still reads `Inbox\Projects\Alpha`, which is the `LeafPath` constant used by
  the shared `Setup()` arrange block.
- The second test's sentinel is never overwritten, proving that no notification is raised at all
  rather than one carrying a wrong payload. The subscription is attached after the selection and
  before the second bind, so only the re-bind's notification could have changed it.

The `Bind()` helper is re-entrant, so the second bind is a genuine re-bind of the same presented row
set. Version 1.0 of the plan referred to an existing "double-`Bind` pattern" in the primary test
file; that pattern is no longer present there, so the second bind is introduced by these two tests
themselves.
