Contract additivity (spec AC-10) was verified directly from the interface diffs. All partial-class extractions are verbatim-plus-guard relocations motivated by the 500-line ceiling, with the relocated `OpenAsync`/`FocusCurrentSurface` bodies matching the deleted originals except for the documented guards.

Two findings warrant action: one blocking coverage-gate finding on a new production file whose documented fallback behavior has no test, and one pre-existing per-file floor miss surfaced (not caused) by this change. One recurring tooling defect (PR-context C# misclassification) was corrected in place during this review. No test was weakened, disabled, or relaxed anywhere in the diff; no silent scope creep was found (the changed-file set matches the spec's 12-file estimate plus the 6 sanctioned new partials exactly).

Notable design strengths observed:

- The latch consume-exactly-once semantics in `BeginOpenCore` (with the leak-prevention comment) correctly prevent a search-originated non-focusing intent from bleeding onto a later gesture open, and `LatchedOpen_SelfClearsSoTheNextOpenTakesFocus` pins it.
- The deliberate choice to keep gesture opens on the 3-parameter overload (documented in `BeginOpenCore`) avoids breaking loose `Mock<IBreadcrumbDropDownHost>` setups across the existing suite — a pragmatic compatibility decision with the rationale recorded in-code.
- The explicit interface implementation of the 4-parameter `OpenAsync` (deviation D11) keeps the concrete host's public surface at one `OpenAsync` and preserves 8 pre-existing reflection-based tests byte-unmodified.
- `ReplaceItemsPreservingSession` deliberately avoids the existing `SetItems` (which destroys session identities via `_model.Clear()`); the reason is documented where the decision lives.

## Detailed Review Notes

### Correctness of the focus-intent pipeline

- `OpenWithFocusIntentAsync` preserves the original open contract exactly (disposal check, already-open early return, `LastInitializationException = null` reset); the only behavioral delta is the `takeFocus` guard on `Schedule(_focusPending)` — matching the deleted 3-parameter body line-for-line otherwise.
- `FocusCurrentSurface` relocation is verbatim with the single `if (takeFocus)` guard; lease-currency checks and the return contract are unchanged, so a non-focusing open reports the same open result as a focusing one (pinned by `OpenAsync_FreshOpenWithoutFocus_InvokesNeitherFocusDelegate` and the zero-working-area rollback test).
- The internal `BreadcrumbDropDownOpenLifetime.OpenAsync` signature change (3→4 parameters, not additive) is internal-only; its single caller (the host) is updated in the same change. No public contract is affected.

### Session and router transitions

- `HighlightRow` requires `IsOpen`, mutates only `PendingIdentity`, and emits `Handled | RenderRequired` — matching the spec's pending-only contract; `Cancel_AfterHighlight_RestoresThePreSearchCommittedIdentity` pins the Escape path (spec AC-5).
- The inclusive-scan adjustment (`index - 1` with negative clamp) into `NextSelectableIndex` is subtle but correctly commented; banner-only and empty sets return `None` without throwing (11 edge-case tests).
- `ReplaceItemsPreservingSession` bumps `_suggestionGeneration` so an in-flight `SetSuggestionsAsync` cannot overwrite a search refresh — a race the plan called out; `BuildPlainRows` reuses the `ForPlainRow` identity rules so replacement snapshots stay identity-compatible.

### Test integrity verification (caller-flagged concern)

Full diff review of all five touched existing test files confirms: exactly one test method was rewritten (the sanctioned one; assertions strengthened, none removed), the three fake edits are purely additive recording members whose 3-parameter forms delegate with `takeFocus: true` (preserving prior behavior), and the two `partial` keywords are one-token structural enablers. No `[Ignore]`, no assertion relaxation, no `Times` loosening anywhere in the diff.

### AC-11 amendment assessment (caller-flagged concern)

The amended AC-11 wording enumerates the sanctioned structural edits exhaustively (three named fakes, one-token `partial` keywords) and pins them with "must add, remove, weaken, or alter no test method". This is a tightening-by-enumeration, not a weakening: the original "single test modification" wording was factually unsatisfiable once the interface member forced fake implementers to add the new member (an interface-implementation requirement, not a behavioral choice), and the amendment constrains those edits to non-behavioral shapes that this review verified individually. The amendment protects test integrity.
