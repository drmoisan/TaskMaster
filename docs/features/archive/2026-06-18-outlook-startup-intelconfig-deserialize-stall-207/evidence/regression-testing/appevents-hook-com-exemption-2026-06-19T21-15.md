# AppEvents.Hook() DispatcherTimer/COM Logging-Only Coverage Exemption (Issue #207, increment 3)

Timestamp: 2026-06-19T21-15

Rule: General Unit Test Policy UT5 explicit-exception call-out, layered with the CLAUDE.md COM/VSTO coverage exemption (and the mirrored exemption in .claude/rules/general-unit-test.md). `AppEvents.Hook()` is in the documented COM-host-bound, coverage-exempt set: it depends directly on `Microsoft.Office.Interop.Outlook` (`Globals.Ol.OlReminders`, `Globals.Ol.ToDoFolder.Items`, `Globals.Ol.Inboxes`) with no injectable seam.

WhyNoUnitTest: `Hook()` and the new private `ScheduleDeferredRemindersProbe(TimeSpan, Stopwatch)` helper it calls cannot be unit-tested without a live Outlook process and a live STA message pump. `Hook()` reads live COM properties; the deferred path additionally schedules a `System.Windows.Threading.DispatcherTimer`, whose `Tick` fires only when an STA `Dispatcher` is pumping messages. Both are external-dependency-bound (live COM + live timer/pump), which the external-dependency prohibition forbids in unit tests. The `DispatcherTimer` wiring is STA scheduling/logging glue around the COM access; it carries no business logic of its own. The pure decision/scheduling logic — whether to defer and the resolved delay `TimeSpan` — is extracted into the COM-free, timer-free, clock-free `RemindersProbeSchedule` seam and is unit-tested separately and deterministically in `TaskMaster.Test/AppGlobals/RemindersProbeScheduleTests.cs`.

VerificationMethod: Inspection of the deferred-path branch in `TaskMaster/AppGlobals/AppEvents.cs`:
- Default path (`RemindersProbeSchedule.ShouldDefer == false`, i.e. `RemindersProbeDelaySeconds <= 0`): the first `OlReminders = Globals.Ol.OlReminders;` assignment executes synchronously, still wrapped by `remindersStopwatch`, identical to the pre-increment-3 implementation.
- Deferred path (`ShouldDefer == true`, `RemindersProbeDelaySeconds > 0`): a single `DispatcherTimer` with `Interval = schedule.Delay` is started; on its first `Tick` it stops itself (guaranteeing single execution) and then performs the same `OlReminders = Globals.Ol.OlReminders;` assignment through the same synchronized `OlReminders` property.
- Exactly one deferred log line ("Hook reminders probe") is emitted on the deferred path only, carrying both `accessLatencyMs` (a per-access `Stopwatch`) and `elapsedSinceHookMs` (the `hookStopwatch` started at `Hook()` entry). No `DateTime.Now`/`DateTime.UtcNow`/`Random.Shared`/`Thread.Sleep`/`Task.Delay` is used; timing is `Stopwatch` only and the delay is `DispatcherTimer` only.
- The `ToDoFolder.Items` read and the inbox subscription loop are untouched by the probe in both paths. No live-Outlook test and no live-timer test were introduced.

RuntimeValidationNote: Confirming the actual latency-vs-delay curve (Possibility 1 relocatable readiness wait vs Possibility 2 intrinsic first-access build cost) requires launching Outlook multiple times with varying `RemindersProbeDelaySeconds` values and reading the emitted `Hook reminders probe` log lines. This is a manual multi-launch runtime capture performed by the user; it is explicitly NOT a unit test and is NOT part of this plan's QC loop.
