## Assessment

The exclusion recommended by the research document (D5) is supported on three independent grounds,
the first of which is decisive:

1. **Authorization.** The `policy-compliance-order` skill's hard constraint reads: "Do NOT modify
   policy documents under `.claude/rules/` or `.github/instructions/`." The epic charter's "Execution
   Authorization Required" section suspends that constraint for `CLAUDE.md` and `.claude/rules/` only.
   `.github/instructions/` is named in the same clause and is **not** covered by the suspension.
2. **Correct repair point.** Editing `AGENTS.md` directly would contradict its own "Do not edit this
   file manually" directive and would be overwritten by any future regeneration. The correct repair is
   at the `.github/instructions/` sources followed by regeneration — but the generator is missing, so
   the repair is not currently mechanically possible without also restoring it.
3. **Ownership.** `.agents/skills/` self-describe as inbound Codex resources originating in the
   separate `drm-copilot` governance repository, so this repository is not their source of truth.

## Required follow-up

Excluding these sites leaves the defect live for Codex-driven and Copilot-driven sessions. A follow-up
issue must be filed through the MCP promotion lifecycle covering:

- authorization to edit `.github/instructions/`;
- restoration or recreation of `scripts/dev-tools/sync-agents-from-instructions.ps1`;
- regeneration of `AGENTS.md` from the corrected sources;
- coordination with `drm-copilot` for `.agents/` and `.codex/`.

Recording this as prose inside a feature folder is not sufficient: per repository practice, an
out-of-scope defect that is not promoted to a real issue disappears when the feature folder is
archived at merge.
