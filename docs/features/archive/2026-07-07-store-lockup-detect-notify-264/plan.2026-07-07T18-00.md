**Fix design (binding):**
- **Detection (`ThreadMonitor`, research §2).** Inject `System.TimeProvider` (production `TimeProvider.System`; tests `FakeTimeProvider`), replacing `Thread.Sleep`-based timing with provider-driven elapsed-time measurement. Add a second, larger, constructor-injected `lockupAttributionThresholdMs` (planning-decision default **5000 ms**, distinct from the existing small `delayThreshold` used for the diagnostic stack-trace cadence; no hardcoded attribution literal at the call site — the default lives on the constructor parameter and is overridable). Add an injected `Action<LockupAttribution> onLockupDetected` callback, invoked on the watchdog's own background `Task.Run` thread when the attribution threshold is crossed. The obsolete `Thread.Suspend`/`Thread.Resume` stack-capture path stays gated behind the unchanged `delayThreshold` and is NOT on the attribution path.
- **Pure decider (`LockupStallDecider`).** Extract the elapsed-ms-in / stall-confirmed-out decision into a pure, COM/clock/Dispatcher-free helper following the `StartupLifetimeStopDecider` split (`TaskMaster/AppGlobals/StartupDiagnosticsProbe.cs:312`), unit-testable without a live host. `LockupAttribution` (readonly struct carrying stall duration + store identity string) is defined here.
- **Attribution (`CurrentStoreContext`).** New `UtilitiesCS/Threading/CurrentStoreContext.cs`: static class backed by `private static volatile string _current`, exposing `Current` (read) and `Begin(string storeIdentity)` returning an `IDisposable` that restores the previous value on `Dispose`. Single-writer (STA) / single-reader (watchdog thread); NOT `AsyncLocal` (research §3.1). `Begin` normalizes a null or `"<unavailable>"` identity to "no context". Host-neutral, no COM.
- **Set/clear points (research §3.2).** Wrap only the post-`DisplayName` blocking calls, using the already-cached `DisplayName`, at three sites: `StoreWrapper.Init()` (wrap `GetRootFolder()` → `GetSmtpAddressFromStore()`), `StoresWrapper.RewireOlObjectsAsync` (wrap `Init()`/`Restore(store)` inside one loop iteration, opened after `await Task.Yield()` so nothing leaks across the yield), and `AppOlObjects.EmitPerStoreInboxAttribution` (wrap the `getDefaultFolder()` call). Additive, behavior-preserving; the existing `[Startup timing]`/`[store-filter]`/`[loadinboxes]` lines are unchanged.
- **Auto-disable-then-notify (`StoreLockupResponder`, research §4).** Host-neutral orchestrator invoked by the `ThreadMonitor` callback. Dependencies are all interface/delegate seams: F1's `IStoreDisableService`, an `IUiDispatcher`, the modeless-notify composition seam, and a logging sink. Confirmed order: guard-no-context → guard-`IsDisabled` → `DisableSessionOnly(StoreIdentity)` synchronously on the background thread → emit one `[store-lockup]` WARN line → `IUiDispatcher.BeginInvoke` (fire-and-forget, never `Invoke`, never modal) to show the modeless notification. The responder converts the cached `DisplayName` string to `StoreIdentity` via F1's pure `StoreIdentity.Resolve(displayName)` (epic Shared Design Alignment; no blocking COM read).
- **Modeless notification (research §4.3).** New internal, non-`using`-scoped modeless composition inside `UtilitiesCS` (new method on `MyBox` or a sibling internal helper, because the `ReplaceButtons`/`AppendButtonInColumn` building blocks are `internal static` and `UtilitiesCS` does not grant `InternalsVisibleTo` to `TaskMaster`; `ActionButton` itself is `public` (`UtilitiesCS/Dialogs/ActionButton.cs:13`), but the in-assembly-composition rationale still holds because the button-wiring helpers are internal). Construct `MyBoxViewer` directly, own its lifetime via a `FormClosed` handler, and show it through an injectable `Action<MyBoxViewer> showAction` defaulting to `viewer => viewer.Show()`, mirroring `EfcHomeController.ViewerShowAction` (`QuickFiler/Controllers/EfcHomeController.cs:294-297`). The existing modal `ShowDialog`/`DialogInvoker` overloads are NOT modified. Three buttons: "Disable This Session Only" → `DisableSessionOnly`, "Disable for Future Sessions" → `DisableForFutureSessions`, "Reenable" → `ReenableAsync` (F1 orchestrates the F3 rehook internally; F4 makes a single call).
- **WARN line (`StoreLockupAttribution`).** Pure `[store-lockup]` line formatter (identity, stall duration, auto-disable outcome), mirroring `StoreFilterAttribution.FormatLine`. No log4net/COM/clock dependency. The existing WARN-filtered `important_logs_file` appender captures a `logger.Warn(...)` line with no config change (research §1.5).
- **Enablement (`ThisAddIn.cs`).** Change `UiThread.Init(monitorUiThread: false)` to `true` at `TaskMaster/ThisAddIn.cs:28` (the only caller of `UiThread.Init`), and wire `StoreLockupResponder`'s dependencies (F1's `StoreDisable` from `IApplicationGlobals`, a `WpfUiDispatcher`, the modeless-notify composition) at startup. This is the RISK task; see Phase 8.
