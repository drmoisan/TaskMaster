## 8. Findings

### RC-1 (Blocking) — event-subscription regression introduced by this branch: `WireIntentEvents` 17 / `UnwireIntentEvents` 16

- Location: `QuickFiler/Controllers/QfcItemController.EventWiring.cs` — `WireIntentEvents()` (17 live `+=` after this branch's addition at line 94), `UnwireIntentEvents()` (16 `-=`, no `PicturesChanged` detachment; both counts re-measured by this reviewer).
- Rule violated: General Code Change Policy design and regression principles — a code change must not introduce a new defect; the epic's own sibling 484 (#481) established balanced wire/unwire as required behavior of `Cleanup()`, and this branch regresses exactly that invariant. Before this branch the surface was balanced 16/16; after it, every controller that is wired and then cleaned up retains one live `PicturesChanged` subscription, keeping the torn-down controller reachable from its pooled viewer and delivering future picture-toggle events to it.
- Why the shipped deferral fails: AC11 required only a handoff record naming the 17th detachment as an obligation on upstream 484, and that record exists and is honest (`evidence/other/wireintentevents-16-to-17-handoff.2026-08-28T01-55.md`). But the record itself documents `Upstream484Landed: true` — 484 is merged and closed, so the obligation is handed to a feature that can never receive it. The spec's deferral design was premised on 484 being in flight; Phase 0 disproved that premise, and no issue, task, or live sibling now owns the detachment.
- Why remediation is small and unblocked (each enabler verified on disk by this reviewer): (a) the 484-owned test `UnwireIntentEvents_DetachesAllSixteenIntentSubscriptions` (`EventWiringTests.cs:377`) asserts sixteen individual `VerifyRemove ... Times.Once()` calls and pins no total, so a 17th detachment keeps it green; (b) `EventWiring.cs` measures 483 lines (17 spare) and is already in this feature's permitted diff set; (c) `EventWiringTests.Part2.cs` measures 81 lines (419 spare) and already contains the wiring-side fixture; (d) a `-=` for a never-attached handler is a no-op, so the added line is safe on every teardown path including the partially-constructed-controller path guarded at the top of `UnwireIntentEvents()`.
- Disposition: **Blocking.** Remediation directives in `remediation-inputs.2026-08-28T03-13.md`.
