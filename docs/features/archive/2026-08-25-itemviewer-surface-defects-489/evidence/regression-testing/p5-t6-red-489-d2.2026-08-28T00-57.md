Both are `Moq.MockException` verification failures, not exceptions escaping the production member.
The "Performed invocations" block is the direct evidence of #489 D2: with `InvokeRequired` stubbed
`true`, the only call the viewer received was `IItemViewer.NavigateToString("")` and `Invoke` was
called **0 times**. `HtmlDarkConverter` at `QfcItemController.FocusAndTheme.cs:288-300` writes to the
WebView2 surface unconditionally, with no `InvokeRequired` check, so a theme change raised on a
background thread touches the control from the wrong thread.

Neither test failed for an unrelated reason. There is no `NullReferenceException` and no
`ArgumentNullException`: the fixture correction recorded at P5-T5 removed the only incidental
exception path, so `ItemHelper.ToggleDark` reduces to a pure string transform returning `""` and
`ConversationResolver.Count` is seeded to a loaded `(0, 0)` that leaves the expanded branch
unentered. What remains is exactly the guard under test.

The two assertions are complementary and both are needed. The first proves the marshal does not
happen; the second proves the write happens anyway. A fix that merely added an `Invoke` call while
still writing directly would satisfy the first and still fail the second.
