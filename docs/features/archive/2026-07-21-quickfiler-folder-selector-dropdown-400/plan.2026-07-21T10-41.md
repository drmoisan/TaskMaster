## Objective and fixed boundaries

Restore the QuickFiler folder selector's specified Windows Forms drop-down behavior while retaining the breadcrumb WebView architecture. The closed surface must show only the committed selected folder and its supplied normalized probability. One accessible drop-down button must open an `ItemViewer`-owned `ToolStripDropDown`/`ToolStripControlHost` popup that overlays sibling controls and is placed within the active monitor working area. Up, Down, Enter, Escape, mouse activation, outside close, Left, and Right must follow the state contracts in `spec.md` without in-place scrolling. Immediate and asynchronous hierarchy paths must preserve score, stable identity, selection, and issue #398 concurrency guarantees.

The following constraints are binding for every task:

- No manual bootstrap, screenshot, user-operated validation, sleep, temporary file, network, Outlook session, or external service is permitted as evidence or as an acceptance gate.
- Use MSTest, Moq at external/host boundaries, FluentAssertions, and Arrange-Act-Assert.
- Do not modify `UtilitiesCS/OutlookObjects/Folder/BreadcrumbBridgeMessages.cs` (443 baseline lines), `QuickFiler.Test/Viewers/BreadcrumbBridgeCoordinatorTests.cs` (460 baseline lines), or add hand-written behavior to `QuickFiler/Viewers/ItemViewer.Designer.cs`; use the focused files named below.
- Every implementation batch is sequential and contains at most three production `.cs` files and three test `.cs` files. Project files and the HTML asset are listed separately and do not relax that C# batch limit.
- Every new `.cs` file must be explicitly included in its legacy `.csproj`; no source or test file may exceed 500 lines.
- Do not add packages, persisted settings, schemas, browser environments, or public `IItemViewer` signature changes. Reuse the existing `CoreWebView2Environment` and `IItemViewer.SetFolderDroppedDown(bool)`.
- All evidence belongs under `docs/features/active/2026-07-21-quickfiler-folder-selector-dropdown-400/evidence/<kind>/`. Each evidence filename must end in the actual UTC execution minute formatted `yyyy-MM-ddTHH-mm`; each command artifact must contain `Timestamp:`, the exact `Command:`, numeric `EXIT_CODE:`, and a concise `Output Summary:`. Evidence may not be written under `artifacts/`.
- A baseline failure is recorded, not hidden. Post-change results must show no new diagnostics or test failures relative to the named baseline, while the absolute final coverage and clean-toolchain gates remain mandatory.
- The final C# toolchain is one uninterrupted formatting -> analyzer -> nullable -> coverage-enabled MSTest pass. If any step fails or changes a file, restart at formatting and create a fresh complete set of final-pass evidence.
- Tool commands must use the installed executable forms verified at preflight: CSharpier 1.3 uses `csharpier check <path>` and `csharpier format <path>`; every direct VSTest invocation must resolve `vstest.console.exe` in the same PowerShell process through `${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe -latest -products * -find 'Common7\IDE\Extensions\TestPlatform\vstest.console.exe'`, validate the returned absolute path, and invoke it with `& $vstest`. Bare `vstest.console.exe` and `dotnet tool run csharpier` are not executable forms in this worktree shell.
