## Design, restated from spec.md so a fresh executor needs no other document

Production change, one file, `QuickFiler/Controllers/QfcCollectionController.cs`:

- Add a lazily-initialised private key ledger holding the `(SourceId, Key)` pairs that `RegisterNavigation()` actually added. The field is named `_registeredNavigationKeys` and its accessor is named `RegisteredNavigationKeys`.
- Append to the ledger only **after** each successful `StringActionsAsync.Add(...)`, so a duplicate-key `ArgumentException` thrown by `Add` leaves the ledger unpolluted. This ordering is what preserves the existing test `RegisterNavigation_CalledTwiceWithoutInterveningUnregister_ThrowsArgumentException`.
- Record the **stored** key read back off the constructed `KaStringAsync` instance, not the pre-construction string. `KaStringAsync.Key`'s setter applies `.ToLower()` (verified at QuickFiler/Controllers/KaStringAsync.cs lines 37-41; that file is not modified by this fix and is deliberately left unbackticked so the change-footprint harvester does not read it as in scope), so reading the instance back makes the ledger exact by definition.
- Rewrite `UnregisterNavigation()` to replay the ledger and clear it, instead of looping to `_itemGroups.Count`. After this change `UnregisterNavigation` does not read `_itemGroups` at all.
- Delete the `_registeredDigits` field declaration with its `// Issue #472:` comment, its assignment inside `RegisterNavigation`, and the `var format = _registeredDigits == 2 ? "00" : "";` expression inside `UnregisterNavigation`, all in the same task. Deleting only the `format` expression leaves a private field that is assigned and never read, which the C# compiler reports as CS0414. The repository type-check gate runs `/p:TreatWarningsAsErrors=true` and promotes CS0414 to an error, and `.editorconfig` line 27's `dotnet_analyzer_diagnostic.severity = suggestion` catch-all covers analyzer rule IDs, not compiler `CSxxxx` diagnostics, so it gives no cover. The three deletions are therefore indivisible.

Supersession of #472, quoted from the spec's "Design summary" section: #472 owns the key **format**; #644 owns the key **cardinality**. A ledger replaces both because it replays recorded strings verbatim. #472's guarantee is strictly strengthened, not withdrawn. **This plan does not reopen, revert, or re-litigate #472.** Its fix, commit `9494ca35`, is already merged on this base and no task below undoes it.

Test-side changes: one new regression file carrying six tests, three arrangement-only amendments in the frozen characterisation file, one flipped assertion plus one rewritten XML-documentation paragraph in the digits file, and a comment-only correction in the #468 defects file.
