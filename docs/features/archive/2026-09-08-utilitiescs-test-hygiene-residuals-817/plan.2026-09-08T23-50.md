## Notes / Design Decisions

1. **AC source and scope.** This plan tracks and checks off the 8 checkbox items under `spec.md`'s `## Acceptance Criteria` heading only, per the `full-bug` work-mode rule in `acceptance-criteria-tracking`. `issue.md`'s own checklist items are informational context, not the AC source.
2. **No coverage-delta obligation.** This is a test-file-only structural split; it touches zero lines of production code. Per `.claude/rules/general-unit-test.md`'s "Configure coverage tooling to exclude test files" clause, test files are outside the coverage denominator entirely, independent of the COM/VSTO/WinForms exemption (which governs production code only). No coverage-percentage gate is included in this plan; the full `vstest.console.exe ... /EnableCodeCoverage` runs in Phase 0 and Phase 4 exist solely to produce a **pass-count** regression gate (spec AC6), not a coverage-threshold gate. `/EnableCodeCoverage` is VSTest's built-in binary collector (`.coverage`), which is `.gitignore`-matched (`*.coverage`, `*.coveragexml`, lines 140-141) and is therefore never committed; the durable, trackable evidence is the `.trx` logger output (`.trx` is **not** `.gitignore`-matched) plus the executor's transcription of the printed summary trailer into the named `.md` artifact.
3. **CSharpier scoping.** CLAUDE.md's literal toolchain command is `dotnet tool run csharpier format .` (repo-wide). This plan instead scopes the mutating `format` invocation to exactly this feature's 5 changed/new `.cs` files, because a repo-wide pass would rewrite any other currently-unformatted file in the repository — including a sibling-owned file from spec.md's Non-Goals list (#813/#821/#823/#824/#825/#826) if that file happens to be unformatted at present — which would breach the hard constraint against touching sibling-owned files. This mirrors documented repo practice for scope-locked CSharpier passes.
4. **Partial-keyword correction.** The current `FolderPredictorTests.cs` primary declaration reads `public class FolderPredictorTests` (no `partial`). Verified against the live precedent `StoreWrapperController_Tests.cs` (line 15: `public partial class StoreWrapperController_Tests`), a partial-class split requires **every** file — including the primary — to carry the `partial` keyword; the C# compiler rejects a merge where one part omits it (CS0260). `[P1-T5]` therefore includes inserting the `partial` keyword into the primary file's class-declaration line as the one intentional token-level edit to otherwise-untouched header content.
5. **Known trap (binding across this whole plan).** Any `/TestCaseFilter:FullyQualifiedName~<X>` used anywhere in this plan's execution MUST filter on the type name `FolderPredictorTests`, never on a new file-name fragment (`SuggestionsAndRecents`, `FolderLookupAndUiSeams`, `CreateFolderWorkflows`, `TestSupport`). A file-name filter silently matches zero tests and exits `0` with "No test matches," which would mask a broken split (confirmed prior incident, issue #498). No task in this plan actually issues such a filter — post-split verification uses `/ListTests` plus text-post-filtering exclusively — but this note is binding if any deviation is ever proposed during execution.
6. **Local environmental note (informational, not a gate).** Two test classes elsewhere in `UtilitiesCS.Test` (`ShellUtilitiesStatic_Tests`, `ShellUtilities_Tests`, confirmed present in this worktree) have been reported to stall `vstest` on some local machines running the full assembly. This is unrelated to `FolderPredictorTests` and unverified in this specific worktree. If a full-suite run in `[P0-T16]` or `[P4-T7]` appears to hang, the executor may add `/Blame:CollectHangDump;TestHangTimeout=15minutes` to that one command and record the addition in its evidence artifact; this does not change the command's required `/EnableCodeCoverage` scope or its pass-count acceptance.
7. **Coverage-threshold documents disagree (80/90 in CLAUDE.md and `.claude/rules/csharp.md` vs 85/75 in `.claude/rules/general-unit-test.md` and `.claude/rules/quality-tiers.md`).** This plan takes no position on that conflict because Note 2 makes it inapplicable here — no coverage percentage is gated by any task in this plan.
