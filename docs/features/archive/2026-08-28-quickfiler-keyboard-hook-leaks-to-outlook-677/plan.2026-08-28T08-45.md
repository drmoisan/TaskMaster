- **D1 — Bugfix Workflow order is binding.** Failing regression tests are authored first (Phase 1), the minimal fix follows (Phases 2–3), full local verification last (Phases 4–5). No `KeyboardHandler` change anywhere in this plan (spec Scope & Non-Goals).
- **D2 — Expect-fail convention for this fix is compile-red plus dossier.** The guard surface (the internal `MayTakeFocus` property on `BreadcrumbDropDownHost`, `IQfcFormViewer.FormDeactivated`/`IsWebView2Focused`/`ParkFocusOffWebView2`, `IItemViewer.CancelBreadcrumbSelector`, `IQfcItemController.CancelBreadcrumbSelector`) does not exist at baseline, so a runtime failing test run is structurally impossible: the regression tests cannot compile, let alone load. For the compile-red to be real, the new test code must reference that surface with compile-time (typed) references — the Part3 harness constructs the concrete `BreadcrumbDropDownHost` directly and assigns the property in typed code, never through reflection (D14). The `[expect-fail]` evidence is therefore a solution build that fails with the specific missing-member compiler errors located in the new test files (proving the guard is genuinely absent today), recorded with `ExpectedExitCode: 1`, plus a `fail-before-exception.<timestamp>.md` dossier in `EVID/regression-testing/` with `WhyFailingRunImpossible:` per `.claude/skills/evidence-and-timestamp-conventions/SKILL.md`.
- **D3 — Property seam, NOT constructor threading.** `BreadcrumbDropDownHost` (`QuickFiler/Viewers/BreadcrumbDropDownHost.cs`, 463 lines at baseline, `#nullable enable`) has a six-constructor chain (lines 37, 57, 79, 101, 121, 143). **No constructor signature changes.** The focus-permission predicate is injected through an internal settable auto-property with a safe default: `internal Func<bool> MayTakeFocus { get; set; } = () => true;` (accessible to tests via `[assembly: InternalsVisibleTo("QuickFiler.Test")]`, `QuickFiler/Properties/AssemblyInfo.cs:5`). Rationale — the previously considered optional-trailing constructor parameter is REJECTED because five existing tests bind to the constructor set by reflection with arity/shape matching and would break: `BreadcrumbDropDownHostTests.cs:426-443` and `BreadcrumbDropDownHostTests.Part2.cs` (`constructor.Invoke(new object[7])` → `TargetParameterCountException` at 8-arity), `BreadcrumbDropDownLifecycleTests.cs:169-188` (same `new object[7]` invoke), `BreadcrumbDropDownReadinessTests.cs:263-289` (exact-signature `GetConstructor` with a `Type[7]` returns null at 8-arity), `BreadcrumbDropDownLifecycleCoverageTests.cs:117-152` (`HaveCount(4)` over arity-matched ctors fails), and `BreadcrumbDropDownLifecycleCoverageTests.cs:236-254` (`.Single(GetParameters().Length == 9)` throws when two ctors become 9-arity, and its per-parameter null-check loop rejects the legally-nullable new parameter). The property seam leaves every constructor at its baseline arity, so all reflection-bound harnesses continue to bind, and spec AC-7 ("All existing `BreadcrumbDropDownHost` and breadcrumb pipeline tests pass without modification", `spec.md:171`) holds literally — no existing test method is modified anywhere in this plan; the only edit to an existing test file is the P3-T7 interface-completion member on the manual fake `FakeQfcItemController`, enumerated as a sanctioned structural-enabler exception in P4-T3 and P6-T4.
- **D4 — Execution-time evaluation sites.** The predicate is consulted at execution time only, in exactly three places: (a) `FinishClose` passes a new private wrapper `FocusAnchorIfPermitted` (which checks `MayTakeFocus()` then calls `_focusAnchor`) to `CompleteAll` instead of the raw `_focusAnchor` field — the `_cancelSelection()` step in `FinishClose` is NOT gated, only the focus step; (b) the existing internal `FocusPending()` method body becomes `if (MayTakeFocus()) _focusPending();`, which guards the fresh-open focus step in `BreadcrumbDropDownOpenLifetime.Focus.cs:40` (`_host.FocusPending()`) with no edit to that file; (c) `BreadcrumbDropDownHost.Open.cs:67` changes `_openLifetime.Schedule(_focusPending)` to `_openLifetime.Schedule(FocusPending)` so the already-open refocus is also guarded at execution time. Because the property is read (invoked) inside each guard body at the moment the scheduled action runs, a caller reassigning `MayTakeFocus` after scheduling is honored — this satisfies the spec Risks item "predicate evaluated at the wrong time" and AC-5.
