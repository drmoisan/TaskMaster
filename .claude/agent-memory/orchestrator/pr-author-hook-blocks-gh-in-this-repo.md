**CURRENT (verified 2026-07-07, issue #254 / PR #258):** Autonomous PR creation works. Two facts to combine:

1. **`Agent(pr-author)` type is NOT in this session's agent set.** A spawn returns `Agent type 'pr-author' not found`. Do not burn a delegation attempt expecting it. Instead run the `pr-author` skill contract yourself from the main thread: write `artifacts/pr_body_<N>.md`, compute the lowercase-hex SHA-256 of the body bytes, write `artifacts/pr_body_<N>.receipt.json` `{skill, pr_body_path, number:<N>, sha256, context_summary_path, created_at}` with `created_at` strictly NEWER than `artifacts/pr_context.summary.txt` last-write, then `gh pr create --base main --head <branch> --body-file artifacts/pr_body_<N>.md`. `<N>` = the issue number (filename N and receipt.number must agree). Record a `pr_author_receipt` in the checkpoint noting in-thread execution.

2. **The `enforce-pr-author-skill.ps1` hook permits that gh pr create** once (a) the orchestrator-state checkpoint passes `--require-pr-creation-ready` and (b) the canonical body-file + verified receipt pair exists. The preflight has a portable PowerShell fallback (`Invoke-OrchestratorStatePreflight` in `.claude/lib/orchestrator-state/OrchestratorState.psm1`) that does NOT need the absent python `scripts.dev_tools`. Run it yourself before delegating/creating: `Import-Module ./.claude/lib/orchestrator-state/OrchestratorState.psm1 -Force; Invoke-OrchestratorStatePreflight -CheckpointPath artifacts/orchestration/orchestrator-state.json` → HasErrors=False means ready.

**Why:** the `.claude` bundle was pushed down from a reference repo with python tooling this repo lacks; the portable fallback closed the old hard block, and the pr-author work simply happens in-thread since the subagent isn't registered here.

**How to apply:** at the PR gate, refresh `collect_pr_context`, run the readiness preflight, author body+receipt in-thread, then `gh pr create --body-file`. `gh` IS installed and authed here (verify with `gh auth status`) despite `pr_context.summary.txt` printing "GitHub CLI unavailable" and "Core logic changes: 0 files" — both are known-false summary lines; author the body from the real diff. See [[pr-context-summary-unreliable-gh-and-classification]].

**Checkpoint schema (verified this session):** required top-level keys use hyphenated names: `relativeFile`, `long-name`, `issue-num`, `work-mode`, `plan-path` (plus `objective`, `change_budget_estimate`, `path_selected`, `promotion-type`, `short-name`, `feature-folder`, `completed_steps`, `next_step`, `last_updated`, `step5_status`..`step10_status`, `delegation_receipts`, `blocked_reason`). Full step-status enum is `{not-applicable, pending, delegated, verified, blocked, not_started, in_progress, completed}` — `completed` is valid (`complete` is NOT). `blocked_reason` must be in `{none, spawn_agent_unavailable, delegation_launch_failed, delegate_no_receipt, delegate_contract_incomplete, validator_failed, user_requested_stop}`. `delegation_receipts` must be an ARRAY; each entry needs `{step, agent_name, agent_id, skill_source, started_at, completed_at, result_signal, artifact_paths}`. Store raw promotion MCP payloads in a sibling key (not inside delegation_receipts). PR-creation readiness requires step5-step8 non-pending/non-blocked, `blocked_reason=none`, and empty/absent `local_execution_overrides`/`delegation_bypasses`. See [[orchestrator-state-validator-divergence]].
