Seams found by preflight review of the #440 plan (delete one conjunct from `LeftArrow()` in `UtilitiesCS/OutlookObjects/Folder/BreadcrumbStateModel.cs`, correct two tests).

**Why:** eight of the seventeen findings were blocking, and each is a gate that could not fail rather than a gate that would fail wrongly. They recur on any change whose whole production delta is a deletion plus a comment rewrite.

**How to apply:**

- **A deletion-only change makes a diff-derived changed-line coverage gate collect nothing.** The removed line has no post-change number and a rewritten comment is never emitted as a Cobertura `line` element, so the derived set is empty and the gate returns the same result whatever the executor does. Derive the set from the enclosing method's post-change line span instead, and carry an explicit non-emptiness floor. Derive the floor conservatively from statements certain to be instrumented, not from the full observed sequence-point count, so an instrumenter that merges a multi-line `if` condition does not fail the gate for a measurement reason.
- **`git add -A` earlier in the same task voids a later "no untracked entry" assertion.** Staging converts every untracked entry into a staged one. Assert on the two-character porcelain status field (`M `, ` M`, `MM` permitted; anything starting `A`, `?`, `R` fails) rather than on the absence of untracked markers.
- **`--name-only` and `--porcelain` emit no hunks.** A task that must observe "this retained line appears as context, not as a deletion" needs a third, content-level `git diff <BASE> -- <one path>` span.
- **An msbuild non-vacuity assertion needs a log and a positive half.** Add `/v:normal /fl "/flp:LogFile=coverage\logs\<name>.txt;Verbosity=normal"` (create the directory first; the log embeds absolute host paths, so it must stay under gitignored `coverage/`). Assert zero occurrences of `Skipping target "CoreCompile"` *and* at least one of `(Rebuild target(s))`; the zero-count alone also passes when the log is empty or was never written. **The `(s)` is load-bearing.** Measured against `docs/features/active/2026-08-28-quickfiler-keyboard-hook-leaks-to-outlook-677/evidence/regression-testing/p1-t5-expectfail-build.msbuild.txt`: `(Rebuild target(s))` appears from line 4 in the ProjectStarted and `Done Building Project` messages, which normal verbosity emits on every run; the shorter `(Rebuild target)` appears only from line 11329, inside the terminal warning/error summary block that MSBuild emits only when the build produced diagnostics. An at-least-1 gate on the short form therefore fails precisely when the build is clean. Do not write that MSBuild never emits the short form — it does, 40 lines' worth in that log; the defect is where it is emitted, not whether.
- **`.csharpierignore` matches a filename SUFFIX, not a directory.** It carries `*.cobertura.xml`, `*.trx`, `*.coverage`, `*.coveragexml`, `**/evidence/**` — and no `coverage/` entry. `coverage\coverage.cobertura.baseline440.xml` does NOT end in `.cobertura.xml`, so `csharpier check .` reads it, raises the checked-file count above the baseline, and reports raw Cobertura as needing reformatting. Name every coverage document `<name>.cobertura.xml`. This breaks both branches of a count-equality/pre-existing-drift formatting gate at once.
- **A pathspec-scoped gate cannot decide an out-of-root absence.** Gates scoped `-- UtilitiesCS UtilitiesCS.Test` return the same result whatever the executor does when the AC asserts that a QuickFiler path is absent from the diff. Add one repo-wide span: `git diff --name-only <BASE> -- . ":(exclude)docs" ":(exclude).claude"` plus a `git status --porcelain -- <out-of-root dirs>` companion for the untracked blind spot. Use `git diff` not `git status` for the wide span — but justify it with the two TRUE reasons: the diff shares a command shape with the scoped span so the two file lists are comparable, and an anchored diff stays discriminating after the commit while porcelain status goes empty. **Do NOT justify it by claiming `.dotnet-sdk` is not gitignored.** That claim entered the round-2 delta unchecked and was falsified in round 3: `git check-ignore -v .dotnet-sdk/dotnet.exe` returns `.gitignore:350:.dotnet*/`. Verified `.gitignore` line numbers in this repo: 26 `[Bb]in/`, 27 `[Oo]bj/`, 191 `**/[Pp]ackages/*`, 350 `.dotnet*/`.
- **Adding a span to a task invalidates every downstream "the P<n>-T<m> diff" citation.** Once a task holds five spans, "the diff file list" and "the porcelain output" are ambiguous. Renumber every Phase 5 check-off to name which span supplies which half of its evidence.
- **`Invoke-Restore.ps1` IS the repo-standard restore, and it runs `msbuild /t:Restore`** with `/p:RestorePackagesConfig=true` (line 36), which is what makes it handle this repo's all-packages.config projects. Do not write "msbuild /t:Restore must not be used"; the property, not the target, is the point.
- **The wrapper's threshold throw leaves the RAW Cobertura on disk.** In `scripts/vscode/Invoke-MSTestWithCoverage.ps1`, line 340 computes the processed content, 341 asserts, 343 writes back. On the throwing branch `class/@filename` is absolute and duplicate classes are unmerged, so a relative-path lookup matches nothing. Re-apply `ConvertTo-KoverageCoberturaXml -XmlContent <raw> -RepoRoot <root>` in memory; it returns a **string**, so cast to `[xml]` before reading.
- **vswhere forms:** msbuild `-latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe'`; vstest `-latest -products * -find 'Common7\IDE\Extensions\TestPlatform\vstest.console.exe'`. `-products *` is load-bearing on a Build-Tools-only install.
- **`FullyQualifiedName~BreadcrumbBridgeRouterTests` does not reach infixed siblings** `BreadcrumbBridgeRouterQueueTests`, `BreadcrumbBridgeRouterIssue439Tests`, `BreadcrumbBridgeRouterIssue614Tests`. A "full suite" AC needs each name as its own alternate.
- **A file-size ceiling equal to the baseline needs a comment budget.** 248-line file, one line deleted, a 4-line comment rewritten: the budget is 5 comment lines. State it in the rewrite task, and state the arithmetic in the ceiling task.
- **A corrected test must appear in a named-outcome list.** Verifying that an old comment literal disappeared does not establish that the rewritten test asserts the new contract or that it passes.
- **A version-agnostic analyzer glob cannot see the failure mode that is actually present.** `Meziantou.Analyzer.*` / `Roslynator.Analyzers.*` presence checks pass on a fresh worktree while the build is broken, because the skew is a VERSION prefix mismatch, not an absent package. Gate on the resolved `Analyzer Include` file paths instead: derive the set from `git ls-files "*.csproj"`, count how many resolved paths do not exist, provision, and require the after-count to be 0. Pair it with `git status --porcelain -- "*.csproj" "*packages.config"` requiring empty output, which is what proves the fix touched no tracked file. Provisioning target is gitignored (`.gitignore:191`), so it is invisible to every diff/status gate.
- **Put the analyzer provisioning INSIDE the existing restore task, before the csharpier baseline.** A new later task would put files under `packages/` between the `csharpier check .` baseline and the final `csharpier check .`, breaking a count-equality formatting gate. Keeping it in the restore task means both counts are taken after it. Confirm the claim by checking that no other task writes there: no msbuild invocation in the plan names the Restore target, and `Invoke-MSTestWithCoverage.ps1` contains no restore and no build step (grep for `Restore|/t:|msbuild` returns nothing).
- **Three consecutive rounds each introduced a fresh defect via the prose written to fix the previous one** (round 1 a log literal, round 2 a `.gitignore` fact, and defect 1's replacement is the plan's largest prose block). On a revision round, verify every factual claim in the replacement text against the tree before writing it, not only the claim the defect names.
- **Round 4: cite an AC by SENTENCE, and read the sentence before naming it.** The round-3 replacement prose attributed a branch-coverage requirement to AC-15's *second* sentence. AC-15 is two sentences and the second names an evidence location only; the branch requirement is in the first. The claim was false, sat inside an acceptance clause, and so would have been transcribed into the evidence artifact and read by the AC-15 check-off. Whenever plan prose says "the AC's Nth sentence requires X", open the AC and count the sentences. This is the same defect class as round 3's justification defect: a plausible attribution asserted without reading the target.
- **An MSBuild `Include` resolves against the DECLARING PROJECT's directory, not the repository root.** Saying "the leading relative segment is resolved against the repository root" reads literally as resolving `..\packages\...` to the repository's *parent*. Verified in this repo: all 162 `<Analyzer Include="` values across 17 project files begin with `..\packages\`, and all 18 solution projects sit exactly one directory below the repository root, so each resolves to the repository-root packages directory. Write the resolution base as the project file's own directory and state the one-level-below fact that makes the result land at the root. The misreading fails closed rather than false-passing, but it costs an execution attempt.
