Seams from applying the coordinator ruling AC15 option (a) to plan 956 (worktree agent-a6974b35cca57abb8) after P4-T8 stopped `AC15: NOT MET` (adjusted delta 2, raw 3).

**Rethrow-following braces are a predictable uncovered class.** When an item removes `[ExcludeFromCodeCoverage]` from a method (here the five-argument `TrySaveAttachmentAsync` core) whose `else { throw; }` arm and enclosing `catch (System.UnauthorizedAccessException e) { ... }` block end in a rethrow, dotnet-coverage maps the closing brace after `throw;` and the catch block's own closing brace as lines with hits=0; no path reaches them and the AC that pins the rethrows (TOKENS A15) forbids restructuring. A Level-1 "final uncovered minus baseline at most 0" gate therefore fails on structure. Plan the exemption up-front whenever a newly measured member contains a `throw;` immediately before a `}`; the outer `catch (System.Exception) { throw; }` brace was NOT uncovered here (only the nested arm's two braces were), so predict from the diagnostic line map, not from the brace count.

**Content-identified exemption rules (never line numbers).** Else-brace: trimmed line i is `}`, i-1 `throw;`, i-2 `{`, i-3 `else`. Catch-brace: trimmed i is `}`, i-1 is an else-brace line, trimmed i+1 starts with `catch (System.Exception)`, and the nearest preceding line AT THE SAME INDENTATION WIDTH whose trimmed text starts with `catch (` equals `catch (System.UnauthorizedAccessException e)`. The caller's literal rule ("nearest preceding `catch (` line") was false against the tree: the nearest such line to L155 is the inner boundary L125 `catch (System.Exception inner)` (indent 20), not L101 (indent 12). Read the source before writing any "nearest preceding header" rule and key it to the brace's indent (same seam as [[project-947-passA-second-call-site-consolidation-seams]]). Print each set separately (`EXEMPT-LAMBDA-*`, `EXEMPT-ELSE-BRACE-*`, `EXEMPT-CATCH-BRACE-*`) plus the sorted union so the existing `EXEMPT-LINES`/`EXEMPT-UNCOVERED` consumers keep their meaning.

**In-memory negative control over `$maps`.** Pick the lowest-numbered `Hits -gt 0` key of the file's LineMap not in the exempt union (`CONTROL-LINE`), recount every final-stage LineMap counting `Hits -eq 0` OR (that file AND that line), recompute adjusted delta = recount - exemptUncovered - baseline; `CoveredLines` in `Get-CoberturaClassLineSummary` is exactly the `Hits -gt 0` count, so CONTROL-DELTA = adjusted + 1 by construction, and CONTROL-RAW-DELTA = raw + 1. Both verdicts FAIL only when the observed deltas sit at their bounds (0 and 3); a PASS verdict means the gate is not discriminating and is a named stop, so do not add this control shape to a gate whose observed value sits strictly below its bound.

**Re-run bookkeeping.** A re-run of one stopped task is not a Phase 4 loop restart: keep `ITERATION: 1` and add `RERUN: revision 1.2, coordinator ruling ...`; require the artifact to keep the prior stop record under `## Prior run (stopped, superseded by ...)` and quote the ruling verbatim under its own heading (the verbatim text lives in the PD so the executor copies rather than paraphrases). The planner amends the spec AC on ONE line (no sibling shift: P4-T28's 3-line grep, P4-T32's lines 290-296 and P0-T2's two literals all survive) and records in the Revision Log that the planner, not the executor, made the amendment so the run's Write Set clause stays true.

**How to apply:** when a C# item lifts a coverage exclusion from a method with rethrows, pre-author the two brace exemptions by construct and the matching bounds; when a ruling hands you a "nearest preceding X" rule, verify it against the actual file and key it to indentation; when a controlled gate re-runs after a stop, preserve the stop record and keep the ITERATION counter truthful.
