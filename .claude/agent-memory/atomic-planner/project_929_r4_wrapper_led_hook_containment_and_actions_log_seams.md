Seams from applying the executor's round-4 preflight deltas to plan 929 (worktree agent-a74dcedbc13b789fd, HEAD 3091b8af9) on 2026-09-30, no Bash in the planner session.

**The pr-author hook's wrapper-led containment rule.** `.claude/hooks/enforce-pr-author-skill-helpers.ps1` line 279 calls `Test-CommandLineInvocation -CommandWord gh -SubcommandPath pr,create`. That is structural for a plain segment, but `hook-command-invocation.ps1` lines 202 to 203 route a wrapper-led or live-substitution segment (any `pwsh -Command '...'`) to `Test-CommandLineRawContainment` (lines 92 to 116): ordinal case-insensitive `IndexOf` of `gh`, then each subcommand element, in any arrangement. A payload with `gh run list ... --json ...,createdAt ... Sort-Object -Property databaseId` therefore reads as `gh pr create` with no `--body-file` and is refused (PR_AUTHOR_SKILL_BLOCKED, case B). Rule for plans: no pwsh payload that reaches gh may contain the sequence `create` anywhere (prose in the plan is fine; only the issued command string is scanned). `pr` is nearly unavoidable (`-Property`, `ProjectConsistency`, `prefix`), so assume it is present.

**Actions log colouring.** In `gh run view --job <id> --log`, Pester's "Tests Passed: N, Failed: N, Skipped: N" line has each segment wrapped in SGR escapes, so a regex over the raw line matches nothing. Strip first: `$esc = [string][char]27; ... | ForEach-Object { $_ -replace ($esc + "[[][0-9;]*m"), "" }`. The class `[[]` avoids a backslash crossing the Bash boundary. The workflow's own `echo "PESTER Passed=..."` lines are plain.

**gh run download folder collision.** A second `gh run download --dir <same>` exits 1 with "The file exists." (absolute path in the error). Shape: `<DIR>` = `coverage/ci-<role>-pester-<RUN-ID>-<n>` with `<n>` per invocation against that run, and print `"DIR-PREEXISTS=" + (Test-Path -LiteralPath "<DIR>")` immediately before the download, asserting False.

**cancel-in-progress and re-listing.** `ci.yml` lines 13 to 15 key the concurrency group on the ref with cancel-in-progress true, so a second dispatch or a PR event on the same ref cancels the run a plan just selected. Split the locate step into LIST (once, then re-run until RUNS-FOR-HEAD is at least 1), DISPATCH (exactly once per pushed head, only when the count is 0, never on a re-run) and WATCH (re-invoked unchanged on tool timeout), and on `conclusion=cancelled` re-list and select the greatest databaseId rather than treating it as a test outcome. A pull_request-event run for the same head satisfies the count.

**PoshQC test route writes three XML files.** `artifacts/pester/pester-junit.xml`, `powershell-coverage.xml` and `powershell-coverage.koverage.xml` (JaCoCo-shaped, report root). Any XML-candidate census under artifacts/ must count all three.

**Bash starts in the session checkout.** `dotnet tool run csharpier check .`, `dotnet tool restore` and bare `msbuild TaskMaster.sln` issued outside `pwsh -Command 'Set-Location "<root>"; ...'` run against the session checkout's own sln and global.json. Wrap each and print `<TOOL>_EXIT=$LASTEXITCODE`; read msbuild counts from the `/flp:` log with `Select-String -LiteralPath ... -SimpleMatch -Pattern ("/out:obj" + [char]92 + "Debug" + [char]92)` (OUT_LINES) and `"CS0006"` (CS0006_LINES). `coverage/.gitkeep` is tracked, so the log directory exists on a fresh checkout. Git outside pwsh is `git -C <root> ...`.

**Failure-message gates need the -Because literal fixed by the authoring task.** A fail-before task that expects a JUnit failure message to "name app-id or a missing client-id line" cannot be judged unless the test-authoring task fixes the `-Because` text (or the exact string format of a collected finding). Pester's `Should -Be` message does carry expected and actual, so version-pair expectations survive without -Because.

**How to apply:** for any TaskMaster plan whose pwsh payloads reach gh, scan every payload for `create` (and `--body`) before handoff; strip SGR escapes before matching CI logs; number download folders per invocation; model cancel-in-progress; count three PoshQC XML files; wrap every dotnet and msbuild command in Set-Location.
