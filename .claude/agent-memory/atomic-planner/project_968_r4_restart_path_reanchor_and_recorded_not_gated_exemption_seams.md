Three seams from the #968 round-4 reviewer report (2026-10-03), plus the session constraint.

1. **A restart rule that sends execution back to a pre-commit census task after the implementation commit changes the meaning of every HEAD-anchored gate in that task.** D-13 sent a Phase 8 failure back to P6-T1; P6-T2 re-ran `git diff --numstat HEAD` and `git diff HEAD` (expecting `1	129` and `3	0`) and a porcelain set with three `??` lines, all of which print nothing or ` M` once the P6-T9 commit is in HEAD. Fix shape (reviewer delta, applied verbatim in the restart rule, not in the task): on that restart the task runs each HEAD-anchored command with BASE as the ref operand, and the porcelain expectation becomes a membership condition (every line under the code roots names a Write Set path with status ` M`), recorded under a distinct label (`P6-RESTART-PORCELAIN:`). Sweep method: Grep the plan for `diff --numstat HEAD|diff HEAD|`?? ` and decide per hit whether any restart loop reaches it after a commit; BASE-anchored macros (CMD-HUNKS, CMD-ADDED-SCAN) and porcelain negatives ("no path under X") survive a commit and need nothing. Also name the rule for a nested restart (a Phase 6 restart that follows the Phase 8 restart) so "on that restart" is not read narrowly.
2. **"Every token, span, hunk and numstat value holds as last recorded" (the round-3 fix) over-reaches: it demands values an earlier task explicitly records without gating** (`HUNK_COUNT:` "recorded, not gated", printed `SPAN:` ranges), which CSharpier may move when `REWRITTEN:` is non-empty. Put every recorded-not-gated value inside the same exemption clause as LINES ("may differ ... only if `REWRITTEN:` named the file"). Sweep method: Grep `recorded, not gated|not gated|\(recorded\)`, then read each consumer of that value.
3. **Classification stop-rules must enumerate directive lines too.** After round 3 added the method-group category, the `#region Linked List Locking` / `#endregion` hits (returned by the `Linked List Locking` alternation of the primary pattern) still fit no category and would force `INVOCATION`. Rule of thumb: for every alternation in the census pattern, list the hit shapes it returns (identifier use, declaration, comment, doc prose, cref, nameof, method group, string literal, directive) and give each a category before writing "any other category is INVOCATION: stop".

Session constraint: with no Bash tool the planner cannot run the plan's pwsh census payload; reproduce each strategy with the Grep tool (same regex, `**/*.cs` glob rooted at the item worktree, narrower glob for the per-directory strategy) and record it as a Grep reproduction, not as the payload's output.

**Why:** 1 and 3 would have been run stops on a correct execution (an unsatisfiable restart gate; a forced `INVOCATION`); 2 would have failed P6-T2 whenever CSharpier re-laid a delivered file, which the Risks section says to expect.

**How to apply:** Whenever a plan has a mid-plan commit and any restart loop, read every git gate downstream of the restart entry point against the post-commit HEAD. Whenever a post-format census says "as last recorded", enumerate which recorded values are gated and exempt the rest.
