Seams found while applying the round-8 preflight deltas to plan 927 (evidence and identity hygiene sweep). All three were MEASURED by the executor through its command channel; the planner has no channel and accepted them.

**Process working directory (R-01).** The Bash tool starts pwsh with its process directory at the SESSION root. `Set-Location <worktree>` moves only the PowerShell location; `[System.IO.File]::ReadAllBytes("relative/path")`, `ReadAllText`, `WriteAllText` and `[System.IO.Directory]` resolve against the process directory and silently read or rewrite the session checkout's copy. Fix adopted: every pwsh payload begins `Set-Location -LiteralPath <worktree-root>; [System.IO.Directory]::SetCurrentDirectory((Get-Location).Path);` (executor substitutes the root at run time, records `<repo-root>`), and any helper script written to SCRATCH joins every repository-relative path to `(Get-Location).Path` before a .NET read or write. PowerShell cmdlets (`Get-Content`, `Get-FileHash -LiteralPath`, `Test-Path`, `Get-ChildItem`) follow the PowerShell location and are unaffected.

**Doubled-backslash collapse (R-02).** Git-Bash argument conversion collapses `\\` to `\` before pwsh runs, even inside single quotes. For `git grep -E` this is harmless (a POSIX bracket keeps the surviving backslash literal), which is why gate counts matched while a `.NET` census of the same pattern returned 0 instead of 1. For `Select-String -Pattern`, `-match`, `-replace` and `[regex]`, a class written `[\\/]` reaches .NET as `[\/]` and matches only a forward slash. Fix: `$b = [char]92; "[" + $b + $b + "/]"`. A guard that reads its pattern from a file is unaffected, so a plan that mixes the two forms produces an arithmetic mismatch between the pwsh census and the guard (here 1,213 versus 1,214) that stops the run.

**Line counts.** The Read tool's last line number is one higher than `Get-Content` / ripgrep for a file that ends in a newline; five citations (222/82/494/104/35) were off by one. Count with `Grep pattern "^" output_mode count` when a plan states a line total or a "500-line" headroom figure. The Glob tool does not enumerate paths under a `.claude/worktrees/` item worktree; use Grep with `files_with_matches` or `count` instead.

**Other round-9 lessons.** (1) A stop-and-request batch design must let ANY PowerShell write of the batch be denied (the session counter is shared with sibling items that can take a slot after the reset), not only the first. (2) Name a stop for every branch a task text describes ("reported as a stop of the batch-4 class" is not a stop token). (3) A hook's caps can also be raised through fields in its state file; read the header for every override route. (4) An observe-only formatter that saves its computed text to SCRATCH must use a non-PowerShell extension (`.txt`) so the payload writes no `.ps1` anywhere. (5) `Invoke-Formatter` under default settings is a substitution for the PoshQC MCP formatter (which bundles its own settings), so an AC worded "the PoshQC format pass makes no change" is read as a recorded substitution, not an equivalence. (6) A merge of origin/main after Phase 0 can add sibling-item evidence (two `.jacoco.xml` projections under an already-merged sibling folder) that shifts a retained-projection count; re-derive every census figure the merge could touch, and mark a figure that changed because of a measurement defect as `MEASUREMENT-CORRECTION:` rather than a post-merge delta.

**How to apply:** in any plan whose payloads run through the Bash tool in a multi-worktree session, (a) put the SetCurrentDirectory prefix in the conventions block and point every `[System.IO.*]` relative-path payload at it; (b) sweep every `-Pattern`, `-match`, `-replace`, `[regex]` operand for `\\` and rewrite with `[char]92`; leave `git grep -E` operands alone; (c) re-derive line totals with ripgrep, not the Read tool.
