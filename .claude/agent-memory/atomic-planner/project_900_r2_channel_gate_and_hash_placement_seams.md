Round 2 revision (2026-09-17) of `plan.2026-09-16T23-27.md` for #900; three blocking, seven non-blocking. Pairs with [[project_900_dedicated_thread_mutation_placement_seams]].

**1. `pwsh -File` is not a fallback from a worktree-isolation refusal of `pwsh -Command`.** The reviewer ran both in the assigned worktree and got byte-identical refusal text: the isolation guard keys on `pwsh` occupying the command-name position, not on the switch. A "two-rung probe" that treats `-File` as rung 2 stops nothing. **How to apply:** make the probe a Phase 0 task (here P0-T4) that tries every declared rung with a trivial `Write-Output "PROBE-OK"` payload, records `CHANNEL: COMMAND|FILE|UNAVAILABLE`, and STOPS at that task on `UNAVAILABLE`; put a header bullet stating the executor session must be non-isolated or granted a pwsh surface and that the orchestrator launches accordingly. Do not invent an unprobed third rung in a planning-only revision.

**2. `git commit -F <file>` is denied by the pre-implementation gate even for exempt paths.** `.claude/hooks/enforce-orchestration-preimplementation-gate-helpers.ps1` models only `-m`, `--message`, `--message=`, `-m<value>` (lines 260-272); every other dash option returns false (273); `$`, backtick, `<`, `>` anywhere on the line deny (33, 327-329); at least one pathspec operand is required (283-285); exempt trees are `docs/features/{epics,parallel,active,potential}/` and `artifacts/orchestration/` (22-28). A docs-only commit therefore must be `git commit -m "<subject>" -- docs/features/active/<folder>`, single segment. Commits staging `QuickFiler.Test/...` can never be exempt and depend on `artifacts/orchestration/orchestrator-state.json` carrying `issue-num`, `feature-folder` (starts `docs/features/active/`), `route_id` or `path_selected`, and `lifecycle_ready: true` (`Test-OrchestrationReady`, gate lines 223-251). **How to apply:** a read-only Phase 0 task records those four keys and stops with `PRE-IMPLEMENTATION GATE NOT SEEDED`; every `.cs` edit task and every non-exempt commit task carries a `PRE-IMPLEMENTATION GATE BLOCKED` stop-and-report sentence; the executor never seeds or edits the checkpoint.

**3. Hash spans need pwsh, so they cannot live in a task that must complete before the channel probe.** Naming `Get-FileHash -Algorithm SHA256 -LiteralPath` (N-5) in P0-T3 would have made P0-T3 command-bearing ahead of P0-T4's probe. Moved both anchors (`RUNSETTINGS-HASH:`, `PRE-EDIT-HASH:`) into P0-T4 part 2 and re-pointed the four consumers (D-10, P1-T1, P4-T2, P5-T9). **How to apply:** any task that owns a stop branch reachable without a channel (branch mismatch, dirty write set, gate not seeded) must use only `git` and the Read/Grep tools.

**4. Gates that cannot fail, found this round.** (a) "no `ASSEMBLY:` line contains `\.claude\worktrees\`" over worktree-relative output — the root is trimmed, so the segment can never appear; replaced with "begins with `\` and contains `\bin\Debug\`". (b) `origin/main...HEAD` vs `MERGE-BASE..HEAD` — identical by definition; replaced with `origin/main..HEAD` vs `origin/main...HEAD`, disagreement meaning origin/main advanced. (c) A "required" value that also routes a named alternative branch (class count 0 vs `MEASURED`) is self-contradictory; state it as a recorded observation that selects a branch.

**5. `.csharpierignore` does not cover `artifacts/csharp/coverage.xml`** (only `**/evidence/**`, `*.cobertura.xml`, `*.coverage`, `*.coveragexml`, `*.trx`, `*.csproj`, `*.props`, `*.targets`), and CSharpier 1.2.6 formats `*.xml`. Copy the review input in the loop-closure task only after `LOOP: CLEAN PASS`, never inside the format→test loop.

**6. Post-fix file at 490/500.** When a file lands near the ceiling and the remarks carry pinned census tokens, add "`FILE SIZE LIMIT EXCEEDED`: stop, do not shorten remarks" rather than letting the executor trim prose that the counts depend on.
