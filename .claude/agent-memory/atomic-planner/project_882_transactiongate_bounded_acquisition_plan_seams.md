**How to apply:** re-check before planning any QuickFiler.Test fixture change, any single-assembly coverage evidence route, or any plan whose spec declares a "verified absent from the repository" literal.

1. **A spec that declares a greppable token pre-falsifies its own repo-wide absence claim.** spec.md line 125 says `TRANSACTIONGATE_ACQUIRE_TIMEOUT` occurs nowhere in the repository; the Grep tool found it in spec.md itself (and the plan quotes it too). Scope the absence half to the source directory (count of `*.cs` files under QuickFiler.Test containing it: 0 before, fixture file at least 1 after) and say so in a decision.
2. **Analyzer HintPath skew is present again (re-derived 2026-09-28).** Every first-party csproj `<Analyzer Include>` names `Meziantou.Analyzer.3.0.235` (QuickFiler.Test.csproj:554) and QuickFiler.Test also names `MSTest.Analyzers.4.4.0` (:529-530), while packages.config pins 3.0.290 (:11) and 4.4.1 (:43). Restore installs only the pins, so a fresh worktree compiles to CS0006. Both referenced folders exist in the primary checkout's `packages/` (three directories above an agent worktree root), so the back-fill is a recursive copy via `Join-Path (Get-Location) "../../../packages/FOLDER"`, version-agnostic (enumerate items, resolve against the declaring project's directory, copy what is missing), never a csproj edit.
3. **The committed-evidence projections have first-class tooling but the runner emits them only after its thresholds.** `Invoke-MSTestWithCoverage.ps1` writes the JaCoCo projection (`:393-401`) and the trx summary (`:408-432`) AFTER `Assert-CoberturaLineCoverageThreshold` / `Assert-CoberturaBranchCoverageThreshold` (`:386-387`), which throw on a sub-floor document-level rate. A QuickFiler.Test-only run therefore may produce neither. Compose them yourself: dot-source the runner (entry guard `:437`), Helpers.ps1 and `Invoke-MSTest.TrxSummary.ps1`; call `Get-DotnetCoverageArgumentList` + `Invoke-DotnetCoverageExe` (append `/Blame:...;HangDumpType=None` and a console logger), `ConvertTo-KoverageCoberturaXml`, the two asserts in try/catch as observations, `Get-CoberturaFirstPartyCoverageReport`, `ConvertTo-JacocoPackageProjection` + `Assert-JacocoProjectionReconciliation`, `Get-TrxRunSummary` + `Format-TrxRunSummary`. `Get-KoverageProjectAllowlist` (Helpers.ps1:44-46) drops every `.Test` assembly, so a test-only change produces no first-party movement by construction; record, do not gate.
4. **A helper script embedded in a fenced plan block must not contain literal triple backticks.** Writing the JaCoCo projection into a Markdown artifact needs a ` ```xml ` fence; inside the plan's own fenced block that terminates the fence. Build it as `$fence = [string]([char]96) * 3`.
5. **Doubled backslashes inside a `-Command` payload regex (`-split "\\Microsoft Visual Studio\\"`) are a collapse hazard.** Use `$m.Substring($m.IndexOf("Microsoft Visual Studio"))` to record a tool tail without any backslash.
6. **Pre-implementation readiness keys are read in the gate script, not its helpers.** `.claude/hooks/enforce-orchestration-preimplementation-gate.ps1:235-253` reads `issue-num`, `feature-folder` (must start `docs/features/active/`), `route_id` or `path_selected`, `lifecycle_ready`; `:39-45` lists five accepted checkpoint paths including `artifacts/orchestration/parallel-orchestrator-state.json`. A grep of the helpers file for those keys returns nothing.
