Seams from revision 1.14 of plan 927, applied after execution stopped at P6-T2 (PoshQC analyze returns no diagnostic count) and the run coordinator issued two rulings.

**Ruling 1 mechanics (PoshQC MCP as the sole local source).** `run_poshqc_analyze` and `run_poshqc_test` return `{ok, tool, workspace_root, summary}` only: no exit code, no count, no diagnostic list. Word the lint gate as the pass flag ("PoshQC analyze: pass (0 findings); tool reports no count"); a folder-level `ok=false` over a folder the plan does not write as a whole is attributable to the change only when the Phase 0 baseline call over the same folder read `ok=true` and the format pass's porcelain span shows no other rewrite there. The test tool writes `artifacts/pester/pester-junit.xml` (ignored by the `artifacts/` rule): root `testsuites tests= failures= errors= disabled=`, each `testcase` with `name` = Describe dot It, a `status` attribute (`Passed`) and a `classname` that is an absolute host path (plus machine-name and user properties), so derive counts and the It enumeration from it read-only and transcribe `Split-Path -Leaf classname` only; filter the hygiene tests with the single-character wildcard (`-like "*tests?scripts?hygiene?*"`) so the separator is channel-independent; require the document's age in seconds to be small so a stale run cannot be read. Scan_folders arrays naming unwritten folders are fenced (harvesting contract).

**CI-sourced coverage (post-PR task).** Append the coverage task after the last task (P6-T38) so no ID changes; locate the run with `gh pr view <branch> --json number,headRefOid` then `gh run list --branch <b> --commit <sha> --workflow CI --json databaseId,headSha,workflowName,event,status,conclusion` (workflow name from ci.yml line 1), select the greatest databaseId mechanically, confirm the Pester job through `gh run view <id> --json jobs --jq`, and filter `gh run view <id> --log` with `[0-9]+` classes: the step's script echo appears in the log with the same literal followed by `$(`, so a bare substring filter matches twice. `gh run download <id> -n pester-coverage -D <scratch>` yields one file (upload-artifact with a single path); require `ARTIFACT-FILES=1` and equality of the artifact's `/report/counter` LINE figures with the log's COVERAGE line to prove the document is the log's source. The deferred AC4 check-off executes inside the new task; the ledger carries `AC4: PENDING P6-T38` from the reconciliation task; sweep C11 (pairing rule), C12 (stop list), the loop-rule sentence, the consolidation task, the "last task" sentence, the guard-repeat sentence, the traceability row and the AC mapping in the same round.

**Ruling 2 mechanics (multiset fidelity gate).** `git diff -U0` reports a moved repetitive log line (`<N>>CoreClean:`) as removed plus added, so an "every removed line carries a token" gate reads 8 unmatched on a correct redaction. Replace it with a per-file line multiset (pre blob versus post blob) keyed by an Ordinal `Dictionary[string,int]` (PowerShell `@{}` is case-insensitive and would merge case-only variants). Read blobs as bytes through `System.Diagnostics.Process` with `RedirectStandardOutput` and `StandardOutput.BaseStream.CopyTo(MemoryStream)` (a `git show` captured by PowerShell re-encodes UTF-16 blobs), decode by byte-order mark, split on `\r?\n`; require `LINECOUNT-MISMATCH=0`, `MULTISET-REMOVED=MULTISET-ADDED` (equal line counts force it), `MULTISET-UNMATCHED=0`, and a `MULTISET-UTF16|` line for the one UTF-16 file so the UTF-16 handling is inside the gate rather than delegated to the helper's figure. Negative control in the same process: drop the first `CoreClean:` line from an in-memory copy of the post side of the named file and require unmatched = 1, removed = genuine removed + 1, added = genuine added.

**Arithmetic trap.** A pattern built as P1-T12's without the `(?im)` prefix is 40 minus 5 = 35 characters, not 36; re-derive every computed literal before writing it as an expectation.

**How to apply:** when a QA gate's tool returns only an ok flag, gate on the flag, derive counts from the ignored document it writes, and move any figure the tool cannot produce to the CI job that prints it, as a post-PR task with a deferred check-off; when a diff-based line-fidelity gate fails on repetitive log content, switch to a blob-level multiset with a same-process negative control rather than choosing a diff algorithm that yields zero.
