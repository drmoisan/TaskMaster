Seams from applying the round-11 rulings to plan 927 (revision 1.15). The planner had no Bash tool in this session; every git fact came from reading `.git/packed-refs`, `.git/worktrees/<id>/logs/HEAD`, `.git/logs/refs/**` and the loose ref files.

**Three-dot anchor after a mid-plan merge of main.** Once the run directs the branch to merge origin/main before the final QA phase, a two-point `git diff BASE-SHA HEAD` counts every path main gained (preflight measured `OUTSIDE-WRITE-SET=215`, `FILES=21` vs 13, `ADDED-RAW=2` vs 0). Anchor every Phase 6 diff (name-only, `--diff-filter=A`, `-U0` over .gitignore) at `origin/main...HEAD` inside the command span, print `MERGE-BASE-NOW=` from `git merge-base origin/main HEAD` as a recorded (never compared) line, keep BASE-SHA only as the formatting-baseline reference, and never backtick the range standalone in prose (the path harvester reads backticked tokens). The three-dot form stays correct even if a later `git fetch` moves origin/main past what was merged.

**Merge-base equality is unsatisfiable after the merge; replace with ancestry checks.** AC "the merge base with main is unchanged" cannot hold; Option B rewrote it as three `git merge-base --is-ancestor` checks (P0 merge base is an ancestor of the current merge base; recorded BASE-SHA is an ancestor of HEAD; the fetched remote-tracking tip of the branch is an ancestor of HEAD, which observes no-force-push). Append `2>&1 | Out-Null` and print `$LASTEXITCODE` per check; an absent ref exits 128, not 1.

**Verify a coordinator-named control ref against the reflog before adopting it.** The ruling named `prep/927-batched-plan-r1.10` (retracted revision, "never merged") as the negative control with commit 1d7100762 as fallback. The worktree reflog showed the retraction was a plain `commit:` entry on top of 1d7100762 (the plan-restore commit), not a reset, and packed-refs showed the ref and the fallback are the same object: both are ancestors of HEAD, both exit 0, and the ruling's own fallback branch would have left the AC permanently unchecked. Under the extended standing authority (re-anchored checks must stay able to fail, shown by a control) the gating control became the reversed first check (`git merge-base --is-ancestor HEAD <P0 merge base>`, exit 1 whenever HEAD advanced), the ruled ref was kept as a recorded-only line, and the substitution was logged as a numbered correction and reported for reversal.

**CI-sourced baseline mechanics.** Read the baseline run itself (`gh run view <id> --json headSha,headBranch,event,status,conclusion` plus `--log` through the same digit-class filter the branch run uses) instead of transcribing the coordinator's figures; treat a differing figure as a recorded transcription mismatch with mechanical floor recomputation. Floor = CI passed + the new It count (373 = 342 + 31) so one lost test fails; percent floor keeps the plan's existing 0.50 tolerance. Add `BASELINE-DRIFT-PS-FILES=` (`git diff --name-only <baseline head> <merge-base-now> -- "*.ps1" "*.psm1" .github`, expected 0) with a re-anchoring branch (`gh run list --branch main --commit <merge-base-now> --workflow CI --event push`, greatest completed databaseId) recorded as a re-anchoring, and fold "baseline figure not printed" into the existing CI-figure stop rather than adding a stop token (C12 stays unchanged). `gh run view --log` prints the step field as `UNKNOWN STEP`, not the step name.

**Spec formatting contract trap.** This spec's AC lines "carry no digits and no code spans"; the reworded AC19 names the checks in words ("phase-zero merge base", "exits zero", "exits one") and the SHAs live only in the dated note under the heading, which may carry digits as the earlier AC1 note does. The note insertion shifts every later citation by two lines; re-derive the checkbox line numbers (452 to 471 became 454 to 473).

**Payloads carrying a removal call.** `.RemoveAt(` or `Remove-Item` together with a literal item-worktree path is refused by the worktree-removal hook; state in the conventions block that the worktree prefix is built from joined string pieces.

**How to apply:** after any ruling that re-anchors a check to post-merge reality, (a) sweep every diff operand in the QA phase for the two-point form, (b) read the reflog for any ref the ruling nominates as a negative control before trusting the "never merged" description, (c) read CI baselines from the run rather than the brief, and (d) obey the spec's AC-line contract when rewording a criterion.
