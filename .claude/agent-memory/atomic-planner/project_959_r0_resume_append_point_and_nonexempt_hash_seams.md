Seams from completing plan 959 (SortEmail latent defects L1 to L4 plus the folded #966 residuals) after a quota stop left a 1,153-line plan with an `INCOMPLETE` banner and an `<!-- APPEND-POINT -->` line.

- **Resume mechanics.** The banner on line 1 quoted the marker string, so `Edit(old_string="<!-- APPEND-POINT -->")` matched twice; anchor every append on the preceding content line plus the marker. Append in chunks (listings, edits, inventory, commands, phases, record) and only then remove banner and marker; re-grep for both afterwards.
- **Spec AC line shape.** This spec writes `- [ ] AC1 (L1 code). ...`, not `- [ ] AC1. `; the check-off Edit is `- [ ] ACn (` to `- [x] ACn (`, and a Grep-tool acceptance pattern is a regex, so write `^- \[x\] AC1 \(` (the space-paren keeps AC1 distinct from AC10). State once in the phase preamble that brackets and parentheses are escaped.
- **Post-format Edits.** An Edit applied after a scoped CSharpier pass, inside a collection initializer under an expression-bodied property, cannot promise exact leading whitespace; declare the OLD/NEW as "identified by trimmed lines, indentation as found (Read first)" and make the two-line anchor unique by its neighbour (`AttachmentsAltNamePrompt,` followed by `RemoveReadOnlyPrompt,` in the array, by `TrySaveAttachmentAsync` in the wrapper).
- **Two-step red-first through a wholesale Write.** When a file is rewritten from a Listing but one defect needs an extraction step observed red, write the final Listing with exactly one named line omitted (the second `RedirectSaveFolder` statement), gate the omission by census (token 0 then 1), and insert the line by Edit after the red run.
- **AC25 gate without line numbers.** Hash the sorted set of `<cobertura filename>::<trimmed source text>` for every uncovered non-exempt line of the family at baseline and final; equality means no new uncovered statement wherever lines moved. Control: append the lowest covered non-exempt line of the exemption file and require the hash to differ. Exemption rules derive from source text: (1) lambda literal; (2) `}` after `else`,`{`,`throw;`; (3) the catch brace directly after a set-(2) line whose NEXT line is either `catch (System.Exception)` (baseline) or exactly eight spaces and `}` (final, outer catch removed), keyed on the brace's own indent; (4) the `}` after the first `throw;` following the single line containing `isRetryAfterClear` that is neither `bool isRetryAfterClear` nor `isRetryAfterClear:` — so no comment or doc line may contain the identifier.
- **Research correction (PD-6).** R2 said one `(saveAttachments: true, savePictures: true)` row "covers both `if` bodies"; `if (!saveAttachments)` and `if (!savePictures)` run only on false, so each test needs the complementary row too (sync adds (true,true) and (true,false); async adds (true,true) and (false,true)). Report such corrections in the handoff, not silently.
- **Pure-forward seam needs two Edits.** Landing the four-argument CSV overload as a forward of the current body requires replacing the header (wrapper + core signature) AND the inner `FileIO2.WriteTextFile(...)` call with `writeTextFile(...)`; otherwise the "seam" still writes the disk.
- **Expect-fail substrings observed in FluentAssertions/Moq messages.** Moq `Times.Once` miss: `but was 0 times`; FA collection Equal: `differs at index 0`; FA Be on int/count: `but found 0` / `but found 3`; enum Be: `but found` plus the enum name (formatting varies by FA version, so assert two substrings); pre-fix NRE: `NullReferenceException`; wrong exception type: the actual type name. Compile-red overloads: count `error CS` lines matching `'Name' takes N arguments` (CS1501) and `'Type' does not contain a definition for 'Member'` (CS0117) with `[char]39`.
- **Get-Content vs Read line counts.** The Read tool numbers the trailing empty line after the final newline, so `@(Get-Content).Count` is one less than the Read last line; write gates in one convention only.
- **Select-String banned by the plan's own convention** means sweeps and fact greps count files via `[regex]::IsMatch` over `Get-Content -Raw`, and the plan itself (under FEATURE) is swept: never write the worktree absolute path into the self-review prose.

**How to apply:** on any resumed plan, grep the banner for the marker text first; on any spec, read one AC line before writing the check-off Edit; when a final-shape coverage rule depends on what follows a brace, write both shapes into the rule; prefer set-of-text hashes over line-delta arithmetic for "no new uncovered line" gates in files that move.
