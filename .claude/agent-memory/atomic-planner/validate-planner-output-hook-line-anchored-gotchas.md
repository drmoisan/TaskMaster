Discovered authoring `docs/features/active/2026-09-02-breadcrumb-bridge-keyboard-navigation-defects-737/plan.2026-09-02T00-00.md` (#737, 2026-09-02). `.claude/hooks/validate-planner-output.ps1` is wired as the atomic-planner SubagentStop hook and is stricter than the prose contract implies:

1. **`Test-TaskContainsExplicitPath` reads only the single line matching `^- \[(?<State>[ xX])\] \[P#-T#\] (?<Text>.+)$`.** `.NET` regex `.` does not cross `Get-Content`'s per-line array boundary, so a path that appears only inside a fenced code block on a *following* line is invisible to the check. A task like `- [ ] [P0-T13] Baseline scoped vstest run against the Write Set's shared assembly (...):` followed by a fenced PowerShell block containing the actual `\bin\Debug\Foo.dll` path FAILS the hook, even though a human reading the task clearly sees a path. Put a slash/backslash-bearing path token directly on the task's own opening line, before any trailing colon that introduces a code fence.
2. **The `PLANNER-INTERNAL-REVIEW:` bounded record is validated against the AGENT'S OWN FINAL CHAT OUTPUT (`payload.output`), not against the plan file on disk.** Writing a pristine bounded record into `plan.md` alone does nothing for this hook; the same record (header, `CITATION-TO-TREE`/`AC-TRACEABILITY`/`SCOPE-BOUNDARY`, one-or-more `CITATION:`, `AC-INVENTORY:`, one `AC-MAPPING:` per inventory ID, `UNRESOLVED-GAPS: NONE`) must be reproduced verbatim in the chat response that ends the planner's turn.
3. **Every declaration line must match its regex with nothing trailing.** `CITATION-TO-TREE: PASS`, `AC-TRACEABILITY: PASS`, `SCOPE-BOUNDARY: PASS`, and `UNRESOLVED-GAPS: NONE` are matched with `\s*$` immediately after the required value — `SCOPE-BOUNDARY: PASS (rationale...)` FAILS because of the trailing parenthetical. Put rationale on the next line instead.
4. **`CITATION:` lines require a pipe-free, space-free Path token immediately followed by ` | `.** `CITATION: fileA.ps1 and fileB.ps1 | locator text` fails to match at all (the regex expects `Path\s*\|\s*Locator` and `Path` is `[^|\s]+`, so it stops at the space before "and" and then fails to find the pipe next). Cite each file on its own `CITATION:` line.
5. **Markdown backtick code-spans around a signal line break the line-anchored regexes**, since the regex requires the line to literally start with the label text (e.g. `^\s*PLANNER-INTERNAL-REVIEW\s*:`), and a leading `` ` `` character is not whitespace. Write `PLANNER-INTERNAL-REVIEW: PASS`, `PREFLIGHT: ALL CLEAR`/`PREFLIGHT: REVISIONS REQUIRED`, and every other structured declaration as **plain unwrapped text**, not inside backticks, in both the plan file and the chat output.
6. **The planner cannot self-emit a genuine `PREFLIGHT: ALL CLEAR`** (per [[planner-mcp-validator-not-in-tool-surface]]), yet the hook unconditionally requires exactly one line matching `PREFLIGHT: (ALL CLEAR|REVISIONS REQUIRED)` after the header or the turn is blocked. Resolution used: emit `PREFLIGHT: REVISIONS REQUIRED` on its own line with NO trailing text, and put the honest qualifier ("this is not a discovered defect; clearance is outstanding because atomic-executor preflight has not yet run") on adjacent separate lines before/after it. This satisfies the hook's mechanical requirement without overclaiming `ALL CLEAR`.

**How to apply:** After drafting a plan, grep the plan file for every task's opening `- [ ] [P#-T#]` line and confirm a `[\\/]`-bearing path appears on that exact line (not merely later in the task). Before ending the turn, copy the plan's `PLANNER-INTERNAL-REVIEW` bounded record and the closing `PREFLIGHT:`/`plan-path:` lines into the chat response verbatim as plain text (no backticks), and grep the record for stray trailing text after every `PASS`/`NONE` declaration.
