Seams found while authoring the issue #973 plan (15 stale redirect pairs, ADAL deletion, aliased System.Linq.AsyncEnumerable install) in worktree `.claude/worktrees/agent-a24d410b914bcefd7` on 2026-10-02, round 0.

**Why:** two acceptance criteria in the sole AC source were unsatisfiable as written, and the planning session had no shell, so every git and clock fact needed another route.

**How to apply:** before planning any redirect/range guard or any coverage no-regression clause, and whenever the Bash tool is absent from a planner session.

1. **A range-only guard (`OldVersion -eq '0.0.0.0-' + NewVersion`) cannot be red before a redirect sweep.** NuGet writes every redirect as `0.0.0.0-X`/`X`, so a stale entry is range-consistent with its own stale newVersion; measured on all 137 pair entries plus the 15 System.Linq.AsyncEnumerable entries. The spec claimed the guard fails in the fail-before run. Fix applied: assert additionally that NewVersion is in the csproj Reference map for the Name (the #953 Fizzler It pins `1.3.1.0` for the same reason). Amended AC5, Part D (a) and the Test Strategy sentence in spec.md under a "Planner Amendments" section, with a read-only P0 verification task (Grep marker counts) and no executor edit of spec.md.
2. **Strict `final >= baseline` on first-party coverage fails on an identical tree.** #940 coverage-final.md recorded 85.33 against 85.31 lines and 79.72 against 79.71 branches between two runs of one committed tree. Amended AC14 to floors plus a 0.10-pp tolerance when the first-party `lines` denominators are equal, one repeat and a one-sentence not-comparable record otherwise, with the strict form kept as the fallback if the orchestrator rejects the amendment. Equal denominators are the falsifiable proof that no production line changed.
3. **Bash disabled in the planner session.** HEAD came from `<main-repo>/.git/worktrees/<agent-id>/HEAD` (a `ref:` line) and `.git/refs/heads/<branch>`; origin/main from `.git/refs/remotes/origin/main`; the harness gitStatus snapshot named an older HEAD than the ref file (the orchestrator had committed since). Record both in P0 by command; never pin them in the plan. Timestamps could not be read from a clock, so the plan header kept the scaffold's timestamp and the amendments carry the date only, stated explicitly.
4. **CR census with the Grep tool.** Pattern `\r$` in count mode works through the Grep tool and, compared with the `^` count, distinguishes a CRLF file with a terminated last line (equal counts: all 17 app.config, the test file) from one without a trailing newline (CR = lines minus 1: every csproj and the five target packages.config). Write the per-file expected delta into every insert/delete task (`+1`/`+1`, `+9`/`+9`, `-4`/`-4`) so an Edit that wrote LF is caught without `git ls-files --eol`.
5. **Value-string census reconciles the family.** Grep `newVersion="(v1|v2|...)"` over `*/app.config` in count mode gave 165 across 15 files = 137 pairs + 13 ADAL + 15 SLAE, proving no other block carries a shared value; shared strings (`10.0.0.7` on Bcl.Memory and SLAE, `8.22.0.0` on eight names) still force the two-line name-anchored Edit.
6. **`$expectedDebt = @()` left unread trips PSUseDeclaredVarsMoreThanAssignments.** Keep the literal (the spec names it) and read it in a zero-count ratchet assertion before the real count assertion.
7. **Coverage route.** The runner wrapper has a hard-coded TestCaseFilter and no hang timeout; the #940 DIRECT route (dot-source the runner for `ConvertTo-DerivedCoverageSettingsXml`, same collector/vstest/runsettings, four shell-icon classes excluded, `/Blame:CollectHangDump;TestTimeout=4min;HangDumpType=None`, then the runner's own post-processing functions) is the reusable shape; record `ROUTE-FILTER:` and the CI job that covers the excluded classes.
