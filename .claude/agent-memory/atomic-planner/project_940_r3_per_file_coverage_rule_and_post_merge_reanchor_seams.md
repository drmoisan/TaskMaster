Seams from applying the coordinator's AC8 ruling (2026-09-30, option 1) and the orchestrator's post-P2-T6 merge to plan 940 (worktree agent-a237392a2250d275b), in a session with no Bash tool.

**Aggregate not-lower gates are variance detectors, not change detectors.** MEASUREMENT 1 and 2 of the same committed tree (DIRECT route, 9 assemblies, 7326 tests) moved the UtilitiesCS package by 2 to 10 covered lines/branches and REPO-LINE by 2 covered lines, all in files the item never touched (PropertyStore.cs, OlTableExtensions.Etl.cs, SubjectMapSco.Orchestration.cs), while all three per-file FILE lines stayed NOT-LOWER=True. The ruling replaced D-7 (package + REPO-LINE not-lower, one identical re-measurement) with: per changed file, covered lines AND covered branches not lower than baseline, plus the first-party 80/75 floors; the package/repo figures survive only as an observational variance table (rows baseline, m1, m2, m3; columns package lines/branches, first-party lines/branches, per-file lines/branches; plus the untouched files' covered counts per stage). Plan the per-file rule from the start for test-only changes; a repo-wide "not lower" comparison of a 65k-line denominator cannot be made deterministic (see [[repo-wide-cobertura-line-rate-is-nondeterministic]]).

**Cobertura per-line branch shape (observed, dotnet-coverage 18.10 after ConvertTo-KoverageCoberturaXml).** Branch lines carry `branch="True" condition-coverage="50% (1/2)"` with a nested `conditions` element; non-branch lines carry `branch="False"` and no attribute; `filename` is the repo-relative path with BACKSLASHES (`UtilitiesCS\HelperClasses\FileSystem\X.cs`), so `-like ("*" + [char]92 + $leaf)` matches and a forward-slash grep does not. Parse the `\((\d+)/(\d+)\)` fragment; single backslashes survive the Bash-tool payload channel (CMD-REBUILD's `(\d+) Warning\(s\)` already did). Per-file union across class elements: key by line number, max hits, and for branches keep the larger covered value with its denominator.

**In-memory comparator negative control.** Read the final document once into a per-line hashtable via a `$read` scriptblock, print CONTROL-SELF (doc vs itself, True), then clone (`$clone` copies each nested hashtable), set the lowest-numbered covered line's hits to 0 (CONTROL-LINE, False), clone again and lower the lowest-numbered branch line's covered count by 1 (CONTROL-BRANCH, False); bracket the payload with Get-FileHash of the document (BEFORE equals AFTER proves nothing on disk changed). Verify beforehand that every file has a covered branch (here each ctor guard line: PDA 13 `(1/2)`, PFA 27 `(1/2)`, DIWP 16 `(2/2)`) or `$kb` is null and the control crashes. Copy the `$read`/`$compare` lines verbatim into every block that uses them and gate byte-identity with a full-literal count grep (3).

**Foreign test-process pre-step.** `Get-CimInstance Win32_Process` filtered on Name like `vstest.console*`, `testhost*`, `dotnet-coverage*`, "foreign" = CommandLine does not contain the worktree root (OrdinalIgnoreCase; unreadable command line counts as foreign); print only name, pid and the `agent-[0-9a-f]+` fragment. No sleep in the payload: the executor re-invokes until `FOREIGN-TEST-PROCESSES: 0`, bounded at 120 minutes (`FOREIGN TEST RUN STALLED`).

**Post-merge re-anchor mechanics (merge made in the item worktree, verified from logs/HEAD).** Derive ANCHOR-SHA-2 as `git rev-parse <merge-sha>^2` (the merged origin/main tip, the new merge base; the merge SHA is a git operand, never an expectation of HEAD), gate `git diff --exit-code ANCHOR-SHA ANCHOR-SHA-2 -- UtilitiesCS UtilitiesCS.Test` exit 0 (`CITED TREE ADVANCED` otherwise) so the old PRE-EDIT/FIX hashes and line citations stay valid, record `git diff --name-only A A2 -- <out-of-set pathspec>` as the reason the out-of-set two-dot gate moves to ANCHOR-SHA-2 (main may have changed TaskMaster.Test files in that pathspec), and gate `git merge-base HEAD origin/main` equal to ANCHOR-SHA-2 in every task that runs a three-dot span (`MERGE BASE MOVED`); three-dot `origin/main...HEAD` then lists only the branch's own paths, so no merged sibling path can enter the footprint. Leave executed two-dot tasks (P1-T31, P2-T1) on the old anchor.

**How to apply:** for any C# item whose coverage gate is "not lower than baseline", author the per-file lines-and-branches form with an in-memory negative control and treat aggregates as observations; after any mid-run merge of main, derive the new anchor from the merge commit's second parent and gate anchor agreement under the source trees; when a ruling offers "ITERATION N or sub-record", choose the form whose counter semantics are true.
