Planning seams re-derived for issue #731 against `bug/quickfiler-controller-lifecycle-disposal-defects-731`.

**Why:** the fix-design research artifact for this issue carried two stale size claims, and both would have produced an unbuildable or ceiling-violating plan if trusted.

**How to apply:** when planning any further work in this region, re-measure before placing new test code.

- `QuickFiler.Test/Controllers/QfcCollectionControllerDefects468Tests.cs` measured **498 lines**, not "well under the cap" as the research said. Any new test for that class must go in a partial-continuation file (`...Defects468Tests.Volatile.cs`) after making the existing declaration `public partial class` — a same-line edit with zero line delta. Only the original part carries `[TestClass]`. See [[project-400-partial-class-headroom-placement]] and [[project-503-ribbon-readiness-plan-seams]] for the same pattern.
- `QuickFiler/Controllers/QfcQueue.cs` is **505 lines** — already over the 500-line ceiling before any edit. Adding even a comment grows an over-ceiling file, so the growth has to be disclosed and numstat-bounded rather than assumed harmless. `QfcCollectionController.cs` is 2327 and `QfcFormControllerSeamTests.cs` is 496 (research said 497).
- The three-owner monitor pin test counts occurrences of the literal `new EmailMoveMonitor()` per file. The explanatory comment the same task adds above each initializer must therefore **not** contain that literal, or the pin counts 2 and fails. Same class of trap as [[zero-hit-grep-gates-need-carveouts]].
- In `QuickFiler.Test/Controllers/QfcDatamodelTests.cs` the identifier `highConfidenceEnabled` occurs **only** inside the `CreateQueueAdmission` factory and its five call sites, so its total disappearance is an exact fail-capable proxy for "the inert strict-mock arrangement was removed". `IAppQuickFilerSettings`, `MockBehavior.Strict` and `Mock<IApplicationGlobals>` all recur elsewhere in the file and are useless as gate tokens.
- `scripts/vscode/Invoke-MSTestWithCoverage.ps1` calls `Assert-CoberturaLineCoverageThreshold` (80% floor, Helpers.ps1:487) **before** `Set-Content` writes the Koverage post-processed XML. On a sub-floor run the artifact at `coverage\coverage.cobertura.xml` still exists but retains dotnet-coverage's absolute `filename` paths. Any per-file coverage extraction must match on the trailing filename substring so it works in both states. Related: [[project-494-threshold-reconciliation-plan-seams]].
- Findings that look "structural, no fail-before possible" often are not. The #731 `Volatile.Read` source-inspection proxy and the #233 constructor-shape pin are both false before their production edit and true after, so both get a genuine test-first `[expect-fail]` run. Only the three-owner topology pin (which passes on the pre-change tree) needs a fail-before exception dossier.

Added on revision round 2:

- **spec.md said ONE comment line, not three.** spec.md line 99 ("Add **one** explanatory comment line above each of the three field initializers") and AC19 at line 235 ("the diff to that file is limited to one statement and **one comment line**") both bound the finding-1 edit to a single line per owner. The design-summary table at spec.md line 87 says "Three comment lines in production", which is one line in each of three files — not three lines in each. Reading the table row instead of the prose produced a plan whose own numstat gate contradicted AC19. Always take the AC text as the bound.
- **`TaskScheduler.Default` continuations have no deterministic observation point.** A deferred `Dispose()` on a `ContinueWith(..., TaskScheduler.Default)` runs on the thread pool, and `.claude/rules/general-unit-test.md` bans both wall-clock waits and polling spins, so the only deterministic route is for the production fix to assign the `ContinueWith` result to a field the test awaits by reflection. Budget one extra private field plus one assignment per branch when planning any deferred-dispose fault boundary. Related: [[project-670-webview-fault-boundary-plan-seams]].
- **A comment inserted near the top of a file invalidates every later line citation in the same plan.** One line above QfcCollectionController.cs:83 moved the finding-4 guard from 991 to 992 and one line above QfcDatamodel.cs:103 moved the admission site from 353-359 to 354-360. State baseline *and* post-edit line numbers, and have later tasks locate by literal token rather than by line number. This is also what makes a changed-line coverage comparison wrong if it keys the baseline lookup on the post-change line number.
- **The 991 guard is unreachable by the existing suite.** Both tests entering `RemoveSpecificControlGroupAsync` (Defects468Tests.cs:165, :199) build on `CreateUninitializedController()` and throw at the `_itemGroups[selection - 1]` dereference at QfcCollectionController.cs:919, well before the guard. A changed-line coverage gate demanding zero uncovered changed lines is therefore unsatisfiable; gate on `post_hits == 0 AND baseline_hits > 0` instead. Related: [[deletion-adjusted-coverage-no-regression-gate]].
- **The baseline Cobertura is destroyed by the final QA run.** (round 2) `Invoke-MSTestWithCoverage.ps1:343` `Set-Content`s over `coverage\coverage.cobertura.xml` in place, so any baseline-vs-post per-line comparison needs a Phase 0 task that copies the per-line `hits` rows into the evidence artifact first. Record the trailing filename only: the threshold assert at :341 throws before that write, so on a sub-floor run the on-disk XML still holds absolute host paths.

Added on revision round 3 (all four defects were in Phase 0 / Phase 5 gate wiring; every implementation task in Phases 1-4 verified clean across two rounds):

- **A gate's own porcelain capture cannot enumerate the artifacts written after it.** [P5-T9] required its `git status --porcelain --untracked-files=all` capture to list every evidence artifact the plan names, but three of them (its own `scope-boundary.md`, and the later `file-size-audit.md` and `ac-traceability.md`) do not exist yet when the capture runs. Bound the enumeration by a task-ID range that ends at the capturing task, and name the later-written artifacts as explicit, auditable exclusions. See [[self-referential-evidence-enumeration]].
- **Two porcelain forms need two set sources.** The collapsed form emits one directory entry for a wholly untracked feature folder; `--untracked-files=all` emits one entry per file. If one gate asserts against the collapsed form and another against the expanded form, the "pre-existing paths" set the two subtract must be populated from **both** forms, or the collapsed directory entry is never a member and the collapsed-form gate is unsatisfiable. Related: [[porcelain-collapses-untracked-directories]].
- **A Phase 0 snapshot cannot bound `.claude/agent-memory/`.** Routing Phase 5 gates through the set Phase 0 captured handles pre-existing drift only. Agents write to their own memory directories *during* execution, so a tracked memory file can enter the modified set after the snapshot was taken — this happened during round 2's own preflight review. Use a standing allowance ("every path under `.claude/agent-memory/` is a member of the disclosed set, whether or not Phase 0 saw it"), never a snapshot. Refines [[agent-memory-is-tracked-scope-git-gates]].
- **Repository-wide `line-rate` is not gateable on this harness.** See [[repo-wide-cobertura-line-rate-is-nondeterministic]]. Fix was a two-branch gate keyed on `lines-valid` comparability, with the hard no-regression judgment resting on the per-changed-line comparison.
- **Guarantee a required diagnostic string rather than hoping for it.** (round 3) `[P2-T3]`'s `[expect-fail]` acceptance demanded an `ObjectDisposedException` in the recorded failure text. Nothing made that certain until the paired test's FluentAssertions call was required to pass the observed `consumer.Exception` as a `becauseArgs` argument. Pass it as an argument, not interpolated: FluentAssertions reads `{` and `}` in a `because:` message as format placeholders.

Added on revision round 4 (all three defects were on the bootstrap/observability axis that no round without shell access could reach):

- **A fresh agent worktree is not bootstrapped, and `dotnet tool restore` is not the first command.** `global.json` pins `sdk.version` `8.0.205` with `paths: [".dotnet-sdk", "$host$"]`, so with `.dotnet-sdk/` absent and only a 10.x host SDK present, EVERY `dotnet` SDK command fails with global.json's own `errorMessage` — including `dotnet tool restore` itself. `scripts/vscode/Install-RepoDotNetSdk.ps1` defaults to `-Version 8.0.205` and throws unless it creates the exact marker directory `.dotnet-sdk/sdk/8.0.205`, so that literal path is a satisfiable acceptance token. Separately, `packages/` is absent and QuickFiler.Test is a legacy `packages.config` project with 70 `..\packages\` HintPaths that `msbuild` does not restore; CI runs `nuget restore $env:SOLUTION_PATH` at `_build-analyzers.yml:45`, `_build-nullable.yml:45`, `_mstest-coverage.yml:45`. Plan a three-step Phase 0 bootstrap (SDK install if marker absent → `nuget restore` → `dotnet tool restore`). Both trees are gitignored (`.gitignore:350` `.dotnet*/`, `.gitignore:191` `**/[Pp]ackages/*`) so they add nothing to a porcelain gate. Residual unverified risk: `nuget.exe` is put on PATH in CI by `nuget/setup-nuget@v2` and may not be on a local PATH. Extends [[agent-worktrees-need-sdk-and-nuget-bootstrap]].
- **`<DebugType>full</DebugType>` turns a quoted failure message into a host-path leak.** `QuickFiler.Test/QuickFiler.Test.csproj:34` sets it, so any Debug stack trace quoted into a committed evidence artifact carries the full source path — and this worktree's absolute path contains a machine account name. A per-task rule on the one Cobertura task is not enough: write a plan-wide **Evidence path-hygiene rule** covering tool output, failure messages, stack traces and Cobertura `filename` values alike. Related: [[../_shared_no_absolute_host_paths]] and [[runtime-derived-account-token-pattern]].
- **A 1:1 baseline/post line mapping is unsatisfiable for a one-line-replaced-by-many hunk.** `git diff --unified=0` renders [P2-T4]'s rewrite of `QfcFormController.SetupDisposal.cs:218` as one hunk with a 1-line pre-image and a ~20-line post-image, so 19 added lines have no integer baseline line at all, and the one pre-image line (`_undoQueue?.Dispose();`, covered at baseline via `QfcFormControllerTests.Cleanup_ShouldCleanupResources` at :253-264) would lend its coverage to all 20. Key the mapping on **hunk shape**: equal add/remove counts map one-to-one; every other shape yields `baseline_line=none baseline_hits=n/a` and is excluded from the regression count. The gate stays fail-capable because the line-neutral [P4-T5] guard rewrite and the [P3-T3] signature edit still produce genuine 1:1 hunks. Related: [[deletion-adjusted-coverage-no-regression-gate]].
- **`_undoQueue` is field-initialized (`= []` at `QfcFormController.cs:90`), never null.** Checked because [P2-T4] replaces a null-conditional `_undoQueue?.Dispose();` with unconditional `CompleteAdding()`/`Dispose()` on a captured local; had the field been lazily assigned, the existing `Cleanup_ShouldCleanupResources` test would have started throwing NRE and tripped [P5-T5]'s no-newly-failing gate. Always re-derive field initialization before removing a null-conditional.

Added on revision round 5 (three of the four defects were reachable by reading two existing plan sentences against each other — the plan's own gate-wiring prose became the defect surface):

- **A PowerShell token-absence assertion is case-insensitive by default and can collide with a retained identifier in the same acceptance list.** `[P3-T5]` demanded `QfcDatamodelTests.cs` no longer contain `highConfidenceEnabled` while the same list required `..._HighConfidenceEnabled_AddsAndHooksWithoutScoring` to survive; `Select-String` and `-match` are both case-insensitive, so the task could never pass. Write a plan-wide **token-assertion case rule** (`-CaseSensitive` / `-cmatch` / `git grep` without `-i`) once in the preamble rather than per task, and check every absence token against the retained identifiers in the same file. Related: [[zero-hit-grep-gates-need-carveouts]] and [[project-469-comment-accuracy-plan-seams]] (`AC1` prefixes `AC10`).
- **A Cobertura descendant-axis (`.//line`) count double-counts on two independent axes.** `Invoke-MSTestWithCoverage.Helpers.ps1:167-175` documents axis one (every source line appears under `methods/method/lines` and again in the class-level `lines` rollup, issue #441) and `Merge-CoberturaClassesByFilename` at `:262-391` exists for axis two (one `filename` carries several `class` elements pre-processing, closure classes discriminated by `name` containing `<` at `:290`). Specify a de-duplicated per-line map once — `./lines/line` then `./methods/method/lines/line`, keyed by `number`, resolved by max `hits` — and have every consumer point at that one definition. Dot-sourcing the helpers file also imports `Set-StrictMode -Version Latest` (`:1`), so the caller's own snippet must use `GetAttribute('...')`, not bare property access.
- **Add a `Cobertura document state:` discriminator (`raw` vs `processed`) to every coverage capture.** `ConvertTo-KoverageCoberturaXml` (`Helpers.ps1:393-457`) rewrites all `class/@filename` to repository-relative at `:423-425`, so a drive-letter prefix is a state discriminator that leaks no absolute value. Without it, a raw baseline and a processed post-change run get compared per-line as if commensurable. The re-derivation remedy is directional: only the document still on disk can be re-processed in memory, so if the *baseline* was raw its document is already gone (overwritten at `Invoke-MSTestWithCoverage.ps1:343`) and only the disagreeing lines can be excluded.
- **A conditional QA branch elsewhere in the plan makes an unconditional AC check-off wrong.** `[P5-T1]` authorised a scoped csharpier branch and `[P5-T5]` a non-zero test exit with residual pre-existing failures, while spec.md AC17 demands a clean toolchain "in a single uninterrupted pass". `[P6-T18]` was checking AC17 off regardless. Any AC whose text states an absolute bar must have its check-off task gated on the non-degraded branch actually having been taken, and the phase's blanket "count of `- [x]` equals tasks completed" clause must subtract the deliberate leave-unchecked case or it contradicts the task it governs. Related: [[feedback-ac-checkoff-one-per-task]].
- **A branch input that is actually derived from another input creates a state the plan can describe but never reach.** Round 3/4 treated the Cobertura document state (`raw`/`processed`) as a third independent branch input. It is not: `Invoke-MSTestWithCoverage.ps1` throws at `:236` when the vstest child exits non-zero and asserts the 80 percent floor at `:341` *before* writing the post-processed XML at `:343`, with `Set-StrictMode`/`$ErrorActionPreference='Stop'` at `:245-246`, so **exit 0 ⟺ processed** and **non-zero ⟺ raw (or no document at all)** for any invocation without `-NoExecute`. Once that is seen, one of the two "directions" the plan branched on is unreachable and the other makes its own gate vacuous. Before writing a multi-branch gate, ask which of the branch inputs are *source* observations and which are functions of the others, and enumerate only the reachable cross product.
- **An exclusion rule whose predicate is the definition of the thing being detected makes the gate vacuous.** "Exclude every changed line whose baseline and post-change `hits` disagree" removes exactly the lines a regression consists of, so "the regression count is 0" is satisfied by construction. When a gate has to be dropped in a degraded state, say so explicitly, and name the compensating evidence that *is* available (here: the 80 percent absolute floor, which the degraded state's own precondition proves passed). Related: [[zero-hit-grep-gates-need-carveouts]].
- **Cobertura `line-rate` is a fraction in 0-1, not a percentage** (`Invoke-MSTestWithCoverage.Helpers.ps1:482-484` range-checks it, `:486` multiplies by 100). A "no more than 0.5 percentage points below baseline" bar compared against two raw fractions can essentially never fail. State every `line-rate` bar in rate units (0.005 for half a percentage point).
- **An unanchored trailing-filename match on Cobertura `class/@filename` also selects the sibling interface file.** `QuickFiler/Interfaces/IQfcDatamodel.cs` ends with the text `QfcDatamodel.cs` and is **not** interface-only — it declares `public readonly struct QfcDequeueBatch` at `:49` with a constructor and expression-bodied properties, so it emits real executable lines that fold into the wrong per-line map. `IQfcQueue.cs` and `IQfcCollectionController.cs` collide the same way (currently bodiless). Anchor on `\<filename>` or `/<filename>`; both document states carry a separator, because `ConvertTo-KoverageRelativePath` (`Helpers.ps1:50-95`) strips only the repo-root prefix and leaves the repository-relative remainder.
- **A plan-wide hygiene rule can contradict an earlier task's explicit instruction.** The round-3 Evidence path-hygiene rule said "reduce any other absolute path to its filename", which collapsed the `vswhere`-resolved `MSBuild.exe` path that `[P0-T7]`/`[P0-T8]` are explicitly required to record. Every blanket rule added late needs a sweep of the tasks that already state a conflicting requirement. Related: [[observation-scope-must-match-blast-radius]].
