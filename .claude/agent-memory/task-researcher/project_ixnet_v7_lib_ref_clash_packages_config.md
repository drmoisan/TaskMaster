Ix.NET v7 (`System.Linq.Async 7.0.1`, `System.Interactive.Async 7.0.1`) ships a ref/lib split: `ref/net48` exposes only `System.Linq.AsyncEnumerableDeprecated` (173 members: SelectAwait, ForEachAsync, ...), while `lib/net48` keeps the full public `System.Linq.AsyncEnumerable` class (334 members incl. ToListAsync, ToAsyncEnumerable, CountAsync, ToArrayAsync, Select) for binary compatibility (dotnet/reactive #2291, PRs #2292/#2293). Verified 2026-10-02 from the shipped XML docs in `<main-checkout-root>\packages\System.Linq.Async.7.0.1\{lib,ref}\net48\`.

**Why it matters here:** every HintPath in this repo points at `lib\net48`, because packages.config cannot select `ref/`. So "PackageReference consumers compile fine with both assemblies" does NOT transfer: referencing the BCL `System.Linq.AsyncEnumerable` package globally duplicates the type and yields CS0121/CS0433 at every shared-name operator call (about 60 production lines in UtilitiesCS/QuickFiler/ToDoModel/TaskMaster). The build compiles today only because csc never needs the BCL assembly (the operators live in the Ix lib dll); the Ix dll's own reference to `System.Linq.AsyncEnumerable 10.0.0.6` is unresolved at build (RAR log in #825 evidence) and would be FileNotFound at runtime if reached.

**How to apply:** when a research/plan proposes adding `System.Linq.AsyncEnumerable` to a packages.config project, require `<Aliases>SystemLinqAsyncEnumerable</Aliases>` on the Reference (no source file needs `extern alias`; Ix.NET's own csproj uses the same alias). The dependency tooling (`scripts/dependencies/PackageGraph.psm1`, `ConsistencyVerifier.psm1`, `BindingRedirectVerification.psm1`) parses Reference/HintPath lines individually and ignores the Aliases line, so all gates read it as a normal reference. Risk: `nuget.exe update`/Dependabot re-adds the Reference and may drop the alias; the failure is a loud CS0121, not silent — propose a Pester assertion in `RepositoryTreeConsistency.Tests.ps1`. Read the restored DLL's AssemblyVersion before writing `Version=` and redirects (10.0.6 -> 10.0.0.6 is verified for this family; 10.0.12 -> 10.0.0.12 is inferred).

Also learned the same day: `Directory.Build.props` (sets `RxUseUnsupportedPackagesConfig=true`, #730) and `Directory.Build.targets` (VSTO signing toggles) DO exist at the repo root; CLAUDE.md's "there is no Directory.Build.props" sentence and the first #973 research's "no Directory.Build reference" line are stale. Neither file touches NoWarn/TreatWarningsAsErrors. All CS0618 sites for obsolete Ix operators are already pragma-suppressed (18 sites); the "~14 unsuppressed CS0618 in UtilitiesCS" note in the atomic-executor memory is stale — the committed #825 gate logs show 0 warnings.
