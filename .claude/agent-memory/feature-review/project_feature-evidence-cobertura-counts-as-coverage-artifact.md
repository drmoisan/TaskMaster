Issue #424 (2026-08-06): the executor committed full-suite Cobertura reports at `<FEATURE>/evidence/baseline/coverage-baseline.cobertura.xml` (merge-base) and `<FEATURE>/evidence/qa-gates/coverage-final.cobertura.xml` (HEAD), and `artifacts/csharp/coverage.xml` was absent. I treated the coverage artifact as PRESENT and verified substantively from the committed XMLs, rather than repeating #309's procedural-FAIL-for-absent-canonical-path disposition.

**Why:** This repo's own rules make the feature folder the canonical location: the evidence-location invariant and the atomic plans' non-overridable evidence rules state "Any `artifacts/`-rooted evidence path is invalid." Writing FAIL because coverage evidence is NOT at an `artifacts/` path would contradict the invariant the executor correctly followed. The skill's artifact-absence FAIL rule exists to guarantee coverage is verifiable; committed full-suite Cobertura satisfies that purpose. Hook mechanics stay safe either way: absent `artifacts/csharp/coverage.xml` parses to `$null` (JaCoCo parser), so neither the sub-85 forced-FAIL nor the sub-75 branch block fires.

**How to apply:** When reviewing a TaskMaster C# feature, look for executor Cobertura under `<FEATURE>/evidence/{baseline,qa-gates}/` first. If present: recompute repo-wide root rates plus per-file line coverage (dedup by filename+line-number; Cobertura repeats lines under `<method><lines>` and class-level `<lines>`) and per-file branch coverage (per-line max of `condition-coverage` `(x/y)`), and write honest PASS/FAIL rows from those numbers. Document the canonical-path reconciliation in the policy audit's Evidence Location Compliance section. A baseline-vs-final pair also lets you verify no-regression and the like-for-like denominator caveat (on #424 `lines-valid` grew 79,957 -> 110,849, +38.6%, between runs — dotnet-coverage instruments a varying assembly set, so repo-wide deltas across runs are measurement artifacts; only per-file/changed-line figures are comparable). Also on #424: full end-to-end hook verification is easy — dot-source `.claude/hooks/validate-feature-review-coverage.ps1` and call `Invoke-FeatureReviewCoverageValidation -RawPayload (@{output=$tokens}|ConvertTo-Json)`; the file guards with `$MyInvocation.InvocationName -eq '.'` so dot-sourcing does not execute the gate. See [[deletion-only-pr-absent-coverage-artifact-309]] for the older stricter disposition this supersedes when committed feature-evidence Cobertura exists, and [[pr-context-summary-misclassifies-cs]] for making the hook enumerate C# at all.
