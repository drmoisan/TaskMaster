On issue #278 review (2026-07-08), no `artifacts/csharp/coverage.xml` was committed (it is `.gitignore`d, per `artifacts/` in `.gitignore`). Rather than either (a) accepting the executor's narrative coverage numbers on faith, or (b) mechanically FAILing the coverage gate because the canonical path was empty, I located the executor's own raw `.coverage` binary already sitting uncommitted in `TestResults/<guid>/<host>.<timestamp>.coverage` (matching the evidence file's reported test-run timestamp/pass-count) and converted it with the `dotnet-coverage` global tool (`dotnet tool list -g` showed it installed; `dotnet-coverage merge -f cobertura -o artifacts/csharp/coverage.xml <file>.coverage`). This is a pure format conversion of already-collected data, not a coverage-generation rerun, so it stays within the "does NOT rerun coverage generation" constraint.

Parsing the resulting Cobertura XML (`<package name="...">` line-rate, then `<class filename="...">` block, then per-`<line number="N" hits="H">`) let me independently corroborate the evidence's claimed 86.02% assembly figure (I got 88.15% for the `UtilitiesCS` package via a different tool/methodology — both clear 80%) and directly confirm `hits="1"` on all 4 new/changed executable lines, without trusting the narrative alone.

**Why this matters:** A missing canonical coverage artifact is not the same as missing coverage evidence — raw `.coverage` output from the same execution session is often still sitting in `TestResults/` and can be converted on the spot with tooling already present in this repo's dev environment (`dotnet-coverage`, `CodeCoverage.exe` under `~/.nuget/packages/microsoft.codecoverage/*/build/netstandard2.0/CodeCoverage/`). Note `CodeCoverage.exe analyze` is deprecated and its usage banner does not clearly document the `/output:` flag in this version — use `dotnet-coverage merge -f cobertura` instead, it worked directly.

**How to apply:** Before flagging "coverage artifact absent" as a FAIL, run `find . -iname "*.coverage"` and check timestamps against the feature's evidence timestamps; if a matching raw file exists, convert it yourself for independent verification, then delete the generated (often 20-30MB) XML afterward since it is not required committed evidence (per [[csharp-repowide-coverage-below-80]] and [[csharp-coverage-artifact-is-cobertura]], raw all-DLL merges read low due to vendored-package inflation — always read the specific `<package name="UtilitiesCS">` line-rate, not the top-level `<coverage line-rate=...>` aggregate, which pools in every vendored/third-party package instrumented by that single-project run). See [[project_testresults-coverage-xml-cross-module-check]] for the related module-scoping caveat, and [[project_pr-context-summary-misclassifies-cs]] for the companion defect (missing coverage-gate detection due to the language not being recognized as changed).
