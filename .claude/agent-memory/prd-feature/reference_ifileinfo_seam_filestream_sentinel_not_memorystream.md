When a spec needs a file-handle test for `FileInfoWrapper` (or anything behind `IFileInfo`) without a repository file and without a temporary file, the design that survived scrutiny on issue #931 (2026-09-28) is: construct the wrapper through the `internal FileInfoWrapper(IFileInfo)` seam with a strict Moq mock whose `OpenRead()` returns a `FileStream` the test opens over `typeof(<TestClass>).Assembly.Location` with `FileMode.Open`, `FileAccess.Read`, `FileShare.ReadWrite`, disposed by `using`. Assert same-instance, `CanRead`, `Length` greater than zero.

**Why:** `IFileInfo.OpenRead()`, `Open(...)`, `Create()` and `OpenWrite()` are declared as returning the concrete `FileStream` type, so a `MemoryStream` cannot be returned through the seam for those members (it works only behind `StreamReader`/`StreamWriter` members). `PhysicalFileInfoAdapter`'s delegate seam does not cover `OpenRead`, so the public `FileInfoWrapper(FileInfo)` path cannot exercise it without a real file. Handle-free alternatives (anonymous pipe, device pseudo-file) give non-seekable streams where `Length` throws, and are still OS handles. The test assembly is gitignored build output, pre-exists as the host's own loaded image, is created/deleted by nobody during the run, and the permissive share mode admits every other holder; the same open shape already runs six times in the same test file. Metadata-only tests (`FullName`, `Name`, `Extension`, `DirectoryName`, `Directory`, `ToString`, `Exists`) need no handle at all: use a rooted literal path that does not exist and never assert `Length`.

**How to apply:** when a caller says "test-owned stream or in-memory stream, never a repository file, never a temp file", check the interface's return types first; if they are `FileStream`, write the assembly-location sentinel design into the spec with the four-part justification (test-owned, not repo-tracked, not temporary, permissive share) and state that the handle-free alternative was evaluated and rejected. Same-class sibling defects still live in PhysicalFileSystemAdapters_Tests and DirectoryInfoWrapper_Tests (recorded as #931 follow-ups).
